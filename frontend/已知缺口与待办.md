### 一条方法学教训（已写进 CONVENTIONS §8）

`vite.config.ts` 的 `AutoImport` / `Components` 把 dts 指向 `src/auto-imports.d.ts` 与 `src/components.d.ts`，而这两个文件**由 `vite build` 生成**、仓库里不存在。在它们缺失时，**模板里的组件与其 props 根本没被类型检查**——`vue-tsc` 会报 0 error，而那是假象。

本项目实测：构建前的「0 error」在构建后变成 **55 个真实错误**，全部在模板里。

因此验收顺序必须是 `vite build` → `vue-tsc` → 再 `vue-tsc`（第一遍生成 d.ts，第二遍才是真的）。

另：统计错误数**不要**用 `| head -N`。head 打满行数即退出，上游收到 SIGPIPE 提前终止，落盘的文件同样被截断，会得出「只有 N 个错」的错误结论（本项目实测 20 vs 55）。

## 2. 契约漂移（代码为准；需后端确认）

前端的接口路径与 DTO 以 `src/api/*.ts` + `src/types/*.ts` 为准。以下各处**文档与代码不一致**，若后端按文档实现会直接跑不通：

| 处 | 文档（模块概要设计） | 代码实际 |
|---|---|---|
| fe-05 §3.1 | `POST /preparations/{id}/approvals` | `POST /preparations/{id}/decisions` |
| fe-06 §3.1 / §4 | `RunFilter.status?: RunStatus`（单选）、`page_no` | `status?: RunStatus[]`（多选）、`page` |
| fe-06 §3.1 | `RunLogFilter.from/to` | 无 `from/to`（改用 `since_seq` 游标） |
| fe-03 §10 | `masking_policy = {default, by_column_type}` | `{default, overrides}` |
| fe-06 §7 | `RunDetail.error_code` 用于判定 `ROLLBACK_FAILED` | DTO 无该字段 |
| fe-06 §6 | `RunSummary` 带预算字段（列表按 `max_reject_rate` 标红） | `RunSummary` 无预算字段 |

## 3. 需要后端补的能力

1. **没有 `POST /pipelines`**：Pipeline 只能由后端流程产生，列表页因此**没有「新建」入口**（宁可没入口，也不放点了会 404 的按钮）。
2. **没有对话/澄清历史接口**：`fetchWorkflowSnapshot` 只返回当前 pending 的问题，已答过的问答对拿不回来。刷新后用户看不到自己之前答了什么。
3. **生成/澄清的响应里没有「本次生成的 draft version id」**：前端只能退回 `pipeline.current_version_id`，若该值仍是上一版，冻结就会指向旧版本（后端会拒，弹窗里能看到原因，但体验上绕了一圈）。
4. **`answers` 是 `Record<string, string>`**：`multi_choice` 只能用逗号拼成字符串提交，语义不如数组清晰。
5. **指标没有增量游标**：`fetchRunMetrics` 没有 `since`，只能「取最近 N 点」整段替换，曲线会被反复截断；视图内自行按 tick 累积采样，若后端能提供游标，这段可以整体下沉到 store。
6. **`POST /runs/{id}/rollback` 无「失败」信号**：`RunDetail` 无 `error_code`，前端改为「本次会话内回滚失败即锁定按钮 + 要求操作员显式重新武装」的降级策略，不做错误字符串嗅探。
7. **项目重命名没有理由通道**：`ProjectUpdate` 只有 `{name, description}`，没有可承载「操作理由」的字段，而 fe-08 §6.5/§8 要求留理由并落证据事件。前端因此**拒绝收集一个交不上去的理由**。
8. **`AUTOFIX_MAX_ROUNDS = 3` 在前端是硬编码常量**（源码注释写明它对应 be-11 的 `LLM_AUTOFIX_MAX_ROUNDS`），仅用于显示「第 n / 3 轮」，上限判定始终在后端。若希望前后端同源，需要一个配置下发接口。
9. **日志导出接口是前端假设**：`GET /runs/{id}/logs/export`、`GET /runs/{id}/error-records/export` 未在任何文档中出现，前端只用两个路径常量 + 后端文件流（不拼 CSV）。若后端路径不同，改这两个字符串即可。

## 6. mock 保真度（仅影响 dev 观感）

- `scope='done'` 按**状态**过滤，而不是「由我处理过」，因此 dev 环境的「已办」标签页会显示用户从未碰过的单据。演示口径问题，不影响生产。
- mock 的 `runCaps(status)` 只看运行状态（`can_pause` 仅 running、`can_rollback` 仅 failed/interrupted），无法在 mock 下验证 403 / 409 与四眼相关分支。
- 探查推进固定 3s，不模拟失败态（`failed` / `expired`），「探查失败」的界面分支需要改 fixtures 手工验证。

## 7. 视觉未与原型逐屏核对（唯一未闭环的验收项）

`前端原型图.pen` **未能读取**：pencil MCP 的 `get_app_state` / `read_skill` / `execute`（含带 `filePath`）一律返回

> **在 pen.dev 设计编辑器里打开 `前端原型图.pen`，然后安排一次 8 个页面的版面走查。**

在走查之前，全部视觉实现依据 `src/styles/variables.scss` 的 `--elt-*` 令牌 + 各 fe-0X 文档的版式描述，**颜色全部从令牌派生、没有新造色值**，但字号/间距/分栏比例可能与原型存在偏差。

## 8. 依赖与构建

- `typescript` 锁在 `^5.9.3`：`vue-tsc@3.3.13` 声明的 peer 范围是 `>=5.0.0`，但它加载的是 TS 旧的包布局（`typescript/lib/tsc`），TS 7 移除了该子路径，装 7.x 会直接崩。
- `@lezer/highlight` 目前是从 `@codemirror/language` 的传递依赖里 import 的（`HoconEditor` 用它做 `tags` 映射）。**建议在 `package.json` 里显式声明**，避免依赖树变动时构建炸掉。
- 生产构建**不包含 mock**：已实测 `dist/` 中搜不到 mock 的路由告警串、fixture 人名与表名。`main.ts` 用静态判定 + 动态 `import()`，生产构建会把整个 mock 模块摇掉。
