## 5 分钟速览（读完这一节，你就知道这项目是什么、能讲什么）

**一句话**：一个**数据同步作业的治理与执行平台**——
业务方用一句人话提出「把 MySQL 两张表合成宽表同步到 Doris」，
系统把它变成受控的作业，**但「能不能上生产」的决定权不在大模型手里**。

**它的赌注**：把「不可信的部分」（大模型、人手写的配置）和「不可商量的部分」（权限、审批、执行、留痕）
用一道**确定性的墙**隔开。大模型只**起草**，放行全部由纯规则代码判定，每一步留哈希链证据。

**已经真能跑的**（我逐条实测过）：

| 能力 | 证据 |
|---|---|
| 安全内核：七步执行序 / 一次性令牌 / 防重放 / 哈希链账本 | `backend/harness/`；全仓 **1407 passed**、`ruff` 全绿、**0 xfail** |
| 确定性风险评级（11 条规则、纯函数） | `engines/policy/`，含「同输入 100 次结果一致」用例 |
| M1 业务闭环：登录→项目→数据源→连通性测试→元数据探查脱敏→账本 | **真连 ECS 上的 MySQL 跑通**：`succeeded 357ms MySQL 8.0.27` |
| **M2 生成链路**：一句人话 → 澄清 → EtlPlan → HOCON → 确定性门禁 → 冻结版本 | **跑通**（真后端 + ECS 上的真 PG/Redis/Vault/MySQL，经 SSH 隧道）：`thread_id=17` → 5 个澄清问题 → 一次请求内依次 `metadata_bound → plan_generated → hocon_rendered → gate_evaluated(pass) → frozen`，`version_no=1`、`sha256=f3ea7843…` |
| **M3 前半段（be-13/14/15）**：准备单 + 四眼审批、Commit 签发**单次** Capability → Outbox → worker 验签执行、SeaTunnel 客户端与 **Secret 物化**（0600 + `O_EXCL` + 异常路径也销毁） | `/api/v1/preparations`、`/api/v1/runs` 已挂载（实测 401 = 存在且要鉴权）；`clients/seatunnel/`、`clients/secrets/` 共 9 个文件 |
| **M3 后半段（be-16/17/18 + 收尾编排）**：指标抄取与硬中断、质量契约与分流（错误行只存摘要）、原子 Swap 与受管回滚，以及**把两边接起来**的 [services/finalize.py](../backend/services/finalize.py) | 单测 **71 + 45 + 34 + 25 + 21 = 196 条**；`openapi.json` 新增 7 条路径（含 `/runs/{id}/rollback`、`/runs/{id}/publish`、`monitor/runs/{id}/quality-report`）；worker 启动日志实测 `quality_error_table_reader_registered`、已注册 12 个任务 |
| 脱敏 | 160 个样本单元格**全部是摘要形态，无一等于原值**（直连 MySQL 逐格比对过） |
| 证据账本独立验链 | `backend/scripts/verify_ledger.py` → **`OK checked=52 from_seq=1`**（真 PG） |
| 前端页面 | 164/164 模块编译通过、`vue-tsc` exit 0（⚠️ **页面实际渲染没真点过**） |

**还没做的（我要你开口就说，别等人问）**：
**这条链的代码第一次全部接上了——但它在真基础设施上一次都没跑过。**
先说接上的部分：be-16 运行监督与硬中断（五维度阈值、越界签票停作业）、
be-17 质量契约与数据分流（错误行只存哈希摘要）、be-18 原子发布与受管回滚（Swap 的判定**以执行后对账为准**，不信工具自报），
加上本次新写的**收尾编排** [services/finalize.py](../backend/services/finalize.py) ——
此前 be-17 与 be-18 的文档**各自把「报告合格之后谁去换表」划给对方**，
于是两个函数（`finalize_report` / `publish_run`）**调用方数量都是 0**，
作业跑完永远不会出质量报告、报告合格也永远不会换表。补上的是那条缝，不是新功能。
再说没做的：M4 整段（策略管理面、Benchmark 三张表零引用、Prometheus 埋点、账本签名检查点、备份/CI-CD），
以及**真 Data Plane**——`preparation` / `execution_run` / `quality_report` **在真库里都是 0 行**（我当场数的），
所以「脏数据超限硬中断 + 原子换表」这条演示**仍然只能靠单测证明，不能现场演**。
**还有一处必须主动交代**：质量分流的**控制面**（路由 SQL、错误表、质量报告）全写完了，
但**数据面没接线**——`render_route_selects` 一个生产调用方都没有，渲染器仍是单源单 sink。
现在跑起来，违规行不会被真的分出去，报告会显示「0 条错误」：**看着干净，其实没分流**。
改法已经固定到六步（运行期令牌 + tagged/valid/rejected + 双 sink），
见 [10 §4.1](10-做到哪一步了.md)；照着讲的口述稿见 [07 必答 6](07-面试题库.md)。
**逐条清单与证据见 [10-做到哪一步了](10-做到哪一步了.md)**（含「面试里怎么讲这些缺口」的现成答案）。

### 🎯 最值得在面试里讲的五个点（直接点名）

**① 「大模型只起草，放行由纯规则决定」——而且这条链子今天真的从头跑通了一次**
一句人话需求进去，LangGraph 先反问 **5 个澄清问题**（主键 / 增量列 / 去重口径 / 目标表 / 质量阈值）；
回答提交后，**同一个请求里**依次走完 元数据绑定 → EtlPlan（10 条字段映射、1 条质量规则）→ HOCON（885 字符 / 42 行）
→ 确定性门禁（`conclusion=pass`，`required_approval_slots=checker_data, checker_security`）→ **冻结**（`version_no=1`、`sha256=f3ea7843…`）。
全程模型只产出一份被 Pydantic 约束的 `EtlPlan`，**能不能放行是纯函数门禁判的，模型碰不到**。
金句：**「我把『不可信的部分』（模型、手写配置）和『不可商量的部分』（权限、审批、留痕）用一道确定性的墙隔开——模型只能站在墙的起草那一侧，翻墙的路径在代码里就不存在。」**

**② 账本哈希链：并发写入怎么保证不断链**
每条事件带前一条的哈希。难点不在算哈希，在**多个 worker 同时写**：
先锁链尾行，**表空的时候没有行可以锁**（两个并发写入会同时算出 `seq=1`），
所以额外加了一把事务级顾问锁；`seq` 用 `MAX(seq)+1` 而**不是自增序列**，
因为序列回滚会留空洞，而验链要求连续——有空洞的话，
「有人删了一行」和「有人回滚了一次」**无法区分**。

**③ 把架构约束做成自动化守卫（而不是写在文档里）**
「`engines/` 这层不许 import 框架 / 不许取时间 / 不许文件 IO」——
光写进文档等于没有，因为**谁都可以 import 一个 LLM 客户端而所有用例照样全绿**。
所以我写了三重扫描：AST 扫 import、AST 扫危险调用、
再起一个 `python -I` 子进程量**增量依赖**（AST 看不见间接依赖）。
最后**给守卫自己写了元测试**，防止有人把禁用名单清空后这个文件仍然全绿。

**④ 「执行权是一张只能用一次的票」——连「停作业」都不能绕过同一个出口**
把「一次执行」表达成一张绑定了**制品指纹 / 环境 / 租户 / 工具**的 Ed25519 票（不是「一次登录会话」），
库里只存它的哈希、原文只随 Outbox 载荷进 worker 内存；消费是**原子的两半**：Redis `SETNX` 占位 + PG 条件 UPDATE，
任一半说「用过」就拒。更值得讲的是**取消**：它也是外部副作用，所以 `request_cancel` **照样签一张绑 `seatunnel.stop` 的票**、
照样经 Outbox 交给 worker，而不是在服务层顺手调一下 SeaTunnel——
注释写明理由：「**那等于在服务层开了第二个副作用出口**」。
金句：**「铁律最容易破的地方不是主流程，是『顺手也调一下』的支线——所以我把取消也写成了同一套票据流程。」**

**⑤ 两个模块各自绿灯，中间那条缝没人认领（本次刚落地的教训）**
be-17（质量分流）与 be-18（原子发布）是分别写的两份设计，**各自都把「报告合格之后谁去换表」写给了对方**，
于是「出质量报告」和「换表」两个函数**谁都没有调用方**——`quality_report` 表永远 0 行，正式表永远不换。
我补的不是功能，是**那条缝**：一个收尾编排，按数据面事实把运行推到结论
（跑完 → 出报告 → 合格才换表 → `succeeded`；不合格 → `failed`；中断的运行**永不发布**——半份影子表换上去比不换更糟；
查不到作业就**不动状态**只告警，因为可能是别人正在取消，一律写 failed 会让「谁停的」永久失去答案）。
顺带在这一轮揪出**四个同一类缺陷**（详见 [10 §2](10-做到哪一步了.md)）：判据的输入**不存在或错位**，
于是某个功能**悄悄地永不生效**——放大比要的 `read_bytes` 认不出 Zeta 报的计数器键名（这一维长期判 `unknown`）、worker 的 broker 没拿到校验公钥（整条执行链在 worker 里一步都走不了）、
提交执行没给操作主体、质量读取器的注册形状在物理上无法实现（端口只拿到表名，定位不到主机）。
**它们全都躲过了当时全绿的 1370 条单测，因为假替换品比真实现宽松。**
金句：**「我现在看这类代码只问两句：这个判据的输入从哪来、那条路径真的会填它吗？这段代码真跑一次会怎样？」**

> 这五个点的共同点是：**它们都是「讲得出为什么」的东西**——不是功能清单，是判断力。
> （一次令牌只在数据库 WHERE 条件里成原子、Redis 挂了 fail-closed 那一条也照样值钱，
> 见 [01-这是什么 §6](01-这是什么.md) 与 [06-知识点精讲](06-知识点精讲.md) 卡片①；
> 想连着讲「这些点我都是怎么验证的」，用 [10-做到哪一步了 §2](10-做到哪一步了.md) 里那六个真缺陷当引子——
> **它们都是「测试写对了、产品是错的」，而且是同一类：判据的输入不存在或错位，功能悄悄地永不生效。**
> 比功能清单更能说明你会怎么工作。）

## 诚实交代：哪些核实过、哪些没有

### ✅ 我亲自跑出来/数出来的

- `cd backend && uv run pytest` → **1407 passed, 3 skipped**（52 个 `test_*.py` / **1073 个 test 函数**）；
  `ruff check .` → **All checks passed**；**0 个 xfail**（六个真缺陷修掉后摘了标记，见 [10 §2](10-做到哪一步了.md)）；
  `/healthz` → `{"status":"ok","app":"elt_agent","env":"dev"}`、`/readyz` → `{"redis":"ok","postgres":"ok"}` → 200
  （就绪探针实测返回 **只有这两项**，Vault 按设计不在探针里，见 [health.py:4](../backend/api/health.py#L4)；
  Vault 是**另一条独立验证路径**：真 AppRole 登录 `health() → True`，建数据源时写入 → 连通性测试时读出 → 真连上了库）
  - 工具坑：`pyproject.toml` 的 `addopts` 里已经有 `-q`，命令行再加一个 `-q` 就是 `-qq`，**汇总行会消失、只剩进度点**——想看 `1407 passed` 就别再加 `-q`（这是工具坑，不是产品问题）
  - 补一句经过：交付当天跑全量时**有两条用例红了**（那时全仓才 395 条的量级），查清是**「定时炸弹测试」**（fixture 里一条事件用真实当前时间、用例用硬编码时刻做下界过滤，于是通过与否取决于**几点跑**，它在 16:01 过期）。**不是产品缺陷**，我改了过滤条件两端夹住，还堵了另一颗「一年后引爆」的同类，并把成因写进了 `CLAUDE.md` §9.1 —— 完整经过见 [05-开发原理 §8](05-开发原理.md) 和 [07-面试题库](07-面试题库.md) 必答 2
- **live 三条外围依赖各自实测过**（2026-10-16，本机 → SSH 隧道 → ECS）：
  Vault `health() → True`；Redis 同一键 `SETNX` 首次 `True` / 第二次 `None`（单次消费的底座）；
  ReplayGuard 拿**从未签发过的** jti 去 `consume` → 被拒（Redis 占位成功但 PG 条件 UPDATE 命中 0 行，
  **双保险的 PG 那一半也在真干活**）；账本在真 PG 上写入 `seq=51` 且 `verify_ledger.py` → `OK checked=52`
- **真连外部数据库**：连通性测试 `succeeded | 357ms | MySQL 8.0.27`（经前端代理打的真请求）
- **脱敏**：探出 2 表 20 列；160 个样本单元格全部 `<类型>:<哈希>` 形态，**逐格与原值比对无一相同**
- **M2 端到端跑通**（今天，真后端 + ECS 上的真库）：一句需求 → `thread_id=17` → 5 个澄清问题 → 一次请求内到 `frozen`（`version_no=1`、`sha256=f3ea7843bbf37148…`、`frozen_by=需求提出人`）；重复冻结 → **409「该版本已经冻结过了；冻结是不可逆的」**（设计如此）；制品里**没有明文口令**，只有 `{{secret:1:jdbc_url}}` 这类令牌
- **账本验链**：`verify_ledger.py` → `OK checked=52 from_seq=1`（**数字随事件增长**，别当成定值背）
- **前端**：Vite 起在 `localhost:5176`（真后端模式；端口会被同机别的项目挤走，**看启动日志那句 `Local:`**；mock 模式怎么起见 [09 §2 ④](09-怎么跑起来.md)），**164/164 模块编译通过**，`vue-tsc` 类型检查 exit 0；`npm run build` → **exit 0**（1.39s，每个页面一个 chunk 的按需分包）
- **起进程这一层也核过（本次新加的两处启动注册）**：API 重启后日志里有一行
  `quality_error_table_reader_registered impl=build_error_table_reader`，**worker 日志里同一行**——
  「钩子漏挂」这类错法的症状是**运行时才 500**，所以必须真的启动一次才算验过；
  顺带核到 worker 的队列是 `etl.default` **+ `etl.execute`**（后者载着 `tasks.execution.*`，
  只挂前者的话提交/停止/收尾任务会一直躺在队列里，**日志里连一行都没有**）
- **接口真实性（用状态码分辨「做到哪一步」）**：未登录时 `/pipelines`、`/pipeline-versions/*` 返回 **401**（有会话时 **200**——经 Vite 代理、带登录态实测过 Studio 那组：`/projects`、`/datasources?project_id=1`、`/pipelines`、`/pipelines/17`、`/pipelines/17/versions`、`/pipeline-versions/7`、`/pipeline-versions/7/plan`、`/pipeline-versions/7/hocon`、`/pipeline-versions/7/gate`、`/pipelines/generations/17`——**全部 200**）；**M3 两条链现在都挂载了**——`/preparations/*`、`/runs/*`、**`/runs/{id}/rollback`**、`/runs/{id}/publish`、`/runs/{id}/quality-report`、`/runs/{id}/error-records` → **401 = 存在且要鉴权**（不是 404）；仍 **404 = 真的没有** 的是 `/monitor/*` 的**指标**端点、`/policy-rules`、`/policy-versions`、`/budget-defaults`、benchmark（以上都当场打过一遍）
- **mock 数据进不了生产包**（这条是**两个方向都实测过**，不是读代码推断的）：生产 `dist` 里 `grep -rl "installMockAdapter"` 与 `grep -rl "DEV MOCK"` **均 0 命中**；换成 `npx vite build --mode development` 构建，两处**都命中**——开关是编译期字面量，条件是死代码，摇得掉
- **写接口幂等**（`Idempotency-Key`）：同一个 key 打两次 `/pipelines/generations` → **同一个 `thread_id`**；换一个 key → 新会话。中间件在 [api/idempotency.py](../backend/api/idempotency.py)
- **指纹是内容寻址的**：两条**不同**会话（pipeline 14 / 15）跑同一个需求，冻结出**同一个** `sha256=f3ea7843bbf37148…`——因为 `pipeline_id` / `version_no` / 时间戳 / 操作者都在排除清单里（[parts.py:48](../backend/engines/fingerprint/parts.py#L48)，be-12 §6.2）。「同一份制品的副本得到同一指纹」是设计，不是碰撞
- **规模数字**（报的时候一并说口径）：backend **69,123 行** Python（含 tests 24,299 行；**排除** `.venv`/`__pycache__`/`alembic/versions`——那是生成的 DDL）/ frontend `src` 39,475 行 / 32 张表 / `openapi.json` **61 条路径** / **52 个 `test_*.py`、1073 个测试函数、收集 1410 条**（`pytest` → **1407 passed, 3 skipped**；收集数 > 函数数是因为 `parametrize` 展开）
- 所有 `file:line` 引用我都打开看过原文（特别是 04 里贴的代码块）

## 🔴 你必须自己打开读的代码（别只信这套文档）

面试官让你**现场改一改**、或者问「第 180 行为什么不放在 179 行前面」，只有自己读过才接得住。
优先级从高到低：

0. **[backend/services/finalize.py](../backend/services/finalize.py) 整份（约 400 行，本次新写）**
   ——「作业跑完到这一运行算完」的全部判断都在这里：只推进 `running`/`interrupted`、
   中断永不发布（两道独立判据）、查不到作业不改状态（`orphaned`）、失败不搬原文。
   **读它的 docstring 比读代码重要**——四条纪律每条都写了「不这么做会怎样」。
1. **[backend/harness/broker.py](../backend/harness/broker.py) 的 `execute`（第 155-232 行）**
   ——七步执行序全在这里。**重点读第 175-180 行的注释**（④a 为什么必须在 ④b 前面）
   和第 249-262 行（进程检查为什么是单向的）。这两处是「设计判断」的落点。
2. **[backend/harness/replay.py](../backend/harness/replay.py) 的 `consume`（第 69-101 行）**
   ——只有 30 行，但每一行都有理由：`nx=True`、`ex=ttl+slack`、`except RedisError` 抛错、
   `where(... is_(None))`、`rowcount == 0`。**这是全项目性价比最高的 30 行。**
3. **[backend/services/pipeline/artifacts.py](../backend/services/pipeline/artifacts.py) 的 `freeze_version`（第 350 行起）**
   ——M2 的终点。**六道闸**（只冻草案 / 从落库制品重算指纹 / 令牌必须解得开 / 门禁无阻塞 / 落冻结人 / 推进状态），
   顺序不能换——每一道都建立在前一道成立的基础上。这是「审批看到的 = 执行拿到的」的**唯一**保证。
4. **[backend/workflow/graph.py](../backend/workflow/graph.py) 的条件边与 `_guarded_node`（路由在 :154 / :176，出口守卫在 :200 / :222）**
   ——`route_after_gate` 把「策略阻断」**直接从图结构上**赶去 `terminal`（压根不进修复回路），让「它没进修复」这件事可见；
   出口守卫两道：装配期校验 `NODE_OUTPUTS` 里没有 schema 不存在的键，运行期拦节点回写白名单外的键。
5. **[backend/engines/hocon/types.py](../backend/engines/hocon/types.py) 的两道令牌闸（`assert_no_unresolved_tokens` :92 vs `secret_token_problems` :109）**
   ——同一个「制品里要不要留 `{{secret:...}}` 令牌」的问题，**执行前**问的是「替换干净了没有」（令牌必须一个不剩），
   **冻结时**问的是「令牌到时候解得开吗」（字段在白名单、指向的数据源还在且有凭据）。两道闸各管一件事；
   混用会让**每一份合法制品都冻不了**（我今天刚踩过，见 [05-开发原理 §9](05-开发原理.md)）。
6. **[backend/harness/ledger.py](../backend/harness/ledger.py) 的 `_lock_tail_and_next_seq`（第 272-295 行）**
   ——空表为什么要顾问锁、seq 为什么不用序列。
7. **[backend/tests/test_policy_import_graph.py](../backend/tests/test_policy_import_graph.py) 第 137-160 行**
   ——独立解释器量「增量依赖」的完整写法。**这段是「我怎么守架构」的实证。**
8. **[backend/core/redis.py](../backend/core/redis.py)** 的客户端构造
   ——必答 2 那个故事的技术落点，注释里写着完整的故障经过。

看的时候带上一个问题：**「这段代码在防什么？」**
凡是你能指着某一行说出它在防什么，那一行就是面试时该主动讲的。
