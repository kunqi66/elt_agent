# 01 · 这是什么

> ⚠️ **先看这一节，再看别的。** 这个项目的「设计」和「已经写出来的部分」差距很大，
> 面试时把两者说混，是最容易被拆穿的地方。本页第 3 节给了一张诚实到不留情面的实现状态表。

## 1. 一句话（外行版）

**它要解决的问题**：让人用一句人话就能拉起一条数据同步作业，同时**不把「能不能上生产」的决定权交给大模型**。

设想的完整链路是：你说「把 MySQL 的订单表和用户表合成宽表放进 Doris」→ 系统用大模型翻译成结构化作业计划
→ 渲染成数据同步引擎（SeaTunnel）的配置 → 过规则门禁 → 两个人签字审批
→ 发一张一次性执行令牌 → 执行到**影子表**（和生产表并存的一张临时表，先往它写，
不碰线上数据）→ 查质量 → 合格才**原子切换**（一次操作把影子表换成正式表，中途没有"改了一半"的状态）
→ 全程留哈希链证据。

**而实际已经落地的是这条链路的「骨架 + 安全内核 + 前半段生成链路」**：

- **安全内核（`harness/`，2,014 行）全部实现且带测试**——它是整条链路里唯一负责「放行」的部分，
  包含七步执行序、Ed25519 一次性令牌、重放防护、哈希链账本；
- **风险评级引擎（`engines/policy/`）全部实现**——11 条内置规则、纯函数、有确定性测试；
- **M1 的整条闭环跑通了**——登录鉴权 → 多租户 → 数据源 → 连通性测试 → 元数据探查与脱敏 → 证据账本；
- **M2 的生成链路也跑通了**——LangGraph 编排（澄清/中断/Checkpoint 恢复）、EtlPlan、HOCON 渲染、
  确定性门禁、有限自动修复、五段指纹、版本冻结：`backend/workflow/` 3,538 行 + `engines/` 六个新目录 + `services/pipeline/` 一趟；
  **我今天在本机（真后端 + ECS 上的真库）把它从头跑到尾了一次**：一句需求 → 5 个澄清问题 → 一次请求内到 `frozen`。

一句话的诚实版本：

> 「我做的是一个 ETL 作业的**治理与执行内核**：『自然语言进、冻结版本出』这半段已经跑通了，
> 而『**冻结之后凭什么被执行**』这半段还没接——但**大模型接进来之后没有执行权**这件事，
> 我已经用代码锁死了：确定性评级、单次令牌、四眼审批、哈希链账本，四件事都是完成的、有测试的。」

## 2. 为什么这件事值得做（价值主张）

普通做法（Airflow 脚本、手写 DataX/SeaTunnel 配置）把「写配置」和「上生产」直接连在一起：
**谁改的、谁批的、凭什么让它动生产数据，全靠人的自觉。**

这个项目的赌注是：**把「不可信的部分」（大模型、人手写的配置）和「不可商量的部分」（权限、审批、执行、留痕）
用一道确定性的墙隔开**——大模型只负责**起草**，所有**放行**的判断由纯规则代码做，每一步都留下能被第三方独立复核的证据。

可背的一句话：

> 「我让大模型只产出被 schema 约束的草案，**能不能跑不由它决定**——
> 风险等级是纯函数规则算的，执行要一次性令牌，令牌的消费是原子的，全链路写哈希链账本。」

**怎么在面试里讲这个差距**（这是加分项，不是减分项）：

> 「我按『哪一半会真出事故』排的序：先做安全内核和确定性判定，再往前把生成链路接起来，
> 然后把治理链路的后半段（监督 / 分流 / 原子 Swap）接上——
> **这一轮最值得讲的不是功能，是那条缝**：be-17 与 be-18 是两份分别写的设计，
> 各自都把「报告合格之后谁去换表」写给了对方，于是那两个函数**谁都没有调用方**，
> 作业跑完永远不会出报告、报告合格也永远不会换表，**而两边的单测都是绿的**。
> 补上的是一个收尾编排，它不拥有任何算法，只做分派与顺序。」

⚠️ 但也要能承认反面：**这条链现在「代码上通了」，但一次都没在真基础设施上跑过**——
`preparation` / `execution_run` / `quality_report` 三张表**都是 0 行**（我当场数的），
所以「一句话生成一条作业 → 两个人审 → 单次票执行 → 脏数据超限硬中断 → 原子换表」
**在真库里一步都没走过**（详见 [07-面试题库](07-面试题库.md) 第 3 题）。
还有一个**反面教材**值得主动讲：发布工具的前置条件写得那么严谨，**恰恰说明「前置条件写得好」不能证明链路通**——
要问的是「这个前置条件**由谁产生**」；这一轮我恰好又踩到同一类四次（判据的输入不存在或错位），
四次都躲过了当时全绿的 1370 条单测。

## 5. 技术栈（人话版）

选型在 [CLAUDE.md](../CLAUDE.md) 里是「已锁定，不得替换」，逐条翻译成人话：

| 层 | 选型 | 人话 |
|---|---|---|
| 控制面 | FastAPI + SQLAlchemy(async) + Alembic + Pydantic v2 | Python Web 框架 + 异步 ORM + 数据库迁移 + 数据校验 |
| 编排 | LangGraph（Checkpoint 存 PostgreSQL） | 把「多轮对话、中途要人等」画成状态图，**断点存数据库**——已实现并端到端跑通 |
| 异步 | Celery + Redis | 「重活丢后台」，API 立刻返回编号让前端轮询 |
| 控制面库 | PostgreSQL 16 | 业务事实的唯一可信副本 |
| 缓存/锁 | Redis 7 | 临时状态、锁、以及「令牌用过没有」 |
| 演示数据源 | MySQL 8 / Doris 2.1 / MinIO | 真数据库，不是 mock |
| 数据面 | Apache SeaTunnel | 真正干活的引擎；本项目只生成它的配置、只通过 API 触发它（`seatunnel.submit` / `seatunnel.stop` 执行器**已注册**，但 ECS 上没起这个容器，**一次都没真提交过**） |
| 密钥 | HashiCorp Vault | 数据库口令存这里，业务库只存「路径 + 版本号」 |
| 模型 | DeepSeek（Provider 抽象层隔离） | 用哪家模型可换，业务代码不认识 DeepSeek |
| 令牌 | Ed25519（EdDSA）签名 JWT | 用非对称密钥签名，**只有公开公钥也能验，伪造不了** |
| 可观测 | structlog + Prometheus + Grafana | 结构化日志（可机读）+ 指标 + 看板 |
| 前端 | Vue 3 + TS(strict) + Vite + Pinia + Element Plus | 主流后台管理组合，TS 严格模式 |
| 部署 | Docker Compose 单机 | 一台机器上的容器编排 |

## 6. 最值得在面试里讲的三个点（直接点名）

### ① 「一次令牌只能刷一次」——并发下的原子性怎么做的

审批通过后发一张 Ed25519 签名的令牌（Capability）。**它的消费必须原子**，否则两个 worker 同时开工 =
**两次真实的数据搬运**（不是报错，是真花钱真改数据的事故）。

做法是三件事叠起来（[harness/replay.py:70](../backend/harness/replay.py#L70)）：

1. 先 `Redis SETNX` 占位——快，挡住 Celery 常态重投；
2. 再 `UPDATE capability SET consumed_at=... WHERE jti=? AND consumed_at IS NULL`——
   **原子性靠这一条 UPDATE 的 WHERE 条件**，并发时 PG 行锁让第二个事务影响 0 行，判为重放；
3. **Redis 挂了直接拒绝执行**（fail-closed），不退化成「只靠 PG」——那等于先查后写。

面试金句：**「我没有用『先查再写』，因为那中间有窗口；我用的是『条件写入 + 看影响行数』。」**

### ② 账本哈希链：并发写入怎么保证不断链

证据账本每条事件都带 `prev_hash` 和 `event_hash`，改了任何一条历史事件，后面的链全部对不上。
难点在于**多个 worker 同时写**。

做法（[harness/ledger.py:278](../backend/harness/ledger.py#L278)）：先拿一个**事务级顾问锁**
（表空时没有行可以锁，两个并发写入会同时算出 `seq=1`，顾问锁补上这段窗口），
再对链尾行 `SELECT ... FOR UPDATE`。真正的保证是这两个锁（READ COMMITTED 下就成立），
文档里要求的 SERIALIZABLE 只是纵深防御。

而且 seq 用 `MAX(seq)+1` 而不是数据库自增序列——**序列回滚会留空洞，而验链要求 seq 连续**。

### ③ 隧道式开发：控制面在本机、基础设施在 ECS（工程能力的证据）

本机没有 Docker，基础设施在阿里云 ECS（安全组只放行 22/8000/19530），要连 PG/Redis 只有两条路：
**改安全组（等于把数据库开到公网）或走 SSH 隧道**。选了后者，并写成了仓库里的脚本
（[deploy/tunnel.py](../deploy/tunnel.py)）：口令只从环境变量进、不落文件、不在服务器装东西、不开公网端口。

配套的坑我实际踩到并修了：**隧道重启后 worker 永久卡死**——redis 客户端是单例、默认不做连接健康检查，
那条死连接永远不会被换掉，日志里只有一句 `Error 22 while writing to socket`。
修法是显式开健康检查 + 重试，并加了一条断言**配置本身**的回归用例
（[backend/tests/test_core_clients.py](../backend/tests/test_core_clients.py)）——
因为这类参数删掉不会报错，只在断连时现形。

## 7. 这个项目**故意不做**什么

- **不做 SQL 解析器/优化器**——只做结构校验与白名单，不重写 SQL；
- **不做调度器**——定时触发交给外部，本项目只负责「一次执行」的可靠交付；
- **不让前端做安全判断**——权限校验服务端 + DB 约束兜底，前端置灰只是体验；
- **不提供「关闭脱敏」的开关**——策略只允许**变严**不允许变松
  （[engines/masking/policy.py:207](../backend/engines/masking/policy.py#L207)），
  理由写在注释里：能被关掉的脱敏开关，迟早会因为某次排查被临时关掉，然后再也没打开；
- **不给大模型执行权**——这句话现在**在「生成 → 审批 → 执行」整条链上都已经落地**：模型只产出一份被
  Pydantic 约束的 `EtlPlan`，放行由纯函数门禁判定；执行侧还要两个不同的人审批、由服务端签发一张
  **只能用一次**的 Capability 才动得了数据面——模型在代码里**根本拿不到签发器**（`harness/broker.py`
  的同一取舍：worker 侧只装验签器、不装签发器）。
