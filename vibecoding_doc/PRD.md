## 1. 产品概述

### 1.1 产品背景

企业数据集成通常涉及异构数据库、文件、对象存储和 API 数据源。传统 ETL 开发依赖人工编写配置和脚本，存在需求理解成本高、元数据不透明、敏感数据泄露、配置错误、审批职责混用、执行不可追溯以及异常回滚困难等问题。

本产品建设一个生产级 ETL-Agent 控制面平台：用户以自然语言描述数据集成需求，系统在受管元数据和安全策略约束下生成结构化 ETL 方案与 SeaTunnel 配置，并通过确定性校验、不可变版本、四眼审批、单次能力令牌和受管执行完成从设计到投产的闭环。

### 1.2 产品定位

面向企业数据工程团队的安全、可审计、可恢复的智能 ETL 控制面。平台负责需求理解、方案生成、策略治理、审批和运行监督；SeaTunnel 负责数据面搬运，控制面不直接传输海量业务数据。

### 1.3 产品目标

1. 降低异构数据集成方案设计和配置生成成本。
2. 保证自然语言生成的 ETL 方案具备结构化、可校验和可追溯特征。
3. 通过职责分离和四眼审批降低生产数据变更风险。
4. 通过 Capability、Replay Guard、Outbox 和 Evidence Ledger 保证副作用执行受控且可审计。
5. 通过影子表、质量契约、运行时预算和受管回滚提升数据发布可靠性。
6. 建立可重复的 Benchmark 评测和安全策略进化闭环。

### 1.4 成功指标

| 指标 | 目标方向 | 验证方式 |
|---|---|---|
| 需求到候选方案生成成功率 | 持续提升 | Benchmark 评测 |
| 生成方案语法与 Schema 校验通过率 | 持续提升 | 门禁结果统计 |
| P0/P1 风险拦截率 | 100% 拦截 | 安全评测集 |
| 申请人自批拦截率 | 100% 拦截 | 审批流程测试 |
| 未授权或重复执行成功率 | 0 | Capability 与 Replay Guard 测试 |
| 生产发布可回滚率 | 100% 可回滚 | 端到端演示与故障测试 |
| 运行质量异常可诊断率 | 持续提升 | 质量报告和根因诊断统计 |

## 2. 用户与权限

### 2.1 用户角色

| 角色 | 主要职责 | 核心权限 |
|---|---|---|
| 数据工程师（Maker） | 配置连接、探查元数据、描述需求、生成并提交 Pipeline | 管理授权范围内连接和 Pipeline，发起审批，不得审批自己的申请 |
| 数据审批人（Checker 1） | 审查业务需求、字段映射、质量规则和 DAG | 执行数据维度审批，不得代替安全审批 |
| 安全审批人（Checker 2） | 审查资源范围、敏感级别、预算、Secret 和回滚方案 | 执行安全维度审批，管理安全策略和 Benchmark |
| 系统操作员 | 执行已审批版本、监控任务、暂停、取消和回滚 | 仅能对审批通过且指纹一致的版本执行 Commit |
| 审计人员 | 查看执行历史、证据账本和质量报告 | 只读访问审计、运行和评测数据 |

### 2.2 权限与职责规则

1. 项目必须支持多租户隔离，用户只能访问所属租户和项目授权范围内的资源。
2. 申请人不能审批自己的 Preparation。
3. 数据审批人和安全审批人必须分别占用独立职责槽。
4. 高风险操作禁止同一用户同时承担多个审批职责。
5. 所有副作用操作必须经 Tool Broker 统一出口，不允许前端或普通 API 直接调用 SeaTunnel 或外部资源。
6. Secret 仅允许通过受管 SecretProvider / Vault KV v2 引用和物化，页面、日志和证据账本不得出现敏感明文。

## 3. 产品范围

### 3.1 本期范围

- 用户认证、鉴权、租户和项目隔离。
- 项目成员、角色和职责槽管理。
- MySQL、PostgreSQL、Oracle、Doris、ClickHouse 等数据库接入。
- CSV、Excel、JSON、Parquet、S3/MinIO、REST API 数据源接入。
- 安全连通性测试、只读元数据探查、近似统计和脱敏样本采样。
- 自然语言需求解析、澄清、中断和 Checkpoint 恢复。
- EtlPlan、SeaTunnel HOCON 候选生成与有限自动修复。
- 确定性门禁校验、不可变 PipelineVersion 和 SHA256 摘要。
- `prepare → approve → commit` 执行协议和四眼审批。
- Ed25519 签名短时单次 Capability、Replay Guard、Transactional Outbox。
- Celery 异步调度、SeaTunnel 执行、运行监督和质量契约分流。
- 影子表写入、质量校验和原子 Swap 发布。
- 受管暂停、取消、回滚、证据账本和审计报告。
- 分层 Benchmark 评测与安全策略进化。

### 3.2 本期不包含

- 控制面直接处理海量业务数据。
- 任意用户自定义脚本的无约束执行。
- 绕过审批的生产发布。
- 明文展示或长期保存数据源凭据。
- 未经策略评估的自动修改生产数据。

### 3.3 后续规划

- 扩展更多数据源和数据仓库连接器。
- 基于历史执行数据的成本和性能优化建议。
- 更丰富的数据血缘、影响分析和跨项目资产复用。
- 多区域执行和灾备编排。

## 4. 核心业务概念

| 概念 | 定义 |
|---|---|
| Data Source | 受管的数据源连接及其访问配置 |
| Metadata Profile | 通过只读探查生成的 Schema、字段类型、统计和脱敏样本概要 |
| Pipeline | 一个逻辑数据集成流程 |
| PipelineVersion | Pipeline 的不可变版本，包含 EtlPlan、HOCON、Schema、质量规则和 SHA256 摘要 |
| Preparation | 冻结本次执行输入、资源、风险、预算和回滚方案的准备单 |
| QualityContract | 字段级清洗、过滤、错误码和错误数据分流规则 |
| RuntimeSupervisionContract | 最大行数、字节数、执行时长、输出放大比和拒绝率预算 |
| ExecutionRun | 一次实际执行实例及其 SeaTunnel 作业 ID 和运行指标 |
| Capability | 绑定主体、工具、环境和制品指纹的短时单次执行授权令牌 |
| Evidence Ledger | 通过哈希链和签名检查点保护的关键操作证据账本 |

## 6. 功能需求

### 6.1 总览工作台

**目标**：让用户快速了解当前项目的数据资产、Pipeline、审批和运行健康度。

**功能要求**：

- 展示当前项目数据连接数量、Pipeline 数量和版本数量。
- 展示待审批 Preparation，区分数据审批和安全审批状态。
- 展示运行成功率、失败率、运行中任务数和近期异常。
- 展示读取行数、写入字节数、平均吞吐量和错误分流率等核心指标。
- 展示核心资源分布和快捷入口：新建连接、创建 Pipeline、审批待办、查看运行。
- 所有指标必须遵循租户、项目和角色权限过滤。

### 6.2 数据源与资产管理

#### 6.2.1 数据源登记

- 支持数据库、文件、对象存储和 REST API 数据源类型。
- 表单根据数据源类型动态展示必填项。
- 凭据只能以 Secret 引用方式保存，页面回显脱敏值。
- 支持连接名称、环境、所属项目、标签、负责人和敏感级别配置。
- 创建或修改连接必须记录审计事件。

#### 6.2.2 连通性测试

- 用户可以发起受管连通性测试。
- 测试只验证网络、认证和最小权限，不读取超出测试范围的业务数据。
- 返回成功、失败、超时和权限不足等明确状态。
- 错误信息不得包含密码、Token 或完整连接串。
- 测试操作需记录主体、时间、数据源、结果和证据摘要。

#### 6.2.3 元数据探查

- 仅允许只读探查。
- 支持 Schema、表、字段、字段类型、可空性、主键和近似统计。
- 支持配置采样行数、采样范围和脱敏策略。
- 对姓名、手机号、邮箱、身份证号、地址、Token 等敏感字段进行掩码、哈希或截断。
- 生成可版本化的 Metadata Profile，供 Pipeline Studio 使用。
- 探查过程不得修改源端数据，不得在日志中记录敏感样本原文。

### 6.3 Pipeline Studio

#### 6.3.1 需求输入与澄清

- 用户选择源端、目标端和目标环境后输入自然语言 ETL 需求。
- LangGraph 状态机负责意图解析、参数补全、元数据关联和需求澄清。
- 缺少主键、增量字段、去重规则、目标表或质量阈值等必要参数时必须中断并提问。
- 用户补充信息后，系统从 Checkpoint 恢复，不重复执行已完成的安全探查步骤。
- 界面显示当前状态：解析中、等待澄清、生成中、门禁校验、待提交等。
- 对模型输出和用户确认内容进行区分展示，并保留对话历史。

#### 6.3.2 方案生成

- 生成结构化 EtlPlan，至少包含输入、输出、字段映射、转换、过滤、质量规则、DAG 和运行预算。
- 生成 SeaTunnel HOCON 配置候选。
- 支持多个模型 Provider 的统一适配，但业务层不得依赖具体模型实现。
- 展示生成依据的 Metadata Profile 版本和模型生成版本。
- 对生成结果执行有限自动修复，自动修复必须有次数上限并保留前后 Diff。
- 超出修复次数或存在高风险问题时，转为人工处理。

#### 6.3.3 拓扑与 Diff 审查

- 展示 Pipeline DAG 拓扑、节点类型、输入输出和依赖关系。
- 展示源端与目标端 Schema 差异。
- 展示字段映射、类型转换、脱敏前后结构和质量规则 Diff。
- HOCON 配置支持语法高亮、折叠、只读和版本对比。
- 用户必须能定位每个门禁错误对应的配置、字段或拓扑节点。

#### 6.3.4 门禁校验与版本冻结

- 执行语法编译校验、Schema 对齐校验、字段映射校验、资源范围校验和策略校验。
- 校验结果分为通过、警告、阻断三类；P0/P1 风险必须阻断。
- 通过门禁后生成不可变 PipelineVersion。
- PipelineVersion 必须绑定 EtlPlan、HOCON、Schema、QualityContract、RuntimeSupervisionContract 和生成上下文摘要。
- 使用 SHA256 计算版本指纹，版本发布后禁止原地修改，只能生成新版本。

### 6.4 准备单与审批控制台

#### 6.4.1 Prepare

- 用户提交 PipelineVersion 后生成 Preparation 准备单。
- 准备单冻结以下事实：输入指纹、制品指纹、变更资源范围、数据敏感分级、执行预算、回滚方案、环境、审批职责槽和风险等级。
- Prepare 阶段不得产生外部数据写入、表结构变更或 SeaTunnel 执行副作用。
- PDP 根据 ToolIntent、资源范围、环境和数据分级输出 P0-P3 风险评级与审批要求。

#### 6.4.2 Approve

- 数据审批人审核需求描述、字段映射、Schema Diff、质量规则和 DAG。
- 安全审批人审核资源范围、敏感分级、Secret 引用、执行预算和回滚方案。
- 审批人只能对冻结事实做决定，不能修改准备单内容。
- 支持通过、拒绝、退回补充三种决定，并要求填写意见。
- 系统强制申请人不可自批，强制两个职责槽独立完成。
- 审批事实包括主体、角色、时间、决定、意见和被审批制品指纹。
- PipelineVersion 或 Preparation 指纹变化后，原审批自动失效。

#### 6.4.3 Commit

- 只有所有必需审批通过且指纹一致时才允许 Commit。
- 服务端重新校验 Preparation、审批事实、策略和版本指纹。
- Capability 令牌使用 Ed25519 签名，绑定主体、工具、环境、制品指纹和有效期。
- Capability 默认有效期为 5 分钟且只能消费一次。
- Tool Broker 在同一事务中创建 ExecutionRun 并写入 Outbox 命令。
- 未授权、过期、指纹不匹配和重复消费请求必须拒绝并记录证据。

### 6.5 运行中心与质量诊断

#### 6.5.1 任务执行

- Celery Worker 消费 Outbox 命令，验签后物化 Secret 并调用 SeaTunnel。
- ExecutionRun 关联 PipelineVersion SHA256、Preparation、SeaTunnel 作业 ID 和操作主体。
- 支持运行中、成功、失败、暂停、取消、硬中断、回滚中和已回滚等状态。
- 控制面仅传递任务指令、配置引用和状态指标，不搬运海量业务数据。

#### 6.5.2 运行监督

- 实时或准实时展示读取行数、写入行数、写入字节、吞吐量、执行时长、输出放大比和拒绝率。
- 依据 RuntimeSupervisionContract 监控预算。
- 接近阈值时触发预警，超过硬阈值时触发硬中断。
- 硬中断必须终止 SeaTunnel 作业、记录失败快照并生成证据事件。
- 运行日志需支持按级别、时间和事件类型过滤，敏感信息自动脱敏。

#### 6.5.3 质量契约与数据分流

- 有效数据写入影子表。
- 不符合字段级质量规则的数据写入错误表，并记录原始值的受保护摘要、错误码和违规原因。
- 展示有效行数、错误行数、拒绝率、错误码分布和规则命中情况。
- 质量报告必须支持定位到 PipelineVersion、规则和执行实例。
- 只有质量校验通过才允许进入发布阶段。

#### 6.5.4 原子发布与回滚

- 质量通过后，目标端通过原子 Swap 将影子表发布为正式表。
- 发布失败时不得留下半发布状态，必须进入可诊断失败状态。
- 操作员可发起受管回滚，Harness 校验权限后清理未发布影子数据并恢复原状态。
- 回滚操作必须具备明确的 Preparation、权限校验和证据记录。

### 6.6 安全治理与 Benchmark

- 支持维护 P0-P3 风险策略、资源范围策略、环境策略和审批策略。
- 支持触发 L0 静态注入、L1 模拟故障和 L2 真实链路评测。
- Benchmark 测试集必须版本化，记录测试用例、输入、预期结果和实际结果。
- 展示生成准确率、门禁通过率、P0/P1 拦截率、误报率、恢复成功率等指标。
- 安全策略变更必须经过审批并记录版本和生效范围。
- 评测结果支持导出和审计追踪。

## 7. 核心业务流程

### 7.1 需求生成与受管发布

1. 数据工程师登记源库和目标库连接。
2. 系统执行受管只读探查并生成 Metadata Profile。
3. 数据工程师在 Pipeline Studio 输入自然语言需求。
4. LangGraph 解析需求；参数不足时中断提问。
5. 数据工程师补充参数，系统从 Checkpoint 恢复。
6. 系统生成 EtlPlan 和 SeaTunnel HOCON。
7. 系统执行语法、Schema 和策略门禁，并进行有限自动修复。
8. 用户确认结果，系统冻结不可变 PipelineVersion 并计算 SHA256。
9. 系统执行 Prepare，生成风险评级和准备单。
10. 数据审批人与安全审批人分别完成审批。
11. 系统校验审批与指纹，操作员执行 Commit。
12. Tool Broker 签发单次 Capability，创建 ExecutionRun 并投递 Outbox。
13. Celery Worker 验签后调用 SeaTunnel。
14. 有效数据写入影子表，异常数据写入错误表，监督引擎持续监控。
15. 质量通过后执行原子 Swap，生成运行报告和 Evidence Ledger 记录。

### 7.2 异常诊断与受管回滚

1. SeaTunnel 执行失败或监督指标超过预算。
2. 监督引擎触发硬中断并保存失败快照。
3. 诊断服务提取错误堆栈、指标和质量分流结果。
4. 系统生成可解释根因说明和修复建议。
5. 操作员确认回滚，Harness 校验权限、对象和回滚范围。
6. 系统清理未发布影子数据，恢复原状态并记录回滚结果。

## 8. 状态与协议要求

### 8.1 三层状态隔离

- **Conversation State**：自然语言交互历史和用户补充信息。
- **Workflow State**：LangGraph 节点状态、Checkpoint、门禁结果和修复次数。
- **Execution State**：ExecutionRun、SeaTunnel 作业 ID、运行指标和质量报告。

三类状态必须具备独立生命周期和权限边界，执行状态不能被对话状态直接覆盖。

### 8.2 执行状态建议

| 状态 | 说明 |
|---|---|
| Draft | Pipeline 正在编辑 |
| Generated | 已生成候选方案 |
| GateFailed | 门禁校验失败 |
| VersionFrozen | 已冻结不可变版本 |
| Preparing | 正在生成准备单 |
| PendingApproval | 等待审批 |
| Approved | 审批全部通过 |
| Committable | 满足 Commit 条件 |
| Queued | 已进入异步队列 |
| Running | SeaTunnel 执行中 |
| Succeeded | 执行和发布成功 |
| Failed | 执行失败 |
| Interrupted | 监督超限或人工中断 |
| RollingBack | 回滚中 |
| RolledBack | 已回滚 |
| Rejected | 审批拒绝 |

### 8.3 防重放要求

- Capability 必须包含唯一 ID、签发时间、过期时间、主体、工具、环境和制品指纹。
- Replay Guard 对 Capability ID 做原子消费标记。
- 重复消费、过期消费、主体不匹配、环境不匹配和指纹不匹配均拒绝。
- 所有拒绝事件写入 Evidence Ledger。

## 9. 数据与接口要求

### 9.1 主要实体

- Tenant、Project、ProjectMember、RoleAssignment
- DataSource、SecretReference、MetadataProfile
- Pipeline、PipelineVersion、EtlPlan、HoconArtifact
- QualityContract、RuntimeSupervisionContract
- Preparation、ApprovalDecision、Capability
- ExecutionRun、ExecutionMetric、QualityReport、ErrorRecord
- BenchmarkSuite、BenchmarkCase、BenchmarkRun
- EvidenceEvent、EvidenceLedgerBlock、OutboxMessage

### 9.2 API 分组

- 认证与项目：登录、租户、项目、成员、角色。
- 数据源：创建、更新、连通性测试、探查、Profile 查询。
- Pipeline：创建、需求对话、生成、门禁、版本冻结、Diff。
- 审批：Prepare、审批列表、审批决定、审批状态。
- 执行：Commit、ExecutionRun 查询、暂停、取消、回滚。
- 监控：指标、日志、质量报告、诊断。
- 安全治理：策略、Benchmark、评测结果、账本查询。

API 必须实现租户隔离、幂等键、权限校验、错误码规范和审计事件写入。涉及副作用的接口必须经 Harness Tool Broker。

## 10. 非功能需求

### 10.1 安全

- 全链路最小权限和租户隔离。
- Secret 使用受管加密存储，禁止明文进入前端、日志、模型上下文和账本。
- 元数据样本必须脱敏。
- P0/P1 风险默认阻断。
- Capability 使用 Ed25519 签名、短时有效和单次消费。
- 关键事件使用哈希链和签名检查点保存。

### 10.2 可靠性

- LangGraph Checkpoint 支持跨请求恢复。
- Transactional Outbox 保证业务事实和异步投递一致。
- Worker 任务支持幂等消费和失败重试策略。
- 影子表和原子 Swap 防止半发布。
- 受管回滚必须可重复执行且具备状态保护。

### 10.3 可观测性

- 记录请求关联 ID、租户、项目、主体、PipelineVersion 和 ExecutionRun。
- 监控 API、Celery、SeaTunnel、数据库和 Redis 的健康状态。
- 运行指标支持历史查询、阈值告警和审计关联。
- 日志分级并实施敏感字段脱敏。

### 10.4 性能

- 控制面接口不得同步等待长时间 ETL 执行。
- 长任务必须异步化并可查询状态。
- 元数据探查支持采样和超时控制。
- 运行指标应支持增量上报，避免高频全量刷新。

### 10.5 可维护性

- FastAPI、LangGraph、Celery、PostgreSQL、Redis 和 SeaTunnel 模块边界清晰。
- Provider、连接器、策略和质量规则采用可扩展接口。
- 关键协议具备单元测试、集成测试和端到端测试。
- 所有不可变制品均可通过摘要复核。

## 11. 页面与交互要求

### 11.1 通用交互

- 所有异步操作展示状态、进度、失败原因和重试入口。
- 所有危险操作提供影响范围、执行预算和回滚方案确认。
- 审批操作明确显示审批人、职责槽、制品指纹和审批意见。
- 敏感字段默认脱敏，具备权限的临时查看也必须记录审计事件。
- 页面需区分“可编辑草稿”和“不可变已冻结版本”。

### 11.2 Pipeline Studio 关键布局

- 左侧：需求输入、源端和目标端选择、澄清对话。
- 中部：EtlPlan、HOCON、DAG 和字段映射视图。
- 右侧：门禁结果、风险提示、质量契约和运行预算。
- 底部：版本信息、SHA256 摘要、生成历史和提交审批操作。

### 11.3 运行中心关键布局

- 顶部：ExecutionRun 状态、SeaTunnel 作业 ID、版本摘要和时间。
- 中部：吞吐、行数、字节、耗时、拒绝率和预算进度。
- 下部：运行日志、质量分流、错误码、根因诊断和回滚操作。

## 12. 关键异常处理

| 场景 | 系统行为 |
|---|---|
| 缺少必要需求参数 | LangGraph 中断提问，保存 Checkpoint |
| Metadata Profile 过期 | 阻止生成或提示重新探查 |
| HOCON 语法错误 | 门禁阻断，定位错误并允许有限修复 |
| Schema 不匹配 | 门禁阻断，展示字段 Diff |
| P0/P1 风险 | 直接阻断，不进入审批或执行 |
| 申请人尝试自批 | 拒绝审批并记录审计事件 |
| 审批后版本指纹变化 | 审批失效，要求重新 Prepare 和审批 |
| Capability 过期或重放 | Tool Broker 拒绝执行并记录证据 |
| Outbox 投递失败 | 保留待投递状态并由可靠机制重试 |
| 质量拒绝率超限 | 硬中断，禁止 Swap，生成诊断报告 |
| SeaTunnel 执行失败 | 记录失败快照，支持受管回滚 |
| 原子 Swap 失败 | 保持原正式表，进入可恢复失败状态 |

## 13. 验收标准

### 13.1 权限与安全

- 可以配置数据工程师、数据审批人和安全审批人。
- 申请人自批和职责混用被系统强制拦截。
- 数据源凭据、样本和日志全链路无敏感明文泄露。
- 未授权、过期和重复 Capability 均无法触发执行。

### 13.2 数据源与元数据

- 至少完成一种异构数据库和一种文件或 API 数据源接入。
- 可完成安全连通性测试、只读 Metadata Profile 和脱敏样本展示。
- 探查过程不会修改源端业务数据。

### 13.3 智能生成

- 自然语言需求可触发 LangGraph 状态机。
- 缺少参数时能够中断提问，补充后从 Checkpoint 恢复。
- 能生成 EtlPlan 和 SeaTunnel HOCON，并展示拓扑、字段映射和 Diff。
- 确定性门禁能够完成语法和 Schema 校验，并在通过后生成 SHA256 不可变版本。

### 13.4 审批与执行

- 能完整执行 `prepare → approve → commit`。
- 能生成 Preparation、完成双职责审批并签发单次 Capability。
- Celery Worker 能调度 SeaTunnel 完成数据搬运。
- 有效数据写入影子表，异常数据进入错误表并生成质量报告。
- 质量通过后可通过原子 Swap 发布正式表。

### 13.5 监控与回滚

- 运行中心可查看实时或准实时运行指标、日志和质量分流。
- 超预算或异常时能够硬中断并生成可解释根因诊断。
- 操作员能够执行受管回滚，清理未发布数据并恢复原状态。
- 关键链路能够生成可校验的 Evidence Ledger 记录。

### 13.6 评测

- 能运行版本化 Benchmark 测试集。
- 能输出生成准确率、P0/P1 安全拦截率等评测报告。
- 至少完成一个端到端场景演示。

## 14. 端到端演示场景

### 14.1 MySQL 至 Doris 业务宽表同步

1. 数据工程师配置 MySQL 源端和 Doris 目标端。
2. 系统探查订单表、用户表并生成脱敏 Metadata Profile。
3. 用户输入“将订单和用户信息汇总为 Doris 业务宽表，并按更新时间增量同步”。
4. 系统发现缺少主键去重逻辑，触发澄清。
5. 用户补充去重字段后，系统生成 EtlPlan、HOCON、DAG 和字段映射。
6. 门禁通过后冻结版本并创建 Preparation。
7. 数据审批人核对字段映射，安全审批人确认敏感字段未明文暴露。
8. 操作员 Commit，Worker 调度 SeaTunnel。
9. 有效数据进入影子表，异常格式数据进入错误表。
10. 质量报告通过后执行原子 Swap，上线正式宽表。
11. 系统展示 ExecutionRun、质量报告和证据账本。

### 14.2 日志同步异常硬中断与回滚

1. 日志清洗任务运行过程中，源端格式发生变化。
2. 错误分流率超过 20% 阈值。
3. 运行监督引擎硬中断 SeaTunnel 作业，保存失败快照。
4. 诊断服务提示字段类型解析异常。
5. 操作员发起受管回滚。
6. 系统清理影子表未发布数据，恢复正式表并生成回滚证据。
