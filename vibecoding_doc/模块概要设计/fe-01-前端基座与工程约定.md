## 1. 职责与边界

- **做什么**
  1. 装配应用：`main.ts` 创建 app / pinia / router，注册「刷新失败」回调，挂载 `App.vue`。
  2. 提供唯一 HTTP 出口 `api/client.ts`：baseURL、请求头注入（`Authorization`、`Idempotency-Key`）、拆响应信封、抛业务错误、401 静默刷新单飞、统一错误提示入口。
  3. 提供与后端**逐字对齐**的类型层 `types/`（枚举字面量、DTO、分页信封）与枚举标签映射 `utils/enums.ts`。
  4. 提供路由表与守卫（登录态 → 角色过滤 → 面包屑/菜单数据）、403 页与 404 兜底。
  5. 提供布局与页面骨架组件（`layouts/`、`components/common/`）。
  6. 提供横切 composables：轮询（2s，不引 WebSocket）、分页查询、异步任务三态、敏感值临时查看、幂等键。
  7. 固化交互与视觉规范：危险操作确认、脱敏默认开启、「可编辑草稿」与「不可变已冻结版本」的区分。

- **不做什么**
  - **组件不直接调 axios、不拼 URL**：一切请求经 `api/<域>.ts`；视图只调 store 或 api 函数。
  - **不做授权判定**：`meta.requiredRoles` 只用于菜单/路由的**可见性过滤**（体验优化）；真正的鉴权是后端查 `role_assignment`。前端收到的 403 只决定展示形态。
  - **不解析 JWT**：角色、租户、项目一律取 `GET /auth/me`（JWT 只作 `Authorization` 头原样透传）。
  - **不做业务聚合**：成功率、拒绝率、平均吞吐等一律用后端返回值，前端不做分子分母运算。
  - **不存敏感值**：localStorage 只放 access/refresh token、过期时刻、用户摘要；凭据、样本原文永不进任何前端存储。
  - 不承载领域算法（门禁、PDP 评级、指纹计算）——那些在 `backend/engines/`。

- **所在分层**：前端自有的单向依赖 `views/components → stores → api → client → axios`；`types/`、`utils/` 是无依赖叶子层，可被任意层引用；`layouts/` 只依赖 stores 与 router。禁止反向依赖（`api/` 不 import `stores/`，`stores/` 不 import 视图）。

## 3. 对外接口

### 3.1 `api/client.ts`（唯一 HTTP 出口）

```ts
export class BizError extends Error {
  readonly code: string          // 后端 ErrorCode 字面量，或 NETWORK_ERROR / HTTP_<status>
  readonly requestId: string     // 后端 request_id，排障用
  readonly status: number        // HTTP 状态码，0 = 网络失败
  readonly details: Record<string, unknown>   // VALIDATION_ERROR 时为 { fields: [{loc, reason}] }
}

export const http: AxiosInstance
export function httpGet<T>(url: string, config?: AxiosRequestConfig): Promise<T>
export function httpPost<T>(url: string, data?: unknown, config?: AxiosRequestConfig): Promise<T>
export function httpPut<T>(url: string, data?: unknown, config?: AxiosRequestConfig): Promise<T>
export function httpDelete<T>(url: string, config?: AxiosRequestConfig): Promise<T>

export function setUnauthorizedHandler(handler: () => void): void
export function readAuth(): PersistedAuth | null
export function writeAuth(auth: PersistedAuth): void
export function clearAuth(): void

declare module 'axios' {           // 请求级开关，调用方按需设置
  interface AxiosRequestConfig {
    _retry?: boolean               // 已因 401 重放过一次
    skipAuthRefresh?: boolean      // /auth/login、/auth/refresh 必须置 true
    skipErrorToast?: boolean       // 由调用方自行处理错误提示
  }
}
```

契约：**拆信封后直接 resolve `data`**（成功响应 `{code:"OK", message, data, request_id}`）；失败一律 reject `BizError`。调用方不得依赖 axios 原始 `AxiosResponse`。

## 4. 数据模型

前端不直连数据库；本节只固化**本地持久化**与**引用的后端结构**。

| 本地键 | 内容 | 生命周期 |
|---|---|---|
| `elt-agent.auth` | `PersistedAuth`：`{accessToken, refreshToken, expiresAt, user}`，**不含**任何敏感值 | 登录写入，登出/刷新失败清除 |

引用的后端表（字段名逐字对齐，前端只读）：`app_user`（`username/display_name/email/status`）、`project`（`code/name/env/status`）、`project_member`、`role_assignment`（`role`）。列表分页统一为 `{items: T[], meta: {page, page_size, total}}`（对应 `core/response.py` 的 `Page`）。

## 5. 核心流程

### 5.1 会话建立与页面刷新恢复

1. 用户在 `/login` 提交 `username/password/tenant_code?` → `POST /auth/login`（`skipAuthRefresh: true`）。
2. `auth.applyTokenPair()` 写内存 + `localStorage['elt-agent.auth']`。
3. 跳转 `redirect` query 或 `/dashboard`；`loadProfile()` 拉 `GET /auth/me` 得到 `projects[].roles`。
4. 刷新页面：store 初始化时 `readAuth()` 恢复 token 与用户摘要；`profile` 为空则重新 `loadProfile()`。
5. `readAuth()` 遇到 JSON 损坏或字段类型不符 → 返回 `null`（按未登录处理），不让应用白屏。

### 5.2 401 静默刷新（单飞）

```
组件 ──httpGet──▶ http ──▶ 后端 401
                              │
                              ├─ config._retry 已 true 或 skipAuthRefresh ──▶ clearAuth + 回调 + 跳 /login
                              └─ 否则 _retry=true
                                   ├─ refreshing 为空 → 发起 POST /auth/refresh（裸 axios，绕开拦截器）
                                   └─ 复用同一 refreshing Promise（并发 401 只刷新一次）
                                        ├─ 成功 → writeAuth(新 token) → http.request(config) 重放
                                        └─ 失败 → clearAuth → unauthorizedHandler() → 跳 /login
```

回调在 `main.ts` 注册（`setUnauthorizedHandler`），避免 `client → router / store` 的循环依赖。

### 5.3 路由守卫与角色过滤

1. `to.meta.public !== true && !isAuthenticated` → 重定向 `/login?redirect=<fullPath>`。
2. 已登录访问 `/login` → 重定向 `/dashboard`。
3. `meta.requiredRoles` 非空且 `profile` 为空 → 先 `await loadProfile()`（避免刷新页面时误判 403）。
4. 角色集合与 `requiredRoles` 无交集 → 重定向 `/403`（**不**静默跳首页，避免「点了没反应」）。
5. `afterEach` 写 `document.title` 与面包屑（由 `meta.title` + 路由层级生成）。

### 5.4 轮询生命周期（`usePolling`）

```
mount → 立即取一次 → setInterval(intervalMs) → 每次仅在无 in-flight 时发请求
document.hidden → 暂停；visibilitychange 恢复 → 立即补一次
unmount → clearInterval + AbortController.abort()
```

默认 `intervalMs = 2000`（《需求对齐记录》§二.7）；**不引 WebSocket**。非活跃指标（无运行中实例时）降到 `30000`；同一页面最多一个轮询器，多个数据块共用一次接口调用。

## 6. 关键算法与规则

### 6.1 拦截器规则

| 时机 | 规则 |
|---|---|
| 请求 | 有 token → 设 `Authorization: Bearer <access_token>`；token 缺失不阻断（由后端判 401） |
| 请求 | 方法 ∈ {POST, PUT, PATCH, DELETE} 且未显式提供 → 设 `Idempotency-Key`（`crypto.randomUUID()`），并挂到 config 上供重放复用 |
| 响应 | 体含 `code: string` 且含 `data` 字段 → 返回 `data`；否则原样返回（兼容 `/healthz` 等非信封响应） |
| 响应 | `code !== 'OK'` → 抛 `BizError`（**待补**，见 §10 第 3 条） |
| 失败 | 规整为 `BizError`；`status === 0` → code `NETWORK_ERROR`；无信封 → `HTTP_<status>` |

**幂等键语义**：一次用户动作 = 一个 key；401 刷新重放沿用同一 config（同一 key），保证不会因刷新重复创建资源；用户点「重试」算新动作 → 新 key。

### 6.2 code → 提示文案映射（`utils/errors.ts` 待建）

| code | 提示方式 | 文案 |
|---|---|---|
| `BAD_CREDENTIALS` | 登录表单行内错误（不 toast） | 用户名或密码错误 |
| `ACCOUNT_LOCKED` | 行内 | 账号已被临时锁定，请稍后重试 |
| `TOKEN_EXPIRED` / `UNAUTHENTICATED` | 拦截器接管 | 登录状态已失效，请重新登录 |
| `FORBIDDEN` / `ROLE_REQUIRED` | toast 错误 + 页面无权限态 | 无权执行该操作／缺少所需职责槽 |
| `TENANT_MISMATCH` | toast 错误 | 跨租户访问被拒绝 |
| `VALIDATION_ERROR` | 映射到表单字段（`details.fields[].loc` → `reason`） | 参数校验失败 |
| `NOT_FOUND` | 页面空态或 toast | 资源不存在 |
| `CONFLICT` | toast 警告 + 刷新按钮 | 数据已被修改，请刷新后重试 |
| `IDEMPOTENCY_CONFLICT` | toast 警告 | 请求与已有操作冲突，请刷新后重试 |
| `RATE_LIMITED` | toast 警告 | 操作过于频繁，请稍后重试 |
| `INTERNAL_ERROR` / `NETWORK_ERROR` | toast 错误（附 `request_id` 可复制） | 服务内部错误／网络异常，请稍后重试 |
| 未登记的 code | toast 错误 | **直接展示后端 `message`**（后端 message 已是可解释中文），dev 下 `console.warn` |

### 6.4 通用交互与视觉规范（PRD §11.1）

| 场景 | 规范 |
|---|---|
| 异步三态 | 每个数据区块独立维护 `idle / loading / ready / error`；首次加载用骨架屏，刷新用局部 loading 遮罩，**不用全屏遮罩**覆盖已渲染内容 |
| 危险操作 | 统一用 `DangerConfirmDialog`：标题 + **影响范围** + **执行预算** + **回滚方案** 三段必填正文 + 输入资源名二次确认；缺任一段则不展示确认按钮 |
| 敏感字段 | 默认渲染掩码；有权限者点「临时查看」→ 调后端解敏接口（记审计）→ 30s 后自动回掩；**不允许前端本地解密或缓存明文** |
| 草稿 vs 冻结 | 草稿态：页面顶部黄色 `DraftFrozenBadge`「可编辑草稿」+ 输入控件可用；冻结态：蓝色锁标「不可变版本 v{n} · {sha256 前 8 位}」+ 全页只读 + 底部「基于此版本生成新版本」按钮 |
| 制品指纹 | 一律用 `ArtifactHash` 组件显示（等宽字体、前 8 + 后 8 加省略、悬停复制全文、可跳转版本详情） |

### 6.5 首屏与构建约束

- Element Plus 走 `unplugin-auto-import` + `unplugin-vue-components` 按需注入（`vite.config.ts` 已配）；禁止 `app.use(ElementPlus)` 全量注册。
- ECharts 只 `import` 用到的图表与组件（`echarts/core` + `BarChart/PieChart/LineChart` + `CanvasRenderer`），禁止 `import * as echarts`。
- Vue Flow、CodeMirror 属重量级且仅 Studio 需要 → 由 `views/pipeline/` 的路由 `import()` 拆独立 chunk，不进首屏。
- `.env` 中 `VITE_` 前缀变量会被内联进产物，**禁止**放任何密钥、连接串；环境变量只允许 `VITE_API_BASE_URL`（若新增轮询间隔等，须在 `env.d.ts` 同步声明）。

## 7. 错误码与拒绝语义

前端**不写证据账本**（账本只由后端 `harness.EvidenceLedger.append()` 写入）。前端对错误码的处理语义如下：

| 触发条件 | 错误码 | HTTP | 前端行为 |
|---|---|---|---|
| 令牌缺失/无效 | `UNAUTHENTICATED` | 401 | 拦截器刷新一次；失败清会话跳 `/login` |
| 令牌过期 | `TOKEN_EXPIRED` | 401 | 同上 |
| 凭据错误 | `BAD_CREDENTIALS` | 401 | 登录表单行内错误（`skipAuthRefresh`） |
| 账号锁定 | `ACCOUNT_LOCKED` | 423 | 登录表单行内错误 |
| 角色不足 | `ROLE_REQUIRED` / `FORBIDDEN` | 403 | 403 页或禁用 + tooltip；**不重复请求** |
| 跨租户 | `TENANT_MISMATCH` | 403 | 403 页 + 提示联系管理员 |
| 参数不合 schema | `VALIDATION_ERROR` | 422 | `details.fields` 映射到表单；提交按钮回到可点 |
| 同 key 不同 body | `IDEMPOTENCY_CONFLICT` | 409 | 提示刷新后重试；**不自动重发** |
| 未捕获/DB 异常 | `INTERNAL_ERROR` | 500 | toast 错误 + 展示可复制 `request_id` |

## 8. 安全与合规约束

- **无明文 Secret**：前端不接触数据源凭据；`DataSourceEndpoint` 类型不允许出现 `password/token/secret` 键（后端 `schemas/` 亦校验，前端同步做类型层防呆）。
- **脱敏默认开启**：所有样本/字段值默认掩码渲染；解敏必须是一次显式用户动作 + 后端审计事件（`EvidenceEventType.SECRET_MATERIALIZED` 之外的解敏事件由后端定义，见 fe-03 §8）。
- **token 存放**：仅 `localStorage` 放 token（不走 cookie，避免 CSRF 面）；不在 URL、日志、`console` 输出 token；`request_id` 可在界面展示，便于排障。
- **不解析 JWT**：不信任 JWT 内 `projects[]` 声明做可见性判定；角色/项目一律以 `/auth/me` 为准（角色可能已被回收）。
- **越权兜底**：任何情况下前端隐藏按钮都不能当作安全措施，后端 403 才是拒绝依据；因此前端**不**对 403 做「静默跳过」。
- **审计可见**：危险操作确认弹窗中展示将要提交的关键事实（版本 `sha256`、影响范围、预算），与后端写账本的内容一致，便于事后对账。

## 9. 测试要点

- **单元测试**（vitest + happy-dom）
  - `client` 拦截器：① 注入 `Authorization`；② POST 自动注入 `Idempotency-Key` 且重放沿用同一 key；③ 成功响应剥信封返回 `data`；④ 失败响应抛 `BizError` 且 `code/requestId/details` 正确；⑤ 401 → 刷新成功 → 原请求被重放一次且仅一次；⑥ 并发 3 个 401 → 只发 1 次 `/auth/refresh`；⑦ 刷新失败 → `clearAuth` + 回调被调用且不重放；⑧ `skipAuthRefresh` 请求不触发刷新；⑨ 网络错误 → `NETWORK_ERROR`、`status=0`。
  - `utils/enums`：未知枚举值 → 返回原文 + `unknown: true`，不抛异常。
  - `usePolling`：`document.hidden` 时暂停；卸载后无定时器残留（fake timers 断言）。
  - `readAuth`：损坏 JSON / 缺字段 → `null`。
- **集成测试**（真后端 + ECS）：登录 → 刷新页面保持登录态 → 访问受保护路由；后端返回 403 时落到 `/403`。
- **必须覆盖的反例**：越权（前端显示按钮但后端 403 时必须正确展示拒绝，而非静默失败）；刷新令牌被吊销后并发请求不产生刷新风暴。
- **类型检查**：`vue-tsc --noEmit` 必须零错误（`strict` + `noUnusedLocals` 已开）。
