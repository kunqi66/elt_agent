## 1. 职责与边界

- **做什么**
  1. 呈现当前**项目**的资产计数：数据连接数（含禁用数）、Pipeline 数、PipelineVersion 数。
  2. 呈现待审批 `Preparation` 列表，并**逐槽**显示数据审批槽与安全审批槽的完成状态。
  3. 呈现运行健康度：成功率、失败率、运行中实例数、近期异常（含异常类型与发生时间）。
  4. 呈现核心指标：读取行数、写入字节数、平均吞吐、错误分流率（拒绝率）。
  5. 呈现资源分布图与快捷入口（新建连接、创建 Pipeline、审批待办、查看运行）。
  6. 提供时间范围选择与手动刷新，以及空态/加载/错误三态。

- **不做什么**
  - **不在前端做任何聚合计算**：成功率、失败率、平均吞吐、拒绝率、各项计数一律由后端返回；前端只做单位换算与百分比格式化（`0.0321` → `3.21%`）。
  - **不做权限过滤**：接口只返回当前账号可见范围；配置了 `requiredRoles` 的区块（审批待办）在后端 403 时展示无权限空态，不用前端角色集合反推。
  - **不展示明细**：此处只给「计数 + 概览 + 跳转」，运行日志、质量报告明细、错误码分布归 fe-06。
  - **不做的动作**：审批（fe-05）、Commit/回滚（fe-06）、数据源增删改（fe-03）都不在本页发起，只提供跳转。
  - 不引入 WebSocket；不订阅 SSE。

- **所在分层**：`views/dashboard/` 只依赖 fe-01 的 `components/common/`、`composables/usePolling`、`api/monitor.ts` 与 `stores/project.ts`；不直接 import axios，不 import 其他 feature 的 store。

## 4. 数据模型

前端只读，字段名与后端表逐字对齐；`MonitorSummary` 为聚合视图，**不落表**。

```ts
/** GET /monitor/summary 响应（建议契约，待 be-21 确认） */
export interface MonitorSummary {
  generated_at: string              // ISO8601，用于展示「数据时间」
  range: '24h' | '7d' | '30d'
  assets: MonitorAssets
  health: MonitorHealth
  metrics: MonitorMetrics
  series: MonitorSeries
  distribution: ResourceDistribution
  pending_preparations: PendingPreparationBrief[]
}

export interface MonitorAssets {
  datasource_count: number          // data_source where status='active'
  datasource_disabled_count: number
  pipeline_count: number
  pipeline_version_count: number    // pipeline_version 计数
  metadata_profile_ready_count: number
  metadata_profile_expired_count: number   // status='expired'，用于提示「需重新探查」
}

export interface MonitorHealth {
  window: '24h' | '7d' | '30d'
  run_total: number
  run_succeeded: number
  run_failed: number
  run_running: number               // RunStatus.active_states() 的 queued/running/paused/rolling_back 计数
  run_interrupted: number
  success_rate: number              // numeric(6,4)，如 0.8500
  failure_rate: number              // numeric(6,4)
  recent_anomalies: AnomalyBrief[]  // 上限 5 条
}

export interface AnomalyBrief {
  run_id: number
  pipeline_id: number
  pipeline_name: string
  severity: 'warning' | 'critical'  // critical=硬中断/失败；warning=超预警阈值
  summary: string                   // 已脱敏的一句话，如「拒绝率 0.2350 超预算 0.2000」
  occurred_at: string
}

export interface MonitorMetrics {
  read_rows: number                 // bigint，JSON number；> 2^53 场景见 §10
  written_rows: number
  written_bytes: number             // bigint
  reject_rows: number
  avg_throughput: number            // numeric(18,4)，行/秒
  reject_rate: number               // numeric(6,4)
}

export interface MonitorSeries {
  points: Array<{ ts: string; throughput: number; reject_rate: number; read_rows: number }>
}

export interface ResourceDistribution {
  by_type: Array<{ type: DataSourceType; count: number }>
  by_env: Array<{ env: Env; count: number }>
  by_sensitive_level: Array<{ sensitive_level: SensitiveLevel; count: number }>
}

/**
 * 待审批条目**不自造 DTO**：直接复用 fe-05 §4 的 `PreparationSummary`。
 * 本页用到的字段：id / pipeline_id / pipeline_name / version_no / artifact_sha256 /
 * risk_level / sensitive_level / environment / status / required_slots / decided_slots /
 * creator_name / frozen_at / expires_at。
 */
export type PendingPreparationBrief = PreparationSummary
```

**双槽状态渲染**：用 `required_slots` 与 `decided_slots` 做**集合成员判断**（该槽是否已出决定），槽内具体决定（通过/拒绝/退回）与审批人在悬停卡片中才请求详情；前端不比对 `approval_decision` 原始行，也不重算「谁能审」。

对应后端来源：`data_source` / `pipeline` / `pipeline_version` / `metadata_profile`（§2）、`preparation` `approval_decision`（§4）、`execution_run` `execution_metric` `quality_report`（§5）。全部聚合在服务端完成。

## 5. 核心流程

### 5.1 首屏加载

1. 从 `stores/project.ts` 取 `currentProjectId`；为空则先展示「请选择项目」空态（不请求）。
2. 并行发起 `GET /monitor/summary`（含 `range`）与 `GET /preparations?slot_state=pending`。
3. 两个请求各自维护 `loading/error`：一个失败不阻塞另一块渲染（局部错误态 + 重试按钮）。
4. `summary` 返回后按 `assets / health / metrics / series / distribution / pending_preparations` 分发到各组件；`pending_preparations` 与独立列表接口取其一，若 summary 已含列表则以 summary 为准（避免两份数据打架，见 §10 第 3 条）。

### 5.2 轮询编排

| 区块 | 空闲（`run_running === 0`） | 活跃（`run_running > 0`） |
|---|---|---|
| `assets` / `distribution` | 60s | 60s |
| `pending_preparations` | 30s | 30s |
| `health` / `metrics` / `series` | 30s | **2s** |

- 所有区块共用**一次** `GET /monitor/summary` 请求（一个定时器），避免每卡一个请求。
- `document.hidden` 时整体暂停；恢复可见时立即补一次。
- 切 `range` 是用户动作 → 立即重取并把该区块置 `loading`，不改变轮询周期。

### 5.3 状态机（视图级）

| 状态 | 事件 | 新状态 | 渲染 |
|---|---|---|---|
| `idle` | `onMounted` 且有 currentProjectId | `loading` | 骨架屏 |
| `loading` | 请求成功 | `ready` | 数据 + `generated_at` |
| `loading` | 请求失败 | `error` | 错误卡片 + 重试按钮（展示 `code` 与 `request_id`） |
| `ready` | 轮询请求失败 | `ready`（数据保留） | 顶部细黄条「数据可能过期」+ 静默重试 |
| `ready` | 切换项目 | `loading`（清空旧数据） | 骨架屏（避免展示上一个项目的数据） |

**非法转移处理**：项目切换竞态用请求序号（`requestSeq`）丢弃过期响应；轮询失败**不**降级为 `error`，避免 2s 一次的错误闪烁。

## 6. 关键算法与规则

### 6.1 指标卡清单与数据映射

| 卡片 | 字段 | 展示格式 | 无数据/为 0 时 |
|---|---|---|---|
| 数据连接 | `assets.datasource_count`（副文案：禁用 `datasource_disabled_count`） | 千分位整数 | `0`，副文案「暂无连接」+ 跳转新建 |
| Pipeline | `assets.pipeline_count` | 千分位 | `0` + 「创建 Pipeline」 |
| 不可变版本 | `assets.pipeline_version_count` | 千分位 | `0` |
| Metadata Profile | `assets.metadata_profile_ready_count` | 千分位 | 过期数 > 0 时显示警示徽标「{n} 个已过期」 |
| 运行成功率 | `health.success_rate` | `85.00%` | 无运行记录时显示 `—`（分母为 0，**不显示 0%**） |
| 运行失败率 | `health.failure_rate` | `10.00%` | 同上 |
| 运行中 | `health.run_running` | 整数 + 脉冲点 | `0` 时灰色静态 |
| 近期异常 | `health.recent_anomalies` | 列表（最多 5 条） | 「近 {range} 无异常」绿色态 |
| 读取行数 | `metrics.read_rows` | 万/亿分级（`1.23 亿行`） | `0` |
| 写入字节 | `metrics.written_bytes` | `GiB/MiB` 二进制单位，一位小数 | `0 B` |
| 平均吞吐 | `metrics.avg_throughput` | `12,000.5 行/秒` | `—` |
| 错误分流率 | `metrics.reject_rate` | `3.21%`，超 80% 预算时转橙色，超标红 | 无质量报告时 `—` |

**格式化规则**（`utils/format.ts`，纯展示，非聚合）：行数 ≥ 1e8 → `亿`；≥ 1e4 → `万`；否则千分位。字节按 1024 进制。比率 `numeric(6,4)` 直接 `× 100` 保留两位小数。任何 `null`/`undefined` 显示 `—`，不显示 `NaN`。**不做四舍五入以外的任何推算**（如趋势箭头需要后端给 `delta`，本轮不给则不做趋势标记）。

### 6.2 图表字段映射（ECharts）

| 图 | 图表类型 | x / 类别字段 | y / 数值字段 | 说明 |
|---|---|---|---|---|
| 数据源类型分布 | 环形饼图（`PieChart`，`radius: ['45%','70%']`） | `distribution.by_type[].type`（经 `enumLabel('DataSourceType')`） | `count` | 中心显示连接总数；图例右侧，点击筛选（仅本地高亮，不重新请求） |
| 环境分布 | 横向条形图（`BarChart`，`yAxis: category`） | `by_env[].env`（`dev/staging/prod`，prod 用警示色） | `count` | 用 `emphasis` 高亮 prod |
| 敏感级别分布 | 横向堆叠条形图 | `by_sensitive_level[].sensitive_level` | `count` | 配色按敏感度递进：`public→internal→confidential→restricted` |
| 吞吐与拒绝率趋势 | 折线/面积图（`LineChart`，双 y 轴） | `series.points[].ts` | 左轴 `throughput`，右轴 `reject_rate` | 右轴画预算阈值虚线（≤ 100 点时用 `markLine`，超出则不画标记线，见 §10 第 5 条） |

统一约束：`import { use } from 'echarts/core'` 按需注册；空数据（length 0）不渲染空画布，改渲染 `EmptyState`；`resize` 监听用一个共享指令，避免每图各挂一个 `ResizeObserver` 泄漏。

### 6.3 双槽状态渲染

对 `required_slots`（通常为 `['checker_data','checker_security']`）逐项渲染 `StatusTag`：槽在 `decided_slots` 中 → 「已决定」（info，实际决定与审批人由悬停请求详情给出）；不在其中 → 「待审批」（warning）。条目整体状态用 `preparation.status`（`PreparationStatus`）渲染；`risk_level` 用 `RiskLevelTag`（P0/P1 红、P2 橙、P3 灰）；`expires_at` 距现在 < 24h 时在行内加「即将过期」。

## 7. 错误码与拒绝语义

| 触发条件 | 错误码 | HTTP | 本页行为 |
|---|---|---|---|
| 未登录 / 令牌失效 | `UNAUTHENTICATED` `TOKEN_EXPIRED` | 401 | 由 fe-01 拦截器统一处理（刷新或跳登录） |
| 无该项目访问权 | `FORBIDDEN` `TENANT_MISMATCH` | 403 | 区块渲染无权限空态；不重试、不轮询 |
| 缺职责槽读审批列表 | `ROLE_REQUIRED` | 403 | 待审批卡渲染「无审批权限」，其余区块不受影响 |
| `range` 取值不在枚举内 | `VALIDATION_ERROR` | 422 | 回退到 `24h` 并 toast；时间选择器同时做前端白名单 |
| 项目不存在 | `NOT_FOUND` | 404 | 页面级空态 + 返回项目列表 |
| 服务端异常 | `INTERNAL_ERROR` | 500 | 区块错误态 + 可复制 `request_id`；轮询退避到 30s |

前端不写证据账本。审批/执行相关的协议类拒绝（`SELF_APPROVAL_FORBIDDEN` 等）不在本页发生。

## 8. 安全与合规约束

- **租户与项目过滤**：请求一律带 `project_id`；后端强制过滤，前端不缓存跨项目数据（切项目即清空）。
- **脱敏**：`recent_anomalies[].summary` 与图表标签都由后端脱敏后下发；前端**不得**在 tooltip 里拼接任何来自错误的原始值。
- **无明文 Secret**：本页不出现连接串、账号、密码；数据源只展示名称/类型/环境/敏感级别。
- **权限展示**：审批列表对 `auditor` 只读（无「审批」按钮）；按钮隐藏仅作体验，拒绝以后端为准。
- **本地存储**：本页不写 localStorage（避免把项目数据落到磁盘）。
- **可观测**：错误 toast 展示 `request_id`，便于与后端 structlog 对齐；不上报任何用户数据到第三方。

## 9. 测试要点

- **单元测试**
  - 格式化：`formatRows(123456789)` → `1.23 亿行`；`formatBytes(5368709120)` → `5.0 GiB`；`formatRate(null)` → `—`；`success_rate = 0` 且 `run_total = 0` → 显示 `—` 而不是 `0.00%`。
  - 图表映射：`distribution.by_type` 空数组 → 渲染 `EmptyState` 且不初始化 ECharts 实例。
  - 未知枚举：`by_type` 出现 `"hive"`（后端新增）→ label 显示 `hive`、不抛异常。
  - `usePolling`：`run_running` 由 0 变 1 时周期切到 2s；变回 0 时切到 30s；组件卸载后无定时器（fake timers）。
  - 组件：`PendingPreparationCard` 在 `slots` 只有 `checker_data` 时不渲染安全槽占位（**不**在前端补槽——缺槽说明后端数据异常，应原样呈现）。
- **集成测试**：切项目后旧响应到达 → 被 `requestSeq` 丢弃，不污染新项目数据；后端 403 的审批列表不影响资产卡渲染。
- **必须覆盖的反例**：越权项目 id（`project_id` 属于他人租户 → 403，页面不得残留上一项目数字）；轮询期间断网 → 保留旧数据并提示过期，不白屏。

## 10. 未决与风险

| 事项 | 现状 | 建议 / 验证方式 |
|---|---|---|
| `/monitor/*` 无已定义契约 | 总纲 §7 只给分组名 | 本页给出 `MonitorSummary` 建议契约，需 with be-21 定稿；落地前前端用 mock，类型上标 `TODO(be-21)` |
| `bigint` 字段 JSON 精度 | `read_rows`/`written_bytes` 为 `bigint`，超过 2^53 时 JSON number 会丢精度 | 建议后端以字符串下发这两类字段（前端按字符串格式化）；需拍板，否则大流量下展示值可能与库内不符 |
| 待审批列表数据来源重复 | `summary.pending_preparations` 与 `/preparations` 两处 | 建议只保留 `/preparations`（fe-05 同源），summary 只给 `pending_count`；避免两处口径漂移 |
| 「近期异常」定义未冻结 | 未定义窗口与条数 | 建议 = `range` 窗口内 `run_interrupted`/`run_failed`/`supervision.warning` 事件，取最近 5 条；需 be-16 be-21 确认 |
| 阈值虚线依据 | 预算随 Preparation 不同而变化，概览聚合时没有唯一阈值 | 建议：概览不画阈值线，只在本页展示「超 80% 预警」计数；阈值线留到 fe-06 单实例视图 |
