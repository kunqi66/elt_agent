## 1. 职责与边界

- **做什么**
  - 把 `quality_contract.rules`（JSON 规则）编译为**可下推到数据面**的判定表达式：违规谓词、分流路由列、错误表列清单。
  - 定义并校验「有效数据进影子表、违规行进错误表」的**分流口径**（含 `warn` 与 `reject` 的差别与优先级）。
  - 在作业结束后**合成不可变质量报告**（`quality_report`）：`valid_rows / rejected_rows / reject_rate / error_code_dist / rule_hits / passed / diagnostics`。
  - 提供纯函数规则求值（`engines/quality/rules.py`），用于单测、L1 假执行器与数据面 SQL 的口径对齐。
  - 通过 `clients/target/errors_table.py` 只读查询目标端错误表，作为拒绝率与错误码分布的**最可信来源**（见《概要设计总纲》§8）。
  - 向 be-18 提供 `passed` 判定，向 be-19 提供 `diagnostics` 与错误码分布。
- **不做什么**
  - 不组装 SeaTunnel HOCON 全文（只产出 SQL 片段与列清单，装配归 [be-10](be-10-EtlPlan与HOCON生成.md)）。
  - 不采集运行指标、不做预算判定与硬中断（归 [be-16](be-16-运行监督与硬中断.md)）。
  - 不执行 Swap / 回滚（归 [be-18](be-18-原子发布与受管回滚.md)）。
  - 不做根因的自然语言解释（归 [be-19](be-19-根因诊断.md)）；本模块只产出结构化的 `diagnostics`。
  - **不搬运业务数据**：违规行原文不进控制面进程，控制面只拷贝目标端算好的 `payload_digest`。
- **所在分层**：`engines/quality/`（纯函数，仅 Pydantic + 标准库，**禁止** fastapi / DB / Redis / 网络 / LLM）→ `clients/target/errors_table.py`（目标端只读）→ `services/quality.py`（编排、租户过滤、证据事件）→ `api/monitor.py`（只读转发）。依赖方向单向向下，`engines/quality` 不得反向 import 任何上层。

目标端**错误表**为实体表（不在控制面库），列与 `error_record` 对齐并多一列 `run_id`：

```sql
-- Doris（由 deploy/doris/init 建，物理名取自 quality_contract.error_table_target.table）
CREATE TABLE dw_demo.etl_error_record (
    run_id BIGINT NOT NULL, rule_id VARCHAR(64) NOT NULL, field_name VARCHAR(64) NOT NULL,
    error_code VARCHAR(32) NOT NULL, payload_digest CHAR(64) NOT NULL,
```

`run_id` 由数据面注入为常量列，因此**同一错误表可被多次运行共用**，控制面一律以 `WHERE run_id = ?` 计数，不复用其他运行的计数。

## 5. 核心流程

```
be-10 装配 HOCON ←── compile_contract + render_*（本模块，M2 门禁期已校验）
SeaTunnel: source → tagged(路由列) → valid_rows → sink(影子表)
                                  └→ rejected_rows → sink(错误表)
作业终态(成功/硬中断) ──▶ services/quality.finalize_report(run_id)
        ├─ 查目标端：valid=COUNT(影子表)、rejected=COUNT(错误表 WHERE run_id)
        ├─ 算分布与命中 → decide_passed → INSERT quality_report（幂等）
        ├─ INSERT error_record（拷贝错误表摘要，不回传原文）
        └─ EvidenceLedger.append(quality.report_generated)
passed=True → 投递 outbox(etl.target.publish_swap) ──▶ be-18
passed=False → run=failed + run.failed 事件 + 禁止 Swap
```

1. **编译期（M2 门禁）**：`services/...→compile_contract` 校验每条规则；失败即 `GATE_BLOCKED`，版本不允许冻结。
2. **运行期**：worker 从冻结版本取 `quality_contract`，编译结果驱动 `be-10` 的 transform 片段（`etl_run_id` 用本次 `run.id` 常量注入）。
3. **终态判定**：`tasks/execution.py` 在 SeaTunnel 作业进入终态后调 `finalize_report`；`tasks/supervision.py` 补扫「作业已终态但 `quality_report` 缺失」的 run（幂等重入，防 worker 崩溃丢报告）。
4. **报告合成**：先查目标端计数（权威），再算比率与分布，再 `decide_passed`，最后一次性 INSERT 报告与 `error_record` 批次。
5. **分流后续**：`passed=True` → 投递 Swap 命令；`passed=False` → `run.status = failed`、`failure_snapshot.quality` 写入分布摘要（供 be-19）、**不投递任何 Swap 命令**。
6. **前端**：2s 轮询 §3.1 的三个端点。

### 状态机（本模块触发的转移）

| 当前状态 | 事件 | 新状态 | 非法转移处理 |
|---|---|---|---|
| `running` | 作业正常结束，报告 `passed=True` | `running`（等 Swap） | — |
| `running` | 作业正常结束，报告 `passed=False` | `failed` | — |
| `interrupted` | 生成报告（`passed` 必为 False） | `interrupted`（不变，等回滚） | — |

| `failed` | 重复生成 | 幂等返回既有报告 | 同上 |

## 6. 关键算法与规则

### 6.1 契约编译：逐 rule_type 的表达式生成

输入单条规则（`quality_contract.rules` 的元素）：`{field, rule_type, params, error_code, on_violation}`。约定 **谓词语义恒为「True == 违规」**。

| rule_type | params | 谓词（True=违规） | 默认 error_code | 备注 |
|---|---|---|---|---|
| `not_null` | `{}` 或 `{"allow_blank": true}` | `allow_blank=false`：`<f> IS NULL`；`true`：`<f> IS NULL OR TRIM(<f>) = ''` | `E_NULL_PK` | 非主键字段若用此规则，由规则自带的 `error_code` 覆盖默认值 |
| `regex` | `{"pattern": "^1[3-9]\\d{9}$"}` | `<f> IS NOT NULL AND NOT REGEXP(<f>, '<p>')` | `E_REGEX_MISMATCH` | MySQL 与 Doris 均支持中缀 `NOT REGEXP`；字面量转义见 §6.2 |
| `range` | `{"min": 0, "max": null, "inclusive_min": true, "inclusive_max": false}` | `<f> IS NOT NULL AND (<f> < 0 [or] <f> >= max)` | `E_RANGE_VIOLATION` | 默认 **`[min, max)`**：`min` 闭、`max` 开；`min`/`max` 为 `null` 表示该侧无界 |
| `enum` | `{"values": ["PAID","REFUNDED","PENDING","CANCELLED"]}` | `<f> IS NOT NULL AND <f> NOT IN ('PAID',…)` | `E_ENUM_INVALID` | 值集合编译期排序去重，保证同名契约产出同字面量（SQL 可缓存、Diff 稳定） |
| `type_cast` | `{"target_type": "decimal(18,2)", "strict": true}` | `strict`：`<f> IS NOT NULL AND CAST(<f> AS DECIMAL(18,2)) IS NULL` | `E_TYPE_CAST` | Doris 的 CAST 失败返回 NULL；MySQL 8 需用 `REGEXP` 前置校验（见 §6.2） |

编译产物：

```python
class CompiledRule(BaseModel):                       # 一律 extra="forbid"
    rule_id: str            # 稳定标识 f"{field}.{rule_type}"（同名冲突追加序号）；落 error_record.rule_id
    field: str; rule_type: str; on_violation: str    # 取值等于数据字典已冻结的字面量
    error_code: ErrorCodeLabel; params: dict[str, Any]
    order: int              # rules 数组下标，决定命中优先级与 _error_code 取值

class CompiledRules(BaseModel):
    rules: list[CompiledRule]; reject_rules: list[CompiledRule]; warn_rules: list[CompiledRule]
    valid_columns: tuple[str, ...]     # 影子表列清单（显式，不用 SELECT *）
    error_columns: tuple[str, ...]     # 错误表列清单
    contract_sha256: str               # sha256(canonical_json(rules))，报告与 diff 锚点
    hard_block_codes: frozenset[ErrorCodeLabel]
```

### 6.2 分流机制

**为什么在数据面分流**：控制面不搬运业务数据（《概要设计总纲》§1 铁律）。若由 FastAPI 逐行判规则，10⁸ 行数据要过控制面进程，既不现实也把敏感原文带进了控制面。因此判定与写入全部下推到 SeaTunnel 的 `Sql` transform 与目标端 sink：

```hocon
# 片段由本模块产出、be-10 装配；语法细节归 be-10 / be-15 验证
transform { Sql { plugin_input = "src_x"  plugin_output = "tagged"      # 打上路由列，不改值
    query = """SELECT <valid_columns>, 142 AS etl_run_id,
        CASE WHEN <reject_predicate_1> THEN 'E_RANGE_VIOLATION' WHEN <reject_predicate_2> THEN 'E_TYPE_CAST'
             ELSE NULL END AS _error_code,
        CASE WHEN <any_reject_predicate> THEN 'reject' ELSE 'valid' END AS _quality_route,
        <first_hit_rule_id_expr> AS _rule_id FROM src_x""" } }
transform { Sql { plugin_input = "tagged" plugin_output = "valid_rows"
    query = "SELECT <valid_columns> FROM tagged WHERE _quality_route = 'valid'" } }
transform { Sql { plugin_input = "tagged" plugin_output = "rejected_rows"
    query = "SELECT 142 AS run_id, _rule_id AS rule_id, <violating_field> AS field_name,
                    _error_code AS error_code, <digest_expr> AS payload_digest,
                    <reason_expr> AS reason, NOW() AS occurred_at
             FROM tagged WHERE _quality_route = 'reject'" } }
sink { Doris { plugin_input = "valid_rows" table = "<影子表>" } }
sink { Doris { plugin_input = "rejected_rows" table = "<错误表>" } }
```

- 影子表 sink **必须显式列列**（`valid_columns`），不得 `SELECT *`：`_quality_route` / `_error_code` / `etl_run_id` 是内部列，一旦落进影子表，Swap 时与正式表的列一致性校验必然失败。
- **`warn` 与 `reject` 的区别**：`warn` 规则命中**不改变路由**，行照常写入影子表（字段值原样保留，不做替换），只累加 `rule_hits[rule_id]`；`reject` 规则命中则该行不写影子表、只写错误表。
- **优先级**：同一条数据的多个 reject 规则命中时，取 `order` 最小（即 `rules` 数组声明序）的那条作为 `_error_code` / `_rule_id`，保证同一份契约产出确定结果；`reject` 与 `warn` 同时命中时以 `reject` 为准。

### 6.3 错误记录脱敏（不可协商）

- 错误表**不存原文**：只存 `payload_digest`（64 位十六进制）与 `reason`（规则模板 + 字段名，**不含值**）。
- digest 定义（数据面 SQL 计算，控制面**原样拷贝不重算**）：

  ```sql
  -- canon(f) = NULL → '\N'；数值 → 去千分位文本；时间 → 'YYYY-MM-DD HH:MM:SS.fff'；字符串 → 去首尾空白
  SHA2(CONCAT_WS(CHAR(31), <canon(f1)>, …, <canon(fn)>), 256)  -- 前 56 位
  || LPAD(HEX(<Σ len(canon(fi))> % 4294967296), 8, '0')        -- 后 8 位：字段总长度
  ```
  即「SHA256 前 56 位 + 8 位长度后缀」，恰好 char(64)：长度后缀让「同哈希不同长度」不可能混淆，也便于诊断区分被截断的行。控制面不实现第二套算法（避免两处口径漂移），`engines/quality/rules.py::payload_digest` 仅作单测黄金向量。
- `engines/policy` 与 `services` 层都不得把该 digest 当作可逆信息使用；**digest 也不投喂 LLM**（可被低熵字典攻击）。
- 单测断言方式：造一行含唯一哨兵字符串（如 `SENTINEL-9f3a`）的违规数据 → 执行后扫描错误表全部列、`error_record` 全部列、structlog 捕获输出与证据事件 payload，断言均不出现该哨兵。

### 6.4 报告合成与 `passed` 判定

```python
processed_rows = valid_rows + rejected_rows          # 与监督侧同源：两处都必须查目标端
reject_rate    = (Decimal(rejected_rows) / Decimal(processed_rows)).quantize(Decimal("0.0001"),
                                                                              ROUND_HALF_UP)  # processed=0 → 0
```

- **分母口径唯一**：`reject_rate = rejected_rows / (valid_rows + rejected_rows)`，其中 `valid_rows` 取自影子表 `COUNT(*)`、`rejected_rows` 取自错误表 `COUNT(*) WHERE run_id = ?`。`be-16` 的监督采样、前端展示、`quality_report.reject_rate`、`runtime_supervision_contract.max_reject_rate` 判定**全部使用这一处计算结果**，禁止任何一方再用 SeaTunnel 的自报指标算拒绝率。
- **`passed` 判定**（两条同时成立才算通过）：
  1. `reject_rate <= contract.reject_rate_budget` —— **等于预算算通过**（预算即闭区间上界）。0.2000 ≤ 0.2000 → 通过；0.2001 → 不通过。比较用 `Decimal`，两侧同为 4 位小数，避免二进制浮点比较。
  2. `error_code_dist` 与 `hard_block_codes` 交集为空。`hard_block_codes = {E_SENSITIVE_PLAINTEXT, E_SCHEMA_DRIFT}`：前者对应风险矩阵的 P0「敏感字段明文出域」，后者表示源端结构与冻结版本不一致（契约本身失效），二者**零容忍**，与拒绝率无关。
- `warn` 规则命中**不计入** `reject_rate`，也不参与 `passed`（否则 warn 与 reject 无差别）。
- 边界：`processed_rows == 0` 且 `read_rows > 0` → 全部行在数据面无故丢失 → `passed=False`、`blocked_reason="zero_routed_rows"`；`read_rows == 0`（空源）→ `reject_rate=0`、`passed` 由硬阻断码决定，并在 `diagnostics.warnings` 记 `"no_rows"`。

### 6.5 `diagnostics` 结构（供 be-19 与前端）

```json
{"version": "v1", "blocked_reason": null, "interrupted": false, "warnings": ["no_rows"],
 "top_error_codes": [{"code": "E_TYPE_CAST", "count": 1203, "share": 0.7614}],
 "rules": [{"rule_id": "phone.regex", "field": "phone", "rule_type": "regex", "on_violation": "reject",
     "error_code": "E_REGEX_MISMATCH", "hits": 391, "share": 0.2475,
     "samples": [{"payload_digest": "9f2c…", "lengths": [12], "reason": "NOT REGEXP(phone, '^1[3-9]\\d{9}$')"}],
     "suggestion": "源端存在非法手机号格式；确认是否需放宽正则或补清洗规则"}],
 "generated_at": "2026-10-16T09:20:11Z"}
```

约束：每条规则最多 3 条 `samples`；`samples` 只含 `payload_digest` / `lengths` / `reason` 模板，**任何字段都不得携带原值或原值的部分片段**；`suggestion` 由规则类型映射到固定文案表（`engines/quality/report.py` 内的 `SUGGESTIONS: Mapping[str, str]`），不由 LLM 生成——保证诊断结论可复现。

### 6.6 前端指标口径

| 展示项 | 口径 |
|---|---|
| 有效行数 | `quality_report.valid_rows` = 影子表 `COUNT(*)` |
| 错误行数 | `quality_report.rejected_rows` = 错误表 `COUNT(*) WHERE run_id=?` |
| 拒绝率 | `rejected / (valid + rejected)`，UI 展示 4 位小数百分比 |
| 预算占用 | `reject_rate / reject_rate_budget`，≥ 0.8 前端置为警戒色（与监督预警阈值同源） |
| 错误码分布 | `error_code_dist`，按 count 降序，UI 只显示 Top-5 + 全长条 |
| 规则命中 | `rule_hits`，区分 reject / warn 两组（warn 不参与拒绝率，需在图例中说明） |
| 是否可发布 | `passed`（唯一依据），`blocked_reason` 非空时展示原因 |

## 7. 错误码与拒绝语义

| 触发条件 | 错误码 | HTTP | 是否写证据账本 |
|---|---|---|---|
| 规则非法（enum 值含引号、`min > max`、regex 不可编译）在**生成期**被门禁捕获 | `GATE_BLOCKED` | 403 | 是（`pipeline.gate_evaluated`） |
| 运行期契约无法编译（冻结制品异常，正常流程不可达） | `INTERNAL_ERROR` | 500 | 是（`run.failed`，payload 记 `rule_id`，不记值） |
| 质量报告 `passed=False`，禁止进入发布 | `QUALITY_REJECTED` | 409 | 是（`quality.report_generated` + `run.failed`） |
| `processed_rows == 0` 且 `read_rows > 0` | `QUALITY_REJECTED`（`blocked_reason="zero_routed_rows"`） | 409 | 是（同上） |
| `queued` 状态请求生成报告 | `CONFLICT` | 409 | 是（`run.failed`，payload `kind="quality_early"`） |
| 报告不存在时查询 | `NOT_FOUND` | 404 | 否 |
| 跨租户访问 run | `TENANT_MISMATCH` | 403 | 见 §10（缺合适事件类型） |
| 目标端错误表不可达 / 查询超时 | `DATASOURCE_UNREACHABLE` / `DATASOURCE_TIMEOUT` | 502 / 504 | 是（`run.failed`，payload `kind="quality_source_unavailable"`） |

`QUALITY_REJECTED` 不触发硬中断：质量报告在作业进入终态之后才合成，此时没有可中断的对象。运行中先超 `runtime_supervision_contract.max_reject_rate` 的情形由 be-16 触发硬中断（run → `interrupted`），本模块随后生成的报告同样 `passed=False`，只是 `diagnostics.interrupted=true`。

## 8. 安全与合规约束

- **租户过滤**：`services/quality.py` 每个入口先解析 `tenant_id / project_id`，repository 查询一律带 `tenant_id`；`finalize_report` 亦不例外（内部任务也要传上下文，不得开无租户后门）。
- **无明文原文**：违规行原文只存在于数据面（SeaTunnel 进程与目标端错误表），控制面只存 digest；日志只记 `run_id / rule_id / error_code / count`，业务代码不拼接字段值；脱敏由 logging 处理器统一兜底。
- **不可变**：`quality_report`、`error_record`、`quality_contract` 只 INSERT；报告修正的路径是「新 run → 新报告」，不存在 UPDATE 语义。
- **证据账本**：`quality.report_generated` 为必写事件，payload 只含计数、比率、错误码分布与 `contract_sha256`；`passed=False` 时额外写 `run.failed`。
- **Secret**：本模块不接触任何 `SecretReference`；目标端连接信息由 be-15 在 worker 内存中物化，本模块只拿到已建好的只读连接句柄。
- **权限**：三个 HTTP 端点均为只读，角色为项目内 maker / operator / auditor；报告与错误摘要对 auditor 完全可见（审计需要），但永远看不到原值——脱敏在**数据面**完成，不依赖前端置灰。
- **注入面**：`enum.values` 与 `regex.pattern` 来自 LLM 生成的 Plan，是唯一的字符串注入面；编译期强制「值不含 `'`、不含 `;`、长度 ≤ 128、regex 可编译且长度 ≤ 512」，违反即 `GATE_BLOCKED`（详见 §6.1 的 `ContractError`）。

## 9. 测试要点

- **单元测试（纯函数，无需 DB）**
  - `compile_contract`：五种 `rule_type` 各出谓词快照；非法参数（enum 含单引号 / `min > max` / regex 非法）抛 `ContractError`；`rules` 顺序变化 → `rule_id` 与 `contract_sha256` 稳定；`warn` 规则不出现在任何 reject 谓词中。
  - `decide_passed` 边界：`reject_rate == budget` → 通过；`budget + 0.0001` → 不通过；`hard_block_codes` 命中且拒绝率 0 → 不通过；`processed_rows=0`：`read_rows=0` → 通过 + `no_rows` 警告，`read_rows>0` → `zero_routed_rows`。
  - `payload_digest`：同一行恒等；改任一字段 → digest 变化；长度相同内容不同 → 前缀不同；输出恒 64 字符；NULL 与空串规范化差异。
  - `evaluate_rule`：`not_null`（NULL / 空串 / 全空格）、`regex` 边界（空串、超长、含换行）、`range` 闭开区间（恰等于 min → 合规；恰等于 max → 违规）、`enum` 越界与大小写敏感、`type_cast`（可转 / 不可转 / NULL 输入）。
- **集成测试（真实 PG + 真实目标端）**
  - 契约夹具表写入含脏数据（含哨兵值）的样本 → 跑 `compile_contract` 产出的 SQL → 断言：影子表行数 + 错误表行数 = 样本行数；错误码分布符合预期；哨兵值不在错误表 / `error_record` / 日志 / 证据事件中。
  - `finalize_report` 幂等（并发两次只产生一行）；SQL 与 Python 谓词一致性（同一夹具下 `evaluate_rule` 与目标端 SQL 判定相同，防两套实现漂移）；反例：跨租户 → `TENANT_MISMATCH`、`queued` 状态 → `CONFLICT`。
- **协议类反例**：`passed=False` 时**不存在**任何 Swap 命令被投递（断言 `outbox_message` 无对应 topic 行），这是「超预算硬中断 / 禁止发布」的自动化证明。

## 10. 未决与风险

| 事项 | 现状 | 验证方式 |
|---|---|---|
| `RuleType` / `OnViolation` 尚无 Python 枚举 | 数据字典只冻结了字面量，`models/enums.py` 未定义对应 StrEnum | 建议新增 `QualityRuleType`（五个值）与 `OnViolation`（两个值），取值严格等于数据字典；新增前文档与代码只写字面量 |
| Doris 2.1 是否有 `SHA2(x, 256)` | 无实机确认；若无则 digest 无法按 §6.3 计算 | M3 在 ECS 上 `SELECT sha2('a', 256)` 验证；缺失时需同步修改数据字典（增 `digest_alg` 列）或改用 Doris UDF，**不得**静默降级为 MD5 |
| Doris `CAST` 失败语义 | §6.1 假定返回 NULL；MySQL 8 的 `CAST` 会直接报错，故 MySQL 方言需前置 `REGEXP` 校验 | M3 在两种目标端各跑一组「不可转换值」夹具，比对谓词结果 |
| `E_DUPLICATE_KEY` / `E_SENSITIVE_PLAINTEXT` / `E_SCHEMA_DRIFT` 的产生点 | 三者都不是字段级规则：去重是 Plan 的 transform、明文出域是 P0 门禁、schema 漂移是目标端列校验 | 需在 be-10 / be-11 / be-18 各自文档中明确写死产生点；本模块只**消费**这三个码 |
| 事件类型缺口 | 跨租户拒绝没有匹配的 `EvidenceEventType` | 建议新增 `security.access_denied`；在此之前记 structlog warning |
| 错误表保留策略 | 未定义错误表行何时清理（错误表与错误表明细永久保留会持续膨胀） | M4 随保留策略一并定；`error_record`（控制面）按 `QUALITY_REPORT_RETENTION_DAYS=0` 永久保留 |
| `no_rows` 是否应放行 Swap | 当前允许（空源不视为失败），但空影子表 Swap 会清空正式表 | M3 演示前确认：空源场景默认**不允许** Swap（改为 `passed=False`），需产品确认 |
