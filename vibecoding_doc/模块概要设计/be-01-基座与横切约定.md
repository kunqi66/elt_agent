## 1. 职责与边界

- **做什么**
  1. 提供 `Settings`：环境变量唯一事实来源，连接串一律由分段字段计算，生产环境启动自检。
  2. 提供统一响应信封（`core/response.py`）与错误码 / 异常处理器（`core/errors.py`）。
  3. 提供 structlog 结构化日志与**统一脱敏处理器链**（`core/logging.py`）。
  4. 提供异步 DB 引擎与会话依赖（`core/db.py`）、Redis 客户端与键模板（`core/redis.py`）。
  5. 提供身份认证基础件：argon2id 口令、HS256 JWT 签发/校验（`core/security.py`）、ID/指纹工具（`core/ids.py`）、Ed25519 密钥 CLI（`core/keys.py`）。
  6. 装配 FastAPI 应用（中间件、异常处理、路由挂载、生命周期）、健康/就绪探针、Alembic 迁移约定、幂等键机制。
- **不做什么**
  - **不承载任何业务规则**：业务在 `services/` 与 `engines/`；本模块不 import 任何领域模型（除了 `models/enums.Env` 只用于配置取值复用、`models/base` 只提供混入）。
  - **不做授权判定**：`core/security.py` 只回答「你是谁」（JWT 验签 + 过期 + 类型），「你能做什么」一律由 be-02 的 `require_role` 查 `role_assignment`。
  - **不定义业务实体**：只提供 `Base` / 混入 / 不可变守卫，具体表见各模块文档。
  - **不提供副作用出口**：写外部系统、执行作业一律经 `harness.ToolBroker`（be-05）。
  - 不做限流的业务语义（只提供 `RATE_LIMITED` 错误码，边缘限流在 Nginx）。
- **所在分层**：`core/` 是最底层，只依赖标准库 + 第三方库 + Pydantic，不被 `services`/`engines`/`clients`/`harness` 反向依赖；`api/router.py` 与 `main.py` 只做装配（依赖注入、路由挂载、生命周期），无业务流程。

## 4. 数据模型

| 表 | 本模块动作 | 关键列 / 约束（详见《核心数据字典》§8） |
|---|---|---|
| `idempotency_key` | 读写 | `UK(tenant_id, scope, key)`、`request_fingerprint`、`response_snapshot`、`expires_at` |
| `login_attempt` | 只读（生产者是 be-02） | 审计用；锁定事实以 Redis 为准 |

`models/base.py` 的约定不属于表定义，但属于**所有表**的横切契约，在此固化：

- `NAMING_CONVENTION`：`ix/uq/ck/fk/pk` 模板，Alembic autogenerate 能产出稳定 diff 的前提。
- `AutoPK = BigInteger().with_variant(Integer, "sqlite")`：SQLite 只把 `INTEGER PRIMARY KEY` 当 rowid 别名，本机单测用内存 SQLite 依赖它。
- 混入：`PKMixin` / `TimestampMixin`（含 `updated_at`）/ `CreatedAtMixin`（不可变表专用，无 `updated_at`）/ `TenantMixin` / `ProjectScopedMixin`。
- 不可变守卫：`Base.__immutable__`、`Base.__mutable_columns__`、`ImmutableViolationError`、`@event.listens_for(Session, "before_flush")`。

## 5. 核心流程

### 5.1 应用装配与生命周期

1. `main.create_app()` 构造 `FastAPI`；生产环境关闭 `docs/redoc/openapi`。
2. `RequestContextMiddleware` 注册（**先注册，使异常处理器也能拿到上下文**）。
3. 非生产且 `CORS_ORIGINS` 非空时挂 CORS；生产由 Nginx 同源反代，不需要 CORS。
4. `register_exception_handlers(app)`。
5. 挂载 `health_router`（根路径）与 `api_router`（前缀 `settings.API_V1_PREFIX`）。
6. `lifespan` 启动：`configure_logging()` → `log.info("app_starting", **settings.safe_dump())`；非生产再记一条 `non_production_mode` 警告。
7. `lifespan` 关闭：`close_redis()` → `dispose_engine()`。

### 5.2 请求生命周期（上下文贯穿）

```
Nginx ──X-Request-ID?──▶ RequestContextMiddleware
                           ├─ request_id = X-Request-ID or new_request_id()
                           ├─ contextvars.bind(request_id, method, path, client_ip)
                           ├─ 调用下游（api 路由 → Depends 解析身份/租户/项目）
                           ├─ 响应头回写 X-Request-ID
                           └─ contextvars.clear()      # 防上下文泄漏到下一个请求
```

- 请求级绑定：`request_id / method / path / client_ip`（本模块）。
- 依赖级补绑：`tenant_id / subject_id / project_id`（be-02 的 `get_current_subject` 解析后 `bind_contextvars`）。
- 制品级补绑：`pipeline_version_id / execution_run_id`（M2/M3 的 service 显式绑定）。
- 跨进程承接：Celery 任务从 `outbox_message.payload` 取出 `request_id` 等并重新 bind，保证 api → worker 同一 `request_id`。

### 5.3 事务边界（service 层显式控制）

| 场景 | 边界 | 说明 |
|---|---|---|
| 只读查询 | 无显式事务 | `get_session()` 默认 autobegin，不 commit |
| 幂等写接口 | **单事务**：业务写 + `idempotency_key` 落库 | 同 key 并发由 `UK(tenant_id, scope, key)` 兜底，不做「先查后写」 |
| 登录 | **单事务**：写 `login_attempt` + 更新 `app_user.last_login_at` | Redis 失败计数在事务外（易失存储，不参与回滚） |
| 副作用协议（Commit/Swap） | **单事务**：业务事实 + `outbox_message` | 见 be-14；禁止拆成两次提交 |
| 证据账本写入 | **独立串行化事务** | 见 be-06；不得与业务事务混用 |

### 5.4 不可变守卫（`before_flush`）

| 对象状态 | 判定 | 结果 |
|---|---|---|
| `session.deleted` 含 `__immutable__=True` 实例 | 直接命中 | 抛 `ImmutableViolationError`（"禁止删除"） |
| `session.dirty` 含不可变实例 | `changed - __mutable_columns__ - {"updated_at"}` 非空 | 抛 `ImmutableViolationError`，逐列报出非法列名 |
| 不可变实例只改 `__mutable_columns__` 内列 | 白名单放行 | 允许 flush |
| 非不可变实例 | 跳过 | 允许 |

**例外白名单**（唯一事实来源，不得在别处另立）：`Preparation.__mutable_columns__ = {"status"}`、`Capability.__mutable_columns__ = {"consumed_at", "consumed_by_run_id", "reject_reason"}`。其余不可变模型白名单为空集。

### 5.5 Alembic 迁移约定

1. 配置：`alembic.ini` 的 `sqlalchemy.url` 不写死，`alembic/env.py` 从 `settings.postgres_dsn_sync` 取（同步 psycopg DSN）。
2. `env.py` 必须 `import models`（导入即注册全部模型），`target_metadata = Base.metadata`；新增模型必须在 `models/__init__.py` 登记，否则迁移静默漏表。
3. 生成：`uv run alembic revision --autogenerate -m "msg"`；**人工审阅**生成的脚本（autogenerate 识别不了跨行约束、部分索引、触发器）。
4. 已 apply 的 revision 文件**不得**编辑；只追加新 revision。
5. 不可变语义由 ORM 守卫承担，DDL 层不额外建触发器（`role_assignment` 的职责互斥触发器是唯一例外，见 be-02）。
6. `deploy/postgres/init/01-init.sql` 只做扩展与审计只读角色，不建业务表。

## 6. 关键算法与规则

### 6.1 Settings 分层与生产自检

| 层级 | 规则 |
|---|---|
| 取值来源 | `backend/.env` → 仓库根 `.env` → 进程环境变量；`case_sensitive=False`、`extra=ignore` |
| 派生而非手写 | `postgres_dsn` / `postgres_dsn_sync` / `redis_url(db)` / `celery_broker_url` / `celery_result_backend` / `minio_endpoint` / `seatunnel_api_base` 全部由分段字段计算；`.env` 禁止出现 `*_URL` |
| 敏感承载 | 一切密钥/口令用 `SecretStr`；`safe_dump()` 输出 `***configured***` / `***empty***` |
| 环境自检 | `APP_ENV=prod` 时逐项校验（见下表），任一违规直接抛 `ValueError`，应用拒绝启动 |

生产自检项：`SECRET_KEY` / `POSTGRES_PASSWORD` / `REDIS_PASSWORD` / `MINIO_ROOT_PASSWORD` / `VAULT_TOKEN` / `LLM_API_KEY` 非空且不以 `change-me` / `changeme` / `your-` / `sk-your` 开头；`APP_DEBUG=false`；`CORS_ORIGINS` 不含 `*`；`VAULT_ADDR` 为 HTTPS 或含 `127.0.0.1`。`APP_ENV` 取值复用领域枚举 `models.enums.Env`，不另立词汇。

### 6.2 异常处理器映射表

| 异常类 | HTTP | 响应 `code` | 服务端日志级别 | `details` |
|---|---|---|---|---|
| `AppError` 子类 | `exc.http_status` | `exc.code.value` | 401/403/409/423 → warning，否则 info | `exc.details`（如有） |
| `RequestValidationError` | 422 | `VALIDATION_ERROR` | info | `{fields: [{loc, reason}]}`，**不回显原始输入值** |
| `IntegrityError` | 409 | `CONFLICT` | warning | 无（只记 `error_type`） |
| `SQLAlchemyError` | 500 | `INTERNAL_ERROR` | error | 无 |
| `Exception`（未捕获） | 500 | `INTERNAL_ERROR` | exception（含堆栈，仅服务端） | 无 |

响应体统一为 `{code, message, request_id, details?}`，`request_id` 由处理器现取 `new_request_id()`。数据库异常、第三方异常**不得**原样透出。

### 6.3 日志脱敏处理器链

`configure_logging()` 的处理器顺序固定：`merge_contextvars` → `add_logger_name` → `add_log_level` → `TimeStamper(iso, utc)` → `StackInfoRenderer` → `UnicodeDecoder` → **`redact_processor`** → 渲染器（prod=`JSONRenderer`，dev=`ConsoleRenderer`）。

`redact_processor` 两级命中：

1. **键名命中**（正则 `pass(word|wd)?|secret|token|api[_-]?key|authorization|auth|credential|private[_-]?key|signature|salt|session|conn(ection)?[_-]?str`，忽略大小写）→ 整值替换为 `***`。
2. **值形态命中** → 按规则替换：`sk-...` → `[REDACTED_API_KEY]`；`Bearer ...` → `Bearer [REDACTED]`；`postgresql|mysql|redis|mongodb|amqp://...` → `[REDACTED_DSN]`；PEM 私钥块 → `[REDACTED_PRIVATE_KEY]`；三段式 JWT → `[REDACTED_JWT]`；18 位身份证 → `[REDACTED_ID_CARD]`；`1[3-9]\d{9}` → `[REDACTED_PHONE]`；邮箱 → `[REDACTED_EMAIL]`。

递归深度上限 6（超出记 `[TRUNCATED]`）；`bytes` 记 `<bytes:len>`；非键名的短字符串用 `前2 + *** + 后2`（长度 ≤6 全掩码）。业务代码**不得**自行拼接敏感值，也不得因为「已自行脱敏」而绕过本处理器。

### 6.4 JWT 契约

| 项 | access | refresh |
|---|---|---|
| 算法 | HS256（密钥 `settings.SECRET_KEY`） | HS256 |
| 有效期 | `ACCESS_TOKEN_EXPIRE_MINUTES`（默认 30 min） | `REFRESH_TOKEN_EXPIRE_DAYS`（默认 7 d） |
| 必需声明 | `exp, sub, jti, type="access", iss="elt-agent", iat, tenant_id, projects[]` | `exp, sub, jti, type="refresh", iss, iat` |
| 撤销 | `KEY_TOKEN_DENY = auth:denied_jti:{jti}`，TTL = 令牌剩余有效期 | 同左 |
| 校验 | `decode_token(token, expected_type=...)`：验签 + issuer + `require` 声明 + `type` 匹配 | 同左 |

**授权不使用 JWT 内的角色声明**：`tenant_id` / `projects[]` 仅作为「候选上下文」的提示，每次请求由 be-02 重新查库确认（角色可能已被回收）。与 Capability 执行令牌（Ed25519，be-05）**算法与用途都不同，禁止混用**。

### 6.5 幂等键机制（`core/idempotency.py`，待建）

1. 写接口从 `Idempotency-Key` 请求头取 key；缺失则按接口声明决定是否强制（本模块不强制，由各业务接口声明）。
2. 计算 `request_fingerprint = sha256_hex(canonical_json(body + path_params))`。
3. `reserve()`：`INSERT ... ON CONFLICT DO NOTHING RETURNING`，命中既有行时比较 `request_fingerprint`：
   - 相同 → `REPLAY`，直接返回 `response_snapshot`；
   - 不同 → `CONFLICT`，抛 `IDEMPOTENCY_CONFLICT`。
4. `complete()` 在**同一事务**内回填 `response_snapshot` / `resource_type` / `resource_id` / `completed=true`。
5. 过期清理：`beat` 按 `ix_idempotency_key_expires_at` 删除 `expires_at < now()`。

`canonical_json` 是 `request_fingerprint` 的唯一输入序列化方式（键排序、无空白、非 ASCII 原样），避免同一请求因字段顺序不同算出两个指纹。

## 7. 错误码与拒绝语义

| 触发条件 | 错误码（`ErrorCode`） | HTTP | 写证据账本 |
|---|---|---|---|
| 参数/请求体不合 schema | `VALIDATION_ERROR` | 422 | 否 |
| 资源不存在 | `NOT_FOUND` | 404 | 否 |
| 唯一/外键约束命中 | `CONFLICT` | 409 | 否 |
| 同 `Idempotency-Key` 不同 `request_fingerprint` | `IDEMPOTENCY_CONFLICT` | 409 | 否 |
| 客户端超频 | `RATE_LIMITED` | 429 | 否 |
| 未带/令牌无效 | `UNAUTHENTICATED` | 401 | 否 |
| 令牌过期 | `TOKEN_EXPIRED` | 401 | 否 |
| 进程内未捕获异常 | `INTERNAL_ERROR` | 500 | 否 |
| 越权、租户不匹配、角色不足 | `FORBIDDEN` / `TENANT_MISMATCH` / `ROLE_REQUIRED` | 403 | 由 be-02 判定并写账本 |
| 修改不可变制品的非白名单列 | `VERSION_IMMUTABLE` | 409 | 是（由调用方 be-12/be-13 写） |

本模块**自身不写证据账本**：它只提供 `errors` 与异常处理器；协议类拒绝的账本事件由具体业务模块（be-02、be-05、be-13）在捕获异常后 `EvidenceLedger.append()`。

## 8. 安全与合规约束

- **无明文 Secret**：`Settings` 全字段用 `SecretStr`；`safe_dump()` 只输出「是否已配置」；`postgres_dsn` 在 `repr`/日志中被 `***` 覆盖。
- **脱敏默认开启**：所有日志经 `redact_processor`；异常处理器只回 `code/message/request_id/details`，`details` 不含原始输入值。
- **租户过滤**：本模块提供 `TenantMixin/ProjectScopedMixin` 与 `tenant_id` 上下文注入点，**具体的强制过滤在 repository/service 层**（be-02 起）。
- **不可变**：`before_flush` 守卫是所有不可变制的最后一道兜底；白名单只允许流程状态列变化。
- **权限校验**：本模块只做认证（JWT 验签），不判定角色；`ROLE_REQUIRED` 由 be-02 抛出。
- **审计**：本模块不写 `evidence_event`；`/healthz`、`/readyz` 不记录访问日志（Nginx 侧 `access_log off`）。
- **攻击面**：生产关闭 OpenAPI 文档；生产禁止 CORS 通配；Nginx 是唯一对外入口。

- **单元测试**（纯逻辑，本机内存 SQLite / 无依赖）
  - `Settings`：`APP_ENV=prod` + 占位密码 → 启动抛 `ValueError`；`APP_DEBUG=true` 于 prod → 抛错；`CORS_ORIGINS=["*"]` 于 prod → 抛错；`safe_dump()` 不含任何明文口令。
  - `redact_processor`：键名 `password`/`token` → `***`；值含 `sk-xxx`、`Bearer eyJ...`、`postgresql://u:p@h/db`、18 位身份证、手机号、邮箱 → 分别被替换；深度 >6 → `[TRUNCATED]`。
  - `canonical_json`：字典键顺序不同 → 同一字符串；`fingerprint` 对同内容稳定、对不同内容变化。
  - 不可变守卫：见 `tests/test_model_guards.py`（改白名单外列报列名、白名单列放行、夹带篡改被拦、删除被拦）。
  - `decode_token`：过期 → `TokenExpiredError`；`type` 不符 → `UnauthenticatedError`；篡改签名 → `UnauthenticatedError`。
  - 异常处理器：`IntegrityError` → 409 `CONFLICT`；`RequestValidationError` → 422 且 `details.fields` 不含原值。
- **集成测试**（真实 PG/Redis）
  - `/healthz` 恒 200；`/readyz` 在 PG 或 Redis 不可用时 503 且 `checks` 标出失败项。
  - 幂等：并发两条同 key 同 body 请求 → 一条 `NEW` 一条 `REPLAY`，业务只生效一次；同 key 不同 body → `IDEMPOTENCY_CONFLICT`。
  - `X-Request-ID` 透传：上游给则沿用，不给则生成并回写响应头；两条并发请求的 `request_id` 不串。
- **必须覆盖的反例**：越权（缺 header → 401，而非 500）；同 key 冲突；生产配置占位值启动失败。
- **测试基建**：`tests/conftest.py` 用 `StaticPool` 内存 SQLite 建全表；纯 ORM 行为在本机跑，依赖 PG 语义（JSONB 查询、部分唯一索引、advisory lock、触发器）的标 `@pytest.mark.integration` 在 ECS 上跑。

## 10. 未决与风险

| 事项 | 现状 | 建议 / 验证方式 |
|---|---|---|
| `alembic/` 与 `alembic.ini` 尚未创建 | 迁移约定已冻结，目录未建 | M1 内补 `uv run alembic init -t async alembic`，`env.py` 接 `settings.postgres_dsn_sync` 并 `import models` |
| `ImmutableViolationError` 无异常处理器 | 会落到通用 `Exception` → 500 | 建议注册处理器映射到 `VERSION_IMMUTABLE`(409)；需确认该码语义为「拒绝修改」 |
| `IDEMPOTENCY_CONFLICT` 无对应异常类 | 枚举值已存在，无 `AppError` 子类 | 建议新增 `IdempotencyConflictError(AppError)`，`code=IDEMPOTENCY_CONFLICT`、`http_status=409` |
| `core/deps.py` 未建 | 依赖注入聚合缺位 | M1 be-02 落 `get_tenant_context`；身份依赖归 be-02 |
| 登录锁定阈值未冻结 | Redis 模板注释仅给 TTL 15min | 建议 `LOGIN_FAIL_MAX_ATTEMPTS=5`、窗口 900s，写入 be-02 并确认 |
| 幂等键 `expires_at` 与 `scope` 命名无统一约定 | 各接口自定会漂移 | 建议 `scope` 用 `"{module}.{action}"`（如 `datasource.create`），TTL 默认 24h |
| 限流是否在应用侧做（除 Nginx） | 未定 | 倾向只在 Nginx 做；若应用侧做需引入 Redis 令牌桶并定义 `RATE_LIMITED` 触发点 |
| `PreparedStatement`/连接池参数 | `pool_size=10`、`max_overflow=20` 为默认 | M4 按 ECS 规格压测后调优 |
