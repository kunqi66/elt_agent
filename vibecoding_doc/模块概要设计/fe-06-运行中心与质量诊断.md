## 1. 职责与边界

- **做什么**
  1. 展示**运行列表**：状态徽章、耗时、行数、字节、拒绝率，支持按 `RunStatus` 筛选。
  2. 承载**运行详情三区布局**（PRD §11.3）：顶部状态与版本摘要、中部指标与预算进度、下部日志 / 质量分流 / 错误码 / 根因诊断 / 回滚操作。
  3. 实现 **2 s 增量轮询**（`?since=`、`visibilitychange` 暂停、终态停止、失败退避）与 ECharts 增量 append。
  4. 展示**质量分流面板**与**根因诊断面板**（含 LLM 不可用时的确定性降级）。
  5. 承载**操作**：暂停 / 取消 / 回滚（operator），含前置状态校验与二次确认；auditor 全程只读。
- **不做什么**
  - **不直连 SeaTunnel / 目标库**：本模块是只读仪表盘 + 命令入口；真实副作用由 `harness.ToolBroker` 的 `seatunnel.stop` / `target.rollback_cleanup` 执行；**不搬运业务数据**（控制面只展示指标与摘要）。
  - **不显示错误行原文**：错误明细只呈现 `payload_digest` 与 `reason`；这是安全约束，前端**不得提供任何绕过入口**（不做「复制原文」「下载明细」）。
  - **不做状态机推演**：合法转移由后端保证，前端只渲染并禁用非法操作的按钮；不引 WebSocket（《需求对齐记录》§二.7 已冻结为 2 s 轮询）。
- **所在分层**：前端展示层。只经 `src/api/run.ts` / `src/api/monitor.ts` 调 `/api/v1/runs` 与 `/api/v1/monitor`。

## 5. 核心流程

**运行详情加载与轮询**

```
1. 进入 /runs/:runId → fetchDetail()（拿到 status / budget / can_* 四个布尔）
2. 非终态 → startPolling()，单 tick 顺序执行：
   fetchDetail() → fetchMetricsIncremental() → fetchLogsIncremental()
3. status 进入终态 → stopPolling() → 一次性 fetchQuality() + fetchDiagnosis()
4. 路由离开/组件卸载 → stopPolling() + reset()
```

**操作前置状态校验**（按钮可见性只取 `can_*`；`false` 时置灰 + tooltip 说明当前状态不允许）

| 操作 | 允许的当前状态 | 结果状态 | 确认弹窗必展示 |
|---|---|---|---|
| 暂停 | `running` | `paused` | 当前进度（已读行数/已写字节）、暂停不回收影子表 |
| 恢复 | `paused` | `running` | 契约剩余预算（上限 − 已消耗） |
| 取消 | `queued` / `running` / `paused` | `cancelled` | 影子表与错误表残留处置说明、是否可回滚 |
| 回滚 | `failed` / `interrupted` / `cancelled` / `succeeded` | `rolling_back` → `rolled_back` | **回滚方案全文**（`rollback_plan.steps`）、影响范围（`shadow_table` / `formal_table`）、是否清理未发布影子数据 |

`readonly`（auditor）时整条操作栏不渲染。非法状态由服务端以 `CONFLICT` 拒绝，前端收到后强制刷新详情。

**RunStatus 状态机（9 态）**：`queued` →`running`（Worker 提交作业）；`running` →`succeeded`（质量通过且 Swap 成功）/`failed`/`paused`（operator）/`interrupted`（监督超限，非人工）；`paused` →`running`（operator）；`queued`/`running`/`paused` →`cancelled`（operator）；`failed`/`interrupted`/`cancelled`/`succeeded` →`rolling_back`（operator）→`rolled_back`（worker 清理成功）。

**终态**（停止轮询）：`succeeded` `failed` `cancelled` `interrupted` `rolled_back`；`rolling_back` 仍在轮询。

## 6. 关键算法与规则

**运行列表列**：Pipeline（`pipeline_name`）/ 版本（`v{version_no}`）/ `RunStatusTag` / 目标表（`formal_table`，超长省略 + tooltip）/ 触发人（`triggered_by_name`）/ 开始时间（本地时区 `YYYY-MM-DD HH:mm:ss`）/ 耗时（`duration_sec` → `1h 23m 45s`）/ 读取行数（千分位）/ 写入字节（`GiB`/`MiB` 人类可读 + 悬停原始字节）/ 拒绝率（`numeric(6,4)` → 百分比两位小数，超 `max_reject_rate` 时标红）。筛选：`status`（多选）/ `pipeline_id` / 时间范围。

**`RunStatusTag` 徽章规范**（色值集中于此组件，其他组件不得自行写色或文案）

| 状态 | tag type | 图标 | 文案 |
|---|---|---|---|
| `queued` | `info` | `Clock` | 排队中 |
| `running` | `primary` | `Loading`（旋转） | 运行中 |
| `succeeded` | `success` | `CircleCheck` | 成功 |
| `failed` | `danger` | `CircleClose` | 失败 |
| `paused` | `warning` | `VideoPause` | 已暂停 |
| `cancelled` | `info`（深灰描边） | `Remove` | 已取消 |
| `interrupted` | `danger`（实心 + 左侧警示条） | `WarningFilled` | 监督硬中断 |
| `rolling_back` | `warning`（图标脉动） | `RefreshLeft` | 回滚中 |
| `rolled_back` | `info`（青灰） | `Back` | 已回滚 |

动画只作用于图标，不作用于整行，避免长列表视觉噪声。

**三区布局**（PRD §11.3）：顶部 `RunHeaderPanel`（RunStatus + `seatunnel_job_id` + 版本摘要 `v{version_no}` / `artifact_sha256` 前 8 位 + `started_at`/`finished_at`）；中部 `MetricsPanel`（吞吐/行数/字节/耗时/拒绝率卡片 + 4 条 ECharts 时序线）与 `BudgetProgress`；下部 Tab 切换（运行日志 / 质量分流 / 错误码分布 / 根因诊断 / 回滚操作）。

**预算进度条**：对 5 个受监督量各渲染一条，统一规则 `ratio = current / limit`：`ratio < warn_threshold_pct/100` 正常色（蓝）；`[warn, 1.0)` 预警色（橙）+「接近预算」；`≥ 1.0` 越限色（红）+「已超预算」。预警线以竖直刻度**显式绘制**在 80% 处，不靠颜色单独表达。比率型指标按百分比展示（`0.0500` → `5.00%`）。着色由前端按当前值计算，但「是否已硬中断」只认 `run.status === 'interrupted'`。

**轮询实现**

```ts
const POLL_INTERVAL_MS = 2000
const BACKOFF_STEPS_MS = [2000, 4000, 8000, 16000, 30000]   // 失败退避，上限 30 s

async function tick(run_id: number): Promise<void> {
  if (document.visibilityState === 'hidden') return          // 页面不可见：跳过本轮，不清计时器
  try {
    await store.fetchDetail(run_id)
    await store.fetchMetricsIncremental(run_id)
    await store.fetchLogsIncremental(run_id)
    failures = 0
  } catch (e) {
    if (e instanceof BizError && e.status === 401) return    // 会话问题交给 client.ts
    failures = Math.min(failures + 1, BACKOFF_STEPS_MS.length - 1)
  }
  schedule(BACKOFF_STEPS_MS[failures])
}
```

- **增量语义**：`since` 取上一批响应的最后一个 `ts`（服务端按 `ts > since` 过滤，故严格大于）；首次不传 `since`，后端返回最近 N 点。日志用 `cursor` 游标。
- **重新可见**：立即执行一次 tick 并复位退避计数（用户刚回到页面，不应等 30 s）。
- **不并发多 tick**：`inFlight` 布尔位保证上一 tick 未完成时跳过下一次触发，防慢网络下请求堆积。
- **终态停止**：`stopPolling()` 后不再发请求。

**ECharts 增量 append 与内存上限**：图表实例 `onMounted` 创建一次，`watch(metrics)` 时 `chart.setOption({series:[{data: appended}]}, {notMerge:false, lazyUpdate:true})` **仅追加新点**，绝不整数组重建 option；缓冲上限 `MAX_POINTS = 1800`（2 s × 1800 = 1 h），超出时从头部 `splice` 并同步 series 长度，同时在图左以灰底标注「更早数据已省略」；缓冲 > 900 点时展示层按 2 点合 1 绘制（取后者，累计量单调递增不失真），原始缓冲不破坏；4 条线各绑独立 y 轴，拒绝率固定 0–100%；`onBeforeUnmount` 调 `dispose()` 防实例泄漏。

**错误码中文文案映射**（`errorCodeLabel.ts` 常量，仅供展示）：`E_TYPE_CAST` 类型转换失败 · `E_NULL_PK` 主键为空 · `E_REGEX_MISMATCH` 正则校验不通过 · `E_RANGE_VIOLATION` 取值范围越界 · `E_ENUM_INVALID` 枚举取值非法 · `E_DUPLICATE_KEY` 主键重复 · `E_SENSITIVE_PLAINTEXT` 敏感字段明文 · `E_SCHEMA_DRIFT` 源端结构漂移。未知取值显示原始枚举字符串并加「未知错误码」提示，**不隐藏、不猜测**。

**错误码分布图**：`error_code_dist` 渲染为**横向条形图**（不用饼图：8 类目且量级差异大，条形更易读出主次），按计数降序；`E_SENSITIVE_PLAINTEXT` 恒定使用警示色（P0 相关信号）。

**根因诊断降级**：`confidence='deterministic'`（来自 `quality_report.diagnostics`，总是可用）与 `'llm_assisted'`（be-19 追加，以「模型辅助解读」标签区分，**不覆盖任何数值**）分别呈现；`degraded=true` 时面板顶部黄色提示「模型解读不可用，以下仅展示确定性结论」，仍完整渲染 `evidence` 与 `suggestions`，不显示空白面板也不隐藏区域。

## 7. 错误码与拒绝语义

| 触发条件 | 错误码（`ErrorCode`） | HTTP | 前端表现 | 写账本 |
|---|---|---|---|---|
| 监督超硬阈值 | `SUPERVISION_INTERRUPTED` | 409 | 顶部红色警示条 + 徽章转「监督硬中断」；自动展开失败快照与诊断；操作栏只留「回滚」 | 是（`run.interrupted`） |
| 质量拒绝率超限、禁止 Swap | `QUALITY_REJECTED` | 409 | 质量面板标注「未通过，禁止发布」；`passed=false`；**不提供「强制发布」** | 是 |
| 原子 Swap 失败 | `SWAP_FAILED` | 409 | 提示「正式表未被修改，处于可诊断失败状态」；并排展示 `shadow_table` / `formal_table`；引导回滚 | 是（`swap.failed`） |
| 回滚执行失败 | `ROLLBACK_FAILED` | 409 | 红色阻断提示「自动回滚失败，需人工介入」，展示失败步骤序号、工具名与错误摘要；**禁用重复点击回滚**（避免状态叠加），改为提示联系运维 | 是 |
| 同一版本已有活跃运行 | `RUN_CONFLICT` | 409 | 运行列表高亮该活跃 run；Commit 入口侧提示（fe-05） | 是 |
| 目标状态不允许该操作 | `CONFLICT` | 409 | 提示「当前状态不允许该操作」并强制刷新详情，按钮按新 `can_*` 重渲染 | 是 |
| 非 operator 调用操作 | `FORBIDDEN` / `ROLE_REQUIRED` | 403 | 操作栏不渲染（auditor 同） | 是 |
| 非本租户/项目资源 | `TENANT_MISMATCH` | 403 | 跳回运行列表 | 是 |
| 运行不存在 | `NOT_FOUND` | 404 | 详情空态 | 否 |
| 诊断服务不可用 | `LLM_UNAVAILABLE` | 200（降级）或 503 | 诊断面板降级展示；不影响指标与质量面板 | 视后端 |
| 同 `Idempotency-Key` 不同请求体 | `IDEMPOTENCY_CONFLICT` | 409 | 提示冲突并停止重试 | 否 |

分支基于 `BizError.code`（`client.ts` 抛出的业务错误），**不用 `message` 判断**。

## 8. 安全与合规约束

- **错误原文不可达**：`error_record` 只存 `payload_digest`（SHA256 + 字段长度），后端不下发原文；前端不提供任何查看原文的入口，「查看原始错误行」类功能属设计外，禁止以调试模式、隐藏按钮或导出绕过。
- **日志脱敏**：`RunLogViewer` 渲染的是后端 structlog 已过脱敏处理器的文本。前端**不得**自行拼接日志内容，也不得从 `failure_snapshot` 中提取疑似敏感的原始值展示；日志面板对 `subject_type/subject_id` 只做跳转，不做展开原文。
- **不缓存执行数据**：运行详情、指标、日志只存内存，`reset()` 清空，不落 `localStorage`（`failure_snapshot` 与错误原因可能含业务语义）。
- **操作即审计**：暂停/取消/回滚的确认弹窗必须写明「此操作将写入证据账本并记录操作人」；回滚弹窗额外强制展示回滚方案全文——操作员必须看到自己将要执行的东西。
- **幂等键**：四个操作接口各带自己的 `Idempotency-Key`，生成与复用规则同 fe-05 §6（弹窗打开生成一次，重试复用，关闭置空）。
- **只读角色**：auditor 的界面表现是——操作栏整体不渲染、`payload_digest` 与诊断可见、证据账本入口可见（跳 fe-07）；前端隐藏之外服务端仍须对四个 POST 做角色校验。
- **轮询不打爆后端**：2 s × 单页面 × 3 个请求已是上限；禁止列表页逐行轮询详情，禁止多标签页叠加（`visibilitychange` 已覆盖后台标签页）。

## 9. 测试要点

- **单元测试（Vitest）**：`RunStatusTag` 9 态各自的 tag type / 图标 / 文案与未知取值容错；`BudgetProgress` 在 `ratio` 取 0.5 / 0.8 / 0.7999 / 1.0 时分别为正常 / 预警 / 正常 / 越限，预警线绘制在 `warn_threshold_pct`；`errorCodeLabel` 8 个枚举全覆盖且未知键回退为原字符串；metrics 缓冲连续 append 超 1800 点后长度恒为 1800 且保留最新点并置「已省略」标志；轮询在 `hidden` 时不发请求、`failures` 递增时退避为 2/4/8/16/30 s 且不再增长；`DiagnosisPanel` 在 `degraded=true` 时显示降级提示但仍渲染 `evidence` 与 `suggestions`。
- **集成测试（真实 PG + 后端 + 假 SeaTunnel 执行器，ECS 上跑）**：**超预算硬中断**（注入超 `max_reject_rate` → `interrupted`、`failure_snapshot` 非空、`run.interrupted` 事件存在）；**质量分流**（错误表 N 行 → `rejected_rows = N`、`error_code_dist` 与 `error_record` 分布一致、`passed=false` 时无发布入口）；**回滚成功**（`interrupted` → `rolling_back` → `rolled_back`，`shadow_table` 已清理，`rollback.succeeded` 存在）；**回滚失败**（注入 `target.rollback_cleanup` 失败 → `ROLLBACK_FAILED` 人工介入提示，且不产生 `rolled_back`）；**Swap 失败**（正式表内容不变，状态 `failed`，展示 `SWAP_FAILED`）；**越权**（auditor 调 pause → 403 且界面无操作栏）；**幂等**（同 key 连点回滚 → 只执行一次清理）；**增量语义**（连续两次 `?since=` → 第二批不含第一批已返回的 `ts`）。
- **必须覆盖的反例**：越权操作、非法状态操作、超预算、Swap 失败、回滚失败、**错误原文不可达**（断言响应与 DOM 中都不含原文）。
- **测试基建**：ECharts 在 jsdom 下不可用，图表组件用 `vi.mock('echarts')` 断言 `setOption` 的调用参数（尤其 `notMerge` 与追加的 data 长度）。
