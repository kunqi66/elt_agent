## 1. 职责与边界

- **做什么**
  1. 数据源列表：分页、按类型/环境/敏感级别/状态/名称筛选、按项目归属展示。
  2. 登记与编辑：表单按 `DataSourceType` **动态渲染必填项**，凭据只以 Secret 引用方式提交。
  3. 连通性测试：受管触发 → 异步结果四态（成功/失败/超时/权限不足）展示与重试。
  4. 元数据探查：提交采样与脱敏配置、展示探查进度与 `ProbeStatus`、Profile 版本列表。
  5. 探查结果浏览：Schema 树 + 字段详情（类型/可空/主键/近似统计）+ **脱敏样本**表格。
  6. 数据源启停（`status: active/disabled`）与删除。

- **不做什么**
  - **不接触凭据明文**：前端不接收、不缓存、不回显密码/Token；凭据只在「新建/重新设置」时单向提交一次。
  - **不做连通性判定**：网络可达性、认证结果、最小权限判定全在后端（`datasource.connectivity_test` 工具的 P3 动作）；前端只渲染结果枚举。
  - **不做脱敏**：`masked_samples` 由后端入库前脱敏；前端不做二次掩码计算，也不提供「查看原文」入口（原文不落库，无从解敏）。
  - **不探查/不校验 Schema 语义**：字段类型推断、近似统计、敏感字段识别都在 `backend/engines/metadata`。
  - 不做 PIPELINE 选择与生成（fe-04）；不在本页发起任何写目标库的动作。

- **所在分层**：`views/datasource/` → `api/datasource.ts` → `api/client.ts`；共享组件取自 fe-01 的 `components/common/`。本页不 import 其他 feature 的 store，不直接使用 axios。

## 4. 数据模型

前端只读/写以下后端结构（字段名逐字对齐）：

| 后端表 | 本页动作 | 用到的列 |
|---|---|---|
| `data_source` | 读 + 写 | `name` `type` `env` `endpoint` `secret_ref_id` `sensitive_level` `tags` `owner_id` `status` `last_tested_at` `last_test_ok` |
| `secret_reference` | 只读（服务端写） | `provider` `path` `version` `key_names` `last_rotated_at` |
| `metadata_profile` | 只读（服务端写） | `version` `status` `schema_snapshot` `sampling` `masked_samples` `masking_policy` `tables_count` `sha256` `expires_at` `error_message` |

```ts
export interface DataSource {
  id: number; project_id: number; name: string
  type: DataSourceType; env: Env; sensitive_level: SensitiveLevel
  endpoint: Record<string, string | number>       // 不含任何凭据键
  secret_ref: SecretReferenceView | null
  tags: string[]; owner_id: number | null; owner_display_name: string | null
  status: 'active' | 'disabled'
  last_tested_at: string | null; last_test_ok: boolean | null
  created_at: string; updated_at: string
}

export interface SecretReferenceView {           // 服务端只回引用与键名
  provider: 'vault'; path: string; version: number
  key_names: string[]                            // 如 ["username","password"]，仅键名
  last_rotated_at: string | null
}

export interface MetadataProfile {
  id: number; data_source_id: number; version: number
  status: ProbeStatus                            // probing / ready / failed / expired
  sampling: { rows: number; scope: SamplingScope; tables: string[] | null }
  masking_policy: Record<string, unknown>
  masked_samples: Record<string, Array<Record<string, string>>>  // 表名 → 行数组，值已脱敏
  tables_count: number; sha256: string
  expires_at: string | null; error_message: string | null
  created_at: string; created_by_display_name: string | null
}

export interface SchemaSnapshot {                // 建议契约，见 §10 第 1 条
  tables: Array<{
    schema: string; name: string; comment: string | null
    row_count_approx: number | null
    columns: SchemaColumn[]
  }>
}

export interface SchemaColumn {
  name: string; data_type: string; nullable: boolean; is_primary_key: boolean
  comment: string | null
  null_ratio: number | null                      // numeric(6,4)
  distinct_approx: number | null
  sensitive_level: SensitiveLevel
  masked: boolean                                // 该字段的样本是否已被脱敏
}
```

## 5. 核心流程

### 5.1 登记数据源

1. `maker` 在列表页点「新建连接」→ 打开 `DataSourceEditDrawer`（`mode='create'`）。
2. 选择 `type` → `EndpointFields` 切换到该类型的字段组（见 §6.1）；「仅注册不真连」类型渲染为**可选中但禁用**，下方黄条说明「当前版本仅登记接口，未接入真实连接器，无法执行连通性测试与探查」。
3. 填 `name`（项目内唯一）/ `env` / `sensitive_level` / `tags` / `owner_id`。
4. 凭据分区填 `key_names` 对应的值（如 `username`、`password`）→ 提交时随请求体一次性发出，**提交后立即清空本地字段**。
5. `POST /datasources`（带 `Idempotency-Key`）→ 后端校验 `endpoint` 无凭据键 → 写 Vault → 建 `secret_reference` 与 `data_source`（单事务）→ 写审计事件 `datasource.created`。
6. 成功后关闭抽屉、刷新列表、toast 成功并给「立即测试连通性」的次要动作。

### 5.2 编辑（凭据不回显）

1. `GET /datasources/{id}` → 表单回填非凭据字段；凭据分区渲染 `****` 占位与「重新设置」按钮。
2. **不点「重新设置」** → 提交体**不含**凭据字段，后端保留原 `secret_ref`。
3. **点「重新设置」** → 清空分区并要求重填 `key_names` 的**全部**键（不允许部分更新，避免旧值与新值混用同一 Vault 版本）；提交体带 `credentials` → 后端写 Vault 新版本 → `secret_reference.version + 1`，旧版本留存供审计。

### 5.3 连通性测试

```
[测试] → POST /connectivity-tests → 202 {test_id, state:'pending'}
   └─ usePolling(2s, only while state==='pending') → GET /connectivity-tests/{test_id}
        ├─ state='succeeded' → 绿：连接成功（{latency_ms} ms），展示探测到的 server_version
        ├─ state='failed'    → 红：按 code 给文案（不含连接串）
        ├─ state='timeout'   → 橙：连接超时（>{timeout_sec}s）
        └─ state='denied'    → 黄：认证失败/凭据无最小权限
   结束 → 停止轮询；刷新 data_source.last_tested_at / last_test_ok
```

四态文案与图标：成功 `CircleCheck`（success）、失败 `CircleClose`（danger）、超时 `Timer`（warning）、权限不足 `Lock`（warning）。**错误信息只允许出现：错误码文案、`request_id`、主机名与端口的掩码形式（如 `10.**.**.5:3306`）**；出现 `jdbc:`/`mysql://`/`user:pass@` 形态的字符串时前端**丢弃该文案**并显示通用提示（防御后端漏脱敏）。

### 5.4 元数据探查

1. 详情页点「探查」→ `ProbeForm`：`sampling.rows`（默认 1000，上限后端定）、`sampling.scope`（`full_tables` / `selected_tables` / `schema_only`）、`masking_policy`（`auto` 或按字段类型指定掩码方式）、`selected_tables`。
2. `POST /probes`（`Idempotency-Key`）→ 返回 `{profile_id, version}`，`status='probing'`。
3. 前端以 2s 轮询 `GET /profiles/{version}` 直到 `status ∈ {ready, failed}`；`probing` 期间显示**不确定进度条** + 阶段文案（「连接 → 读取 Schema → 采样 → 脱敏 → 落库」）。
4. `ready` → 展示 `tables_count`/`sha256`/`expires_at`，并展开 Schema 树；`failed` → 展示 `error_message`（后端已脱敏）+ 重试入口。
5. `expired` → 版本列表标黄，且**禁止**在 fe-04 用该 Profile 生成方案（提示「重新探查」），对应错误码 `METADATA_PROFILE_EXPIRED`。

## 6. 关键算法与规则

### 6.1 `DataSourceType` → 必填字段表（`EndpointFields` 的配置来源）

| type | 是否真连 | endpoint 必填键 | 凭据（Vault `key_names`） | 备注 |
|---|---|---|---|---|
| `mysql` | 是 | `host` `port` `database` | `username` `password` | 端口默认 3306；`charset` 选填 |
| `postgresql` | 是 | `host` `port` `database` | `username` `password` | 端口默认 5432；`schema` 选填 |
| `doris` | 是 | `host` `port` `database` | `username` `password` | FE 端口默认 9030；`warehouse` 选填 |
| `minio` | 是 | `endpoint` `bucket` `path` | `access_key` `secret_key` | `endpoint` 为 URL（含 scheme）；`path` 为 bucket 内前缀 |
| `csv` | 是 | `path` `encoding` `delimiter` | 无（`secret_ref` 可空） | `has_header` 选填；`path` 为 MinIO 路径或本地挂载路径 |
| `json` | 是 | `path` `encoding` | 无 | `json_path` 选填（根节点定位） |
| `parquet` | 见 §10 第 2 条 | `path` | 无 | 暂按「仅注册」处理 |
| `oracle` | **否** | `host` `port` `service_name` | `username` `password` | 表单可存，禁测试/探查 |
| `clickhouse` | **否** | `host` `port` `database` | `username` `password` | 同左 |
| `excel` | **否** | `path` | 无 | 同左 |
| `rest` | **否** | `base_url` `auth_type`（`none`/`basic`/`bearer`/`api_key`） | 依 `auth_type`：`basic`→`username`+`password`；`bearer`→`token`；`api_key`→`api_key` | 同左 |

规则：字段表是**前端唯一事实来源**（`types.ts` 的 `ENDPOINT_FIELDS` 常量）；`endpoint` 的键**不得**包含 `password`/`token`/`secret`（后端 `schemas/` 会拒绝，前端在提交前用同一黑名单做防呆校验并给字段级错误）。

### 6.2 列表页列与操作

| 列 | 字段 | 渲染 |
|---|---|---|
| 名称 | `name` | 链接到详情；禁用时灰显 + 「已禁用」标签 |
| 类型 | `type` | `enumLabel('DataSourceType')` |
| 环境 | `env` | `prod` 用 danger tag |
| 敏感级别 | `sensitive_level` | `enumLabel('SensitiveLevel')`，四级配色递进 |
| 负责人 | `owner_display_name` | 空显示 `—` |
| 状态 | `status` | `active` 绿 / `disabled` 灰 |
| 最近探查 | `profiles[0].created_at` + `ProbeStatus` | 无 Profile 显示「未探查」+ 快捷探查按钮 |
| 最近测试 | `last_tested_at` + `last_test_ok` | 未测试显示 `—` |
| 操作 | — | 编辑 / 测试连通性 / 探查 / 禁用（启用）/ 删除（`maker` 可见） |

筛选：`type` `env` `sensitive_level` `status` 多选 + 名称模糊 `q`；筛选变化写回 URL query 并重置到第 1 页。

### 6.3 敏感字段展示规范

| 字段类别 | 默认展示 | 可临时查看原文 | 审计 |
|---|---|---|---|
| 凭据（Vault 内） | 永不展示，仅 `****` 占位 + `key_names` 键名回显 | **否**（前端无接口可拿） | 提交/轮换时后端写事件 |
| `masked_samples` 样本值 | 已脱敏值（后端入库前脱敏） | **否**——库里不存在原文，无解敏对象 | 探查时写 `metadata.probed` |
| `endpoint` 非凭据键（`host`/`port`/`bucket`/`path`） | 明文（本就不属敏感值） | 不适用 | — |
| 错误信息 / `error_message` | 掩码化主机与端口后展示 | 否 | 由后端决定 |
| 字段级样本（若 M3 引入按权限解敏） | 掩码 | 需后端提供 `POST .../reveal` + 证据事件 | **待定，见 §10 第 5 条** |

`fe-01` 的 `SensitiveText` + `useSensitiveReveal` 在本页**不启用**（无可解敏对象）；保留组件是为 fe-05 的资源范围/凭据引用视图复用。

### 6.4 脱敏样本表格约束

- 表头固定带一条 `Alert`：「样本已脱敏（掩码/哈希/截断），平台不保存原始值」。
- 单表最多渲染 `limit`（默认 50）行，超出显示「仅展示前 N 行」。
- 单元格等宽字体；空值显示 `NULL`（区分空串 `''`）；`null_ratio`/`distinct_approx` 以 tooltip 呈现。
- **无「查看原文」「导出原文」「复制整行」按钮**；仅允许复制单个已脱敏单元格（便于排障）。
- 复制动作不写审计（复制的是已脱敏值）；若未来引入解敏，复制必须写审计。

## 7. 错误码与拒绝语义

| 触发条件 | 错误码 | HTTP | 本页行为 |
|---|---|---|---|
| 缺 `maker` 角色 | `ROLE_REQUIRED` | 403 | 隐藏写操作入口（体验）+ 操作时展示无权限提示 |
| 项目内重名 | `CONFLICT` | 409 | 表单字段级错误「名称已存在」 |
| `endpoint` 含凭据键 / 必填键缺失 | `VALIDATION_ERROR` | 422 | `details.fields` 映射到字段 |
| 同 `Idempotency-Key` 不同 body | `IDEMPOTENCY_CONFLICT` | 409 | 提示刷新后重试，不自动重发 |
| 网络不可达 | `DATASOURCE_UNREACHABLE` | 200/4xx（见 §10 第 6 条） | 红：连接失败（含掩码主机） |
| 认证失败/无最小权限 | `DATASOURCE_AUTH_FAILED` | 同上 | 黄：凭据或权限不足 |
| 连接超时 | `DATASOURCE_TIMEOUT` | 同上 | 橙：连接超时 |
| Profile 已过期仍被引用 | `METADATA_PROFILE_EXPIRED` | 409 | 黄条 + 「重新探查」 |
| 数据源不存在/已删除 | `NOT_FOUND` | 404 | 抽屉关闭 + toast + 回到列表 |
| 删除时存在关联 Pipeline | `CONFLICT` | 409 | 提示受影响对象数量与清单入口（不显示 Pipeline 内容） |
| 探查未捕获异常 | `INTERNAL_ERROR` | 500 | 展示 `request_id`；`MetadataProfile.status='failed'` 优先于该错误 |

前端不写证据账本；`datasource.created` / `datasource.connectivity_tested` / `metadata.probed` 由后端写入。

## 8. 安全与合规约束

- **无明文 Secret**：凭据字段的响应式对象在提交成功后立即置空；不写入 Pinia、不写 sessionStorage/localStorage、不进 URL、不进 `console`；编辑态一律 `****`。
- **脱敏默认开启**：样本表格与错误文案默认掩码；`MaskedSampleTable` 不接受原文输入（类型上就是 `string` 的已脱敏值）。
- **错误信息不得含连接串**：前端对 `jdbc:`、`://`、`user:pass@`、`Bearer ` 形态做**拦截式过滤**（命中即替换为通用提示），与后端 `core/logging` 的 `redact_processor` 形成双层防御。
- **租户与项目**：所有请求带 `project_id`；`GET /datasources/{id}` 跨租户 → 后端 `TENANT_MISMATCH`(403)，前端展示 403 页而非空详情。
- **审计**：创建/修改/启停/测试/探查/删除均由后端写 `EvidenceLedger`；前端在操作确认弹窗中展示「本次操作将记录的审计事件类型」，让用户预期可追溯。
- **只读探查**：探查配置界面明确标注「只读探查，不修改源端数据，不读取超出采样范围的业务数据」；不提供任何写源端的入口。
- **副作用**：连通性测试与探查是 `ToolName.DATASOURCE_CONNECTIVITY_TEST` / `ToolName.METADATA_PROBE`（P3，免 Capability），由后端经 ToolBroker 执行；前端不得假设可绕过。

## 9. 测试要点

- **单元测试**
  - 动态表单：切换 `type` → 必填键集合与占位文案正确；「仅注册不真连」类型 → 测试/探查按钮 `disabled` 且提示文案存在。
  - 凭据：未点「重新设置」时提交体**不含** `credentials` 键；点了之后缺失任一 `key_name` → 表单校验失败。
  - endpoint 黑名单：`{host:'h', password:'x'}` → 提交前即被拦并给出字段级错误。
  - 样本表格：行内不含「查看原文」按钮（快照测试断言 DOM 中无该文案）。
  - 错误文案过滤：注入 fake 响应 `message: 'jdbc:mysql://u:p@h:3306/db 连接失败'` → 渲染结果不含 `u:p@h`。
  - `ProbeStatusTag`：`expired` → 黄色 + 「需重新探查」。
- **集成测试**：创建 → 测试 → 探查 → 看到脱敏样本的完整路径（对真 MySQL/MinIO 容器）；探查失败时 `status='failed'` 且 `error_message` 不泄露凭据。
- **必须覆盖的反例**：越权读取他人项目数据源 → 403 且不渲染任何字段；重复提交（同幂等键）只产生一个数据源；探查期间并发提交两次探查 → 只产生一个新版本号。

## 10. 未决与风险

| 事项 | 现状 | 建议 / 验证方式 |
|---|---|---|
| `schema_snapshot` 的键名未冻结 | 《核心数据字典》只写「表/字段/类型/可空/主键/注释/近似统计」，没有键名 | 本页给出 `SchemaSnapshot` 建议契约；需 be-04 定稿后回填，否则前端解析会与后端漂移 |
| `parquet` 是否真连 | `models/enums.py` 未标注「仅注册」，但《需求对齐记录》§二.1 把 Parquet 列入「仅注册」 | 建议按「仅注册」实现并在 `enums.py` 补注释；需拍板 |
| 探查进度无字段 | `metadata_profile` 无进度列 | 建议不新增列，用不确定进度条 + 阶段文案；若要百分比需后端在 Redis 缓存进度（`meta:profile:{id}` 键已预留 `KEY_META_CACHE`） |
| 连通性测试的 HTTP 语义 | 未定：测试失败是 200 + `state='failed'`，还是 4xx + `DATASOURCE_UNREACHABLE` | 建议 **200 + `state` 字段**（业务结果不是请求错误），4xx 只用于权限/参数问题；需 with be-03 确认 |
| 字段级解敏（临时查看 + 审计） | M1 数据源模块无原文可解敏 | 若 M3 为审批人提供「看一个样本值」能力，需后端新增 `POST .../reveal` 并写证据事件；本页现不提供入口 |
| `sampling.rows` 上限与 `scope` 枚举 | 未定义 | 建议 `rows ≤ 10000`、`scope ∈ {full_tables, selected_tables, schema_only}`（`sampling` 为 jsonb，需 be-04 固化并写入 `schemas/` 校验） |
| `masking_policy` 结构未定义 | `metadata_profile` 有该列但无结构约定 | 建议 `{default: 'mask_middle'|'hash'|'truncate', by_column_type: {...}}`；需 be-04 定稿 |
| 删除数据源的关联限制 | 未定：软删还是拒删 | 建议有关联 Pipeline/Preparation 时拒删（`CONFLICT` 并返回引用计数），否则软删；需拍板 |
| 标签（`tags`）输入组件 | 未定用 Element Plus 的 `el-select` allow-create 还是自研 | 建议 `el-select multiple filterable allow-create`；限制 20 个、单个 ≤ 32 字符 |
