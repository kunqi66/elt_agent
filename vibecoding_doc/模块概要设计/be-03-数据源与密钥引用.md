## 1. 职责与边界

- **做什么**
  1. 数据源登记：按 `DataSourceType` 分派连接器注册表，按类型对 `endpoint` 做 Pydantic 强校验。
  2. 凭据承载：一律以 `secret_reference`（Vault 路径 + 版本 + 键名）表达，任何接口不落、不回显、不日志明文口令。
  3. Vault 集成：KV v2 写/读/删除版本、AppRole 换取 token、密钥轮转（90 天）。
  4. 受管连通性测试：经 `harness.ToolBroker` 调 `ToolName.DATASOURCE_CONNECTIVITY_TEST`（P3 免审批，只读）。
  5. 脱敏回显：对已保存的 `secret_reference` 只返回键名与掩码占位。
  6. 审计：写 `DATASOURCE_CREATED` / `DATASOURCE_CONNECTIVITY_TESTED`。
- **不做什么**
  - **不做元数据探查**：探查（information_schema / 采样 / 脱敏）属 be-04，本模块只负责「连得上」。
  - **不搬运业务数据**：控制面只做连接定位与最小权限探测，不读业务行。
  - **不直接连库绕过 ToolBroker**：连通性测试必须经工具出口；`services/` 不得在路由里裸调连接器。
  - 不做跨库类型映射（be-10 的 HOCON/Schema 对齐职责）。
  - 不实现 Capability 签发（be-05）；本模块的测试工具是 P3，无需令牌。
- **所在分层**：`api/datasources.py`（校验/权限/转发）→ `services/datasource.py`（编排、事务、Vault 时序、错误映射）→ `clients/vault.py`（外部系统封装）+ `clients/db/*`（只读探测驱动，be-04 复用）+ `harness.ToolBroker`（副作用出口）。`models/datasource.py` 只定义 ORM；`schemas/datasource.py` 承载按类型校验。

## 3. 对外接口

### 3.1 HTTP（前缀 `/api/v1/datasources`）

> ⚠️ **本节已于 2026-10-16 按 `frontend/src/api/datasource.ts` 改写**（前端为先，见下方「与初稿的差异」）。
> 初稿的 `PATCH` / `secret` / 同步连通性 / `soft-delete` 均已废弃。

| 方法 | 路径 | 角色 | 幂等 | 说明 |
|---|---|---|---|---|
| POST | `/` | 任一管理角色㋡ | **是** | 入参 `{name, type, env, endpoint, credentials?, sensitive_level, tags}`；`credentials` 只写 Vault，永不回显 |
| GET | `/` | 任一项目角色 | 天然 | 分页列表；`type`/`env`/`sensitive_level`/`status` 支持逗号分隔多值 |
| GET | `/{id}` | 任一项目角色 | 天然 | 单条详情；含 `secret_ref` 视图（**只有键名**） |
| PUT | `/{id}` | 管理角色 | 否 | `endpoint`/`tags`/`env`/`sensitive_level`；**不含 `credentials`** |
| POST | `/{id}/credentials` | 管理角色 | **是** | 换凭据；写 Vault **新版本**，旧版本保留 |
| POST | `/{id}/disable` | 管理角色 | **是** | 停用；探查与执行前会拒 |
| POST | `/{id}/enable` | 管理角色 | **是** | 启用 |
| DELETE | `/{id}` | 管理角色 | **是** | 有引用（探查档案 / 将来的流水线版本）时 → `CONFLICT` |
| POST | `/{id}/connectivity-tests` | 管理角色 | **是** | **202** + `{test_id}`，轮询取结果 |
| GET | `/{id}/connectivity-tests/{test_id}` | 管理角色 | 天然 | 状态与耗时，不含连接串 |

㋡ **管理角色 = `maker` / `operator` / `checker_security`**，判定在纯函数
`engines/policy/roles.py::can_manage_datasource`。**`auditor` 刻意不在内**：
他的职责是事后核证，能改配置就无法保证「他看到的账本与当时的事实一致」。

元数据探查的 4 条路由（`/probes`、`/profiles`、`/profiles/{v}/schema`、`/profiles/{v}/samples`）
挂在同一前缀下，归 **be-04**，不在本节列。

#### 与初稿的差异（前端为准，均已实现）

| 项 | 初稿 | 采纳 | 理由 |
|---|---|---|---|
| 修改 | `PATCH`，含 `secret` | `PUT`，**不含 `credentials`** | 换凭据是独立动作，要有自己的审计与幂等键；混在同一个 PUT 里，一次改名会顺手把凭据覆盖成 `null` |
| 停用/启用 | `DELETE` 软删 | `POST .../disable` + `.../enable` + `DELETE` 真删 | 「停用」与「删除」是两件事；合成一个接口后，用户点「停用」实际做的是软删，语义对不上 |
| 凭据字段名 | `secret` | `credentials` | 前端已定型。后端字段名也统一叫 `credentials`，`secret_ref` 只用于**响应**里的引用视图 |
| 连通性 | 同步返回 `{ok, latency_ms}` | **202 + `test_id` 轮询** | 直连远端可能耗时数秒到数十秒（DNS、握手、超时），同步会占住一个 API worker |
| 单独取 secret-ref | `GET /{id}/secret-reference` | 并入 `GET /{id}` 的 `secret_ref` 字段 | 一个只读的从属资源不值得单独一条路由 |
| 探查 | 无 | `POST /{id}/probes` 等 4 条（be-04） | 原设计把探查混在连通性测试里，见 be-04 spec §5.4 |

## 5. 核心流程

### 5.1 数据源登记（含 Vault 写入时序）

1. `require_role(RoleName.MAKER)` + `resolve_project`；`UK(project_id, name)` 预检。
2. `validate_endpoint(type, endpoint)`：按类型 Pydantic 模型强校验；`assert_no_credential_keys(endpoint, where="endpoint")`。
3. 若有 `secret`（瞬时对象，不落库）：校验键名 ∈ 白名单 `ALLOWED_SECRET_KEYS`；否则 `VALIDATION_ERROR`。
4. **先写 Vault**：`path = VaultClient.build_path(tenant_id, project_id, name)`；`version = await vault.write_kv(path, secret)`。
5. **再写 `secret_reference`**：`key_names = sorted(secret.keys())`，`provider="vault"`，`last_rotated_at=utcnow()`。
6. **最后写 `data_source`**：`secret_ref_id = ref.id`；同事务提交（步骤 5、6 同一事务）。
7. 若步骤 5/6 事务失败 → 补偿删除刚写入的 Vault 版本（`delete_kv_versions(path, [version])`），避免孤儿密钥；补偿失败只告警并记 `error` 日志（孤儿由轮转巡检清理）。
8. 写 `EvidenceLedger.append(DATASOURCE_CREATED, payload)`；payload 只含 `data_source_id / type / env / key_names`，**不含值**。
9. 返回 `DataSourceDTO`，其中 `secret_ref.masked_values = {k: "***" for k in key_names}`。

**无 secret 的数据源**（公开 CSV / 只读 MinIO）：跳过 3–5，`secret_ref_id = NULL`。

### 5.2 连通性测试

```
api ──▶ services.test_connectivity
          ├─ resolve_project + 取 data_source（带 tenant_id 过滤）
          ├─ 读 Vault：secret 只在内存物化（read_kv），不落任何持久层
          ├─ harness.ToolBroker.execute(DATASOURCE_CONNECTIVITY_TEST, token=None, args)
          │     └─ clients/db/* 执行最小权限探测（SELECT 1 / stat_object / 打开文件头）
          ├─ 更新 data_source.last_tested_at / last_test_ok
          ├─ 写 EvidenceLedger(DATASOURCE_CONNECTIVITY_TESTED)
          └─ 返回 {status, latency_ms, error_code?}   # 不含 host/port/db/连接串
```

- 测试**不读业务行**：数据库类只执行 `SELECT 1`；MinIO 只 `stat_object`/`bucket_exists`；CSV/JSON 只读首行推断可解析性；REST 只 `HEAD base_url`。
- 目标定位从 `endpoint` 拼装、凭据从 Vault 物化；两者都只在 `args` 内，落 `ToolBroker` 后即释放。
- 工具执行结果映射为 `status ∈ {ok, failed, timeout, permission_denied}`。

### 5.3 密钥轮转（90 天）

1. `beat` 每日扫描 `secret_reference.last_rotated_at < now() - 90d`（`RUN_*` 之外的巡检任务，M3 排期）。
2. 从 Vault 生成/接收新版本 → `write_kv` → 新 `version`。
3. 由于 `UK(provider, path, version)` **只增不改**（`secret_reference` 不可变语义），轮转产生**新行**并更新 `data_source.secret_ref_id` 指向新版本；旧版本保留一段时间后删除。
4. 因轮转会改 `data_source.secret_ref_id`，需同步确认该列不在任何不可变白名单内（`data_source` 是可变表）。

### 5.4 状态与非法转移

| 实体 | 允许转移 | 非法转移处理 |
|---|---|---|
| `data_source.status` | active → disabled（软删）；disabled → active（重新启用） | 对 disabled 源发起测试 → `CONFLICT` |
| `secret_reference` | 只增行（新版本）；不 UPDATE、不原地删除当前版本 | 试图改已存在 `(provider, path, version)` → `CONFLICT`（UK 命中） |
| 连通性测试结果 | `last_test_ok` 可反复变更（可变表） | — |

## 6. 关键算法与规则

### 6.1 连接器注册表（按 `DataSourceType` 分派）

| type | 真做 | endpoint 必需字段 | secret 键 | 测试探测 |
|---|---|---|---|---|
| `mysql` | 是 | `host, port, database` | `username, password` | `SELECT 1` |
| `postgresql` | 是 | `host, port, database[, schema]` | `username, password` | `SELECT 1` |
| `doris` | 是 | `host, port, database`（FE 查询端口 9030） | `username, password` | `SELECT 1` |
| `csv` | 是 | `path` 或 `{bucket, object_key}` | 无（或 `access_key, secret_key`） | 打开并读首行 |
| `json` | 是 | `path` 或 `{bucket, object_key}` | 同上 | 解析首条对象 |
| `minio` | 是 | `endpoint, bucket[, prefix, region]` | `access_key, secret_key` | `bucket_exists` + `stat_object` |
| `oracle` / `clickhouse` | 否 | 仅注册表单字段（`host, port, database`） | `username, password` | 未实现 → `DATASOURCE_UNREACHABLE` 前先 `VALIDATION_ERROR`（提示「连接器未启用」） |
| `excel` / `parquet` | 否 | 仅注册 `path` | 无 | 同上 |
| `rest` | 否 | `base_url` | `token` / `api_key` | 同上 |

注册表实现为 `CONNECTOR_REGISTRY: dict[DataSourceType, ConnectorSpec]`（`schemas/datasource.py` 或 `clients/db/__init__.py`）；未启用类型的探测驱动为 `None`，登记时即拒绝（`VALIDATION_ERROR`，避免出现「能建不能连」的僵尸数据源）。

### 6.2 endpoint 禁键校验（`assert_no_credential_keys`）

1. 递归遍历 `endpoint`（含嵌套 dict/list），键名匹配正则 `(pass(word|wd)?|secret|token|credential|api[_-]?key|private[_-]?key|access[_-]?key|conn(ection)?[_-]?str)` → 抛 `VALIDATION_ERROR`，`details` 指出命中键路径（不回显值）。
2. 值侧兜底：任何字符串值命中 be-01 的 DSN 规则（`mysql://...` 等）也拒绝。
3. 该校验在**写前**执行，且 `data_source.endpoint` 的 Pydantic 模型用 `model_config = ConfigDict(extra="forbid")` 防止额外字段夹带。
4. `secret_reference.key_names` 是**键名清单**（如 `["password","username"]`），不走本规则——它不含值。

### 6.3 密钥键名白名单

`ALLOWED_SECRET_KEYS = {username, password, token, api_key, access_key, secret_key, private_key, passphrase, cert, client_id, client_secret}`。写入 Vault 的 `data` 字典键必须全部命中白名单，值必须为非空字符串（`SecretStr`），否则 `VALIDATION_ERROR`。Vault `path` 约定 `{VAULT_KV_MOUNT}/etl/project-{project_id}/ds-{uuid4hex}`（用 uuid 而非自增 id，使路径在 `data_source` 插入前即可确定，满足「先写 Vault」的时序）。

### 6.4 连通性测试的错误映射（不回显连接串）

| 驱动异常 | `ErrorCode` | HTTP | `status` | 账本事件 |
|---|---|---|---|---|
| 网络不可达 / 连接被拒 | `DATASOURCE_UNREACHABLE` | 502 | `failed` | `DATASOURCE_CONNECTIVITY_TESTED` |
| 认证失败 / 权限不足 | `DATASOURCE_AUTH_FAILED` | 502 | `permission_denied` | 同上 |
| 探测超时 | `DATASOURCE_TIMEOUT` | 504 | `timeout` | 同上 |
| 成功 | `OK` | 200 | `ok` | 同上 |

错误 `message` 只写「数据源不可达/认证失败/超时」与 `data_source_id`；服务端日志记 `host/port/database` 与异常类型，**不记 DSN、不记口令**（be-01 脱敏链再兜底一层）。

### 6.5 前端脱敏回显

`masked_secret_view(ref)` 返回 `{provider, path, version, key_names, masked_values}`，其中 `masked_values = {k: "***" for k in key_names}`。前端表单对 `password`/`token` 类字段以占位符渲染，**编辑时留空表示不变更**；提交新值才触发 Vault 写新版本。任何接口、任何字段都**不得**返回键值——包括管理接口。

## 7. 错误码与拒绝语义

| 触发条件 | 错误码 | HTTP | 写证据账本 |
|---|---|---|---|
| endpoint 缺必填 / 类型不符 / 含凭据键 | `VALIDATION_ERROR` | 422 | 否 |
| 未启用连接器类型（oracle/clickhouse/excel/parquet/rest） | `VALIDATION_ERROR` | 422 | 否 |
| secret 键名不在白名单 | `VALIDATION_ERROR` | 422 | 否 |
| 非法类型 / 额外字段 | `VALIDATION_ERROR` | 422 | 否 |
| 跨租户 / 非成员访问数据源 | `TENANT_MISMATCH` / `FORBIDDEN` | 403 | 否 |
| 重复名称 `UK(project_id,name)` | `CONFLICT` | 409 | 否 |
| 删除仍被 Pipeline 引用的数据源 | `CONFLICT` | 409 | 否 |
| 测试失败：不可达 / 认证 / 超时 | `DATASOURCE_UNREACHABLE` / `DATASOURCE_AUTH_FAILED` / `DATASOURCE_TIMEOUT` | 502/502/504 | 是（`DATASOURCE_CONNECTIVITY_TESTED`） |
| Vault 不可用或读不到版本 | `INTERNAL_ERROR` | 500 | 否（服务端日志含 `path/version`，不含值） |
| 数据源不存在 | `NOT_FOUND` | 404 | 否 |

## 8. 安全与合规约束

- **无明文 Secret**：库表结构不含凭据列；`endpoint` 禁键校验；响应只回键名与掩码；日志经脱敏链；账本 payload 绝不含值。
- **Secret 引用而非值**：`secret_reference` 只存 `(provider, path, version, key_names)`；值只在 worker/api 内存瞬时物化，用完即弃。
- **Vault 访问**：AppRole（`VAULT_ROLE_ID` + `VAULT_SECRET_ID`）；KV v2（`VAULT_KV_MOUNT=kv`）；生产自检要求 `VAULT_ADDR` 为 HTTPS 或回环（be-01）。轮转周期 90 天。
- **副作用出口**：连通性测试经 `ToolBroker` 调 `ToolName.DATASOURCE_CONNECTIVITY_TEST`（P3，免 Capability，执行者 api，只读）。
- **租户过滤**：所有查询带 `tenant_id`（经 `subject` 解析），跨租户 → `TENANT_MISMATCH`。
- **最小权限探测**：只做 `SELECT 1` / `stat_object` / 文件头解析，不读业务行、不写任何目标。
- **审计**：`DATASOURCE_CREATED`（登记）、`DATASOURCE_CONNECTIVITY_TESTED`（每次测试，含结果状态与耗时）。

## 9. 测试要点

- **单元测试**
  - `validate_endpoint`：六种真做类型各自必需字段缺失 → `VALIDATION_ERROR`；多余字段（`extra=forbid`）→ 拒绝。
  - `assert_no_credential_keys`：`{"password": "x"}`、嵌套 `{"opts": {"token": "y"}}`、值为 `mysql://u:p@h/db` → 全部拒绝且**不把值写进错误消息**。
  - `ALLOWED_SECRET_KEYS`：`{"dba": "x"}` → 拒绝；`{"username","password"}` → 通过。
  - `masked_secret_view`：输出只含键名与 `***`，序列化后字符串中不含任何键值。
  - `VaultClient.build_path`：路径含 `tenant/project` 且不含用户可注入字符。
- **集成测试**（真实 PG/Redis/Vault）
  - 登记：Vault 写入产生新 `version`，`secret_reference` 行与之一致；模拟第 6 步失败 → 触发补偿删除（Vault 版本被清理）。
  - 连通性测试：对可达 MySQL 返回 `ok`；停掉目标 → `DATASOURCE_UNREACHABLE`（502）；错误响应体不含 `host/database/DSN`。
  - 轮转：`last_rotated_at` 超 90 天 → 新版本行产生、`data_source.secret_ref_id` 指向新版本、旧版本记录仍可读。
  - `DATASOURCE_CONNECTIVITY_TESTED` 与 `DATASOURCE_CREATED` 落账本且 payload 无敏感值。
- **必须覆盖的反例**：endpoint 携带 `password` 键被拒；错误响应/日志/账本中出现连接串或口令（全库 grep + 响应断言）；跨租户读数据源；未启用类型的登记请求。
- **测试基建**：SQLite 内存库验证 ORM 与约束（`UK(project_id,name)`、`UK(provider,path,version)`）；Vault/MySQL/Doris 相关标 `integration` 在 ECS 上跑。

## 10. 未决与风险

| 事项 | 现状 | 建议 / 验证方式 |
|---|---|---|
| Vault 写入是否须经 ToolBroker | 工具注册表（《概要设计总纲》§5）**无** vault 写入工具，但安全红线 1 要求所有外部写经 Broker | **建议**新增 `ToolName.SECRET_PUT`（或显式豁免「Vault 写入属控制面配置面」）；在 be-05 一并拍板 |
| 缺少数据源更新/删除审计事件 | `EvidenceEventType` 无 `datasource.updated` / `datasource.disabled` | **建议新增**这两个事件；在此之前只落 structlog |
| `DATASOURCE_*` 无对应异常子类 | 三个码已在 `ErrorCode`，无 `AppError` 子类 | **建议新增** `DataSourceUnreachableError` / `DataSourceAuthFailedError` / `DataSourceTimeoutError`（HTTP 502/502/504） |
| 密钥轮转调度未落 | 只有 90 天约定，无任务 | M3 在 `tasks/maintenance.py` 加 `rotate_due_secrets`；需确认是否自动轮转还是人工触发 |
| 建源时 Vault 先行产生孤儿版本 | 已定义补偿删除，但补偿失败会留孤儿 | 补偿失败的孤儿由轮转巡检（按 `created_at` 与 `secret_reference` 反查）清理；M3 实现 |
| 文件源上传通道 | CSV/JSON 支持 `path`（本地/MinIO）；浏览器上传是否落 MinIO 未定 | Nginx 已放 `client_max_body_size 32m`；建议上传走 MinIO 直传，M1 先支持 `bucket+object_key` |
| 连接池/探测超时默认值 | 未定义 | 建议 `DATASOURCE_TEST_TIMEOUT_SEC=10`、单次探测连接数 1，加入 `Settings` |
| 敏感级与测试的关系 | `sensitive_level=restricted` 是否限制测试者角色 | 建议 restricted 源仅 `maker`+`checker_security` 可测；待拍板 |
| `data_source.env` 与 `project.env` | 二者都存在，可能出现项目 dev 下登记 prod 源 | 建议登记时校验 `data_source.env <= project.env` 的严重度序；待拍板 |
