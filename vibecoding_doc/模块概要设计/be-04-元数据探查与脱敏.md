## 1. 职责与边界

- **做什么**
  1. 只读探查：列出 schema / 表 / 字段 / 类型 / 可空 / 主键 / 注释，及近似统计（`row_count_approx` / `null_ratio` / `distinct_approx`）。
  2. 采样与超时控制：按配置采样行数与范围，逐语句与整轮设超时上限。
  3. **入库前脱敏**：样本按字段名正则 + 类型 + `SensitiveLevel` 命中掩码 / 哈希 / 截断，原文不落库、不进日志、不进 LLM 上下文。
  4. 生成不可变指纹：计算 `metadata_profile.sha256`，支撑「Profile 是否变化」与「过期判定」。
  5. Profile 版本化与过期：`version` 只增不改；过期后阻断生成（`METADATA_PROFILE_EXPIRED`）。
  6. 审计：写 `METADATA_PROBED`。
- **不做什么**
  - **不修改源端**：任何 DDL/DML 一律禁止（白名单 + 只读会话 + 最小权限账号三重）。
  - **不把样本原文写入任何持久层或日志**；不给 LLM 投喂未脱敏样本（生成本身属 be-09/be-10）。
  - 不做 Schema 对齐与字段映射（be-10 的门禁职责）；本模块只产出 Profile。
  - 不做连通性测试（be-03）；本模块假定数据源已可连。
  - 不做业务数据搬移（数据面 SeaTunnel 职责）。
- **所在分层**：`api/datasources.py`（探查路由，与 be-03 同文件）→ `services/metadata.py`（编排、事务、ToolBroker 调用、错误映射）→ `clients/db/*`（各库只读驱动，IO）+ `harness.ToolBroker`（副作用出口，P3 只读工具）。**纯算法**（脱敏、schema 规范化、diff、采样计划、SQL 白名单）全部在 `engines/metadata/`，只依赖 Pydantic + 标准库。

## 3. 对外接口

### 3.1 HTTP（前缀 `/api/v1`）

> 🔴 **本节已于 2026-10-16 按 `frontend/src/api/datasource.ts` 改写**（前端为先，差异见下表）。
> 探查从 be-03 的「连通性测试」里**独立出来**：一次只读握手不该真读远端库并落样本，
> 而原设计的 `scope` 在后端也无路可传。

| 方法 | 路径 | 角色 | 幂等 | 说明 |
|---|---|---|---|---|
| POST | `/datasources/{id}/probes` | 项目成员（`maker`） | **是** | 入参见 §4.1；**202** `{profile_id, version}`（异步） |
| GET | `/datasources/{id}/profiles` | 项目成员 | 天然 | 版本列表（倒序），只回摘要不含全量快照 |
| GET | `/datasources/{id}/profiles/{version}` | 项目成员 | 天然 | 指定版本；`probing` 也返回（前端要显示进度），**不 404** |
| GET | `/datasources/{id}/profiles/{version}/schema` | 项目成员 | 天然 | `?table=` 可选；`probing`/`failed` → 409 |
| GET | `/datasources/{id}/profiles/{version}/samples` | 项目成员 | 天然 | `?table=&limit=`；未抽样表 → 404 且 `details.sampled_tables` |

#### 与初稿的差异

| 项 | 初稿 | 采纳 | 理由 |
|---|---|---|---|
| 触发探查 | `POST /{id}/probe` 同步返回摘要 | `POST /{id}/probes` **202** | 探查要连远端、拉结构、逐值脱敏，可能几十秒；同步会占住 API worker |
| 取快照 | `GET .../profiles/{version}` 含全量 | 拆出 `/schema` 与 `/samples` | 结构快照可能几十 KB，而 Pipeline Studio 多数时候只要结构、不要样本；一次全量下发会把样本（即使已脱敏）送到不需要它的页面上 |
| `latest` 便捷路由 | 有 | **取消** | 前端总是先拿列表再取指定版本；多一条「latest」等于多一条能绕过版本号缓存的路 |
| 扁平 `/profiles/{id}` | 有 | **取消** | 同上，且它与 `/datasources/{id}/profiles/{version}` 是两种定位方式，两套都在则跨租户校验要做两遍 |
| 入参形态 | `{tables, sampling:{rows, scope, masking_policy}}` | 平铺的 `{scope, tables, sampling:{rows}, masking_policy}` | 前端已定型；且 `scope` 是**互斥条件的来源**（§4.1），埋在 `sampling` 里容易被当成可选项 |
| `profile_id` | 前端自选 | **必填、由 service 生成** | 探查结果不能走 `ToolResult.detail`（§5.4），执行器必须知道「往哪个档案里写」 |

## 4. 数据模型

| 表 | 本模块动作 | 关键列 / 约束（见《核心数据字典》§2） |
|---|---|---|
| `metadata_profile` | 读写 | `UK(data_source_id, version)`、`Index(data_source_id, sha256)`、`status`(probing/ready/failed/expired)、`schema_snapshot`、`sampling`、`masked_samples`、`masking_policy`、`tables_count`、`sha256`、`expires_at`、`error_message` |
| `data_source` | 只读 | 取 `type` / `endpoint` / `secret_ref_id` / `sensitive_level` / `env` |
| `secret_reference` | 只读 | 探查也需凭据；值经 Vault 内存物化 |

`metadata_profile` **不是** `__immutable__` 模型（`models/datasource.py` 用 `CreatedAtMixin` 未置 `__immutable__`）：版本行只增，但同一行内 `status` 允许 `probing → ready|failed`、`ready → expired` 转移。`version` 由服务层分配为 `max(version)+1`。

## 5. 核心流程

### 5.1 探查主流程（时序不可颠倒）

```
api ──▶ services.probe
  1. require_role(MAKER) + resolve_project；取 data_source（带 tenant_id）
  2. 校验 type 已启用（be-03 注册表）；版本号 = max(version)+1
  3. INSERT metadata_profile(status=probing, version=n)          # 先占版本，失败亦留痕
  4. 读 Vault 物化 secret（内存）；构造 ProbeDriver（只读会话 + statement timeout）
  5. ToolBroker.execute(METADATA_PROBE, token=None, args={data_source_id, tables, sampling})
       └─ driver: list_schemas → list_tables → describe_table → approx_row_count → sample_rows
  6. engines.sampling 计算近似统计；engines.schema.normalize_schema 规范化
  7. engines.masking：逐列 resolve_policy → mask_row                        ← 入库前已脱敏
  8. E_SENSITIVE_PLAINTEXT 兜底复核每个掩码值，命中则替换 [REDACTED] 并记警告
  9. sha256 = engines.fingerprint.profile_sha256(...)
 10. UPDATE profile(status=ready, schema_snapshot, sampling, masked_samples, sha256, expires_at)
 11. Redis SET KEY_META_CACHE = meta:profile:{profile_id}（TTL = 剩余有效期）
 12. EvidenceLedger.append(METADATA_PROBED)；提交
```

失败路径：步骤 5–9 任一异常 → `UPDATE status=failed, error_message=<脱敏后的原因>`，写 `METADATA_PROBED`（`result=failed`），错误映射见 §7。**已写入的 probing 行不删除**（保留失败痕迹）。

### 5.2 Profile 读取与缓存

1. `GET` 请求按 `profile_id` 或 `(data_source_id, version)` 查库（强制 `tenant_id`）。
2. 命中 `KEY_META_CACHE` 且未过期 → 直接返回；否则回源 DB 并回填缓存（TTL = `expires_at - now`）。
3. 若 `status=ready` 但 `expires_at < now` → 服务层置 `status=expired`（幂等），缓存删除。
4. `expires_at` 为空 → 视为不过期（当前探查总是写 `expires_at`，此分支仅为兼容旧数据）。

### 5.3 过期判定

| 输入 | 判定 | 结果 |
|---|---|---|
| `status != ready` | 非就绪 | `METADATA_PROFILE_EXPIRED`（未就绪亦按过期论） |
| `status=ready` 且 `expires_at > now` | 新鲜 | 放行 |
| `status=ready` 且 `expires_at <= now` | 过期 | 置 `expired` 并抛 `METADATA_PROFILE_EXPIRED` |
| `profile_id` 不存在 | — | `NOT_FOUND` |

生成链路（be-09）在关联 Profile 前调 `assert_profile_fresh`；过期即阻断生成并提示重新探查（PRD §12）。

### 5.4 状态与非法转移

| 实体 | 允许转移 | 非法转移处理 |
|---|---|---|
| `metadata_profile.status` | `probing → ready`、`probing → failed`、`ready → expired` | `failed → ready`（试图复活失败探查）→ 拒绝，重新探查产生新版本 |
| `metadata_profile.version` | 只增（新行）；同 `(data_source_id, version)` 重复插入 → `CONFLICT` | 禁止 UPDATE 已有版本的 `schema_snapshot` / `masked_samples` / `sha256`（服务层不提供该路径） |
| `data_source` | — | 探查不修改数据源任何列 |

## 6. 关键算法与规则

### 6.1 只读 SQL 白名单（`assert_read_only`）

1. 语句只允许以 `SELECT` / `SHOW` / `DESCRIBE` / `EXPLAIN` 开头（去前导空白后比较，忽略大小写）。
2. 禁止关键字（任一命中即拒）：`INSERT UPDATE DELETE MERGE DROP ALTER CREATE TRUNCATE RENAME GRANT REVOKE CALL EXECUTE LOAD DATA OUTFILE DUMPFILE LOCK UNLOCK SET`。
3. 禁止多语句（`;` 后仍有非空非注释内容）与注释注入（`--`、`/*`）——注释会掩盖后半段语句。
4. 访问对象限 `information_schema` / `pg_catalog` / `mysql` / `performance_schema` 及各库自身 schema 的表（采样用 `SELECT ... LIMIT`）。
5. 除白名单外**再加两层**：连接以只读会话打开（PG `SET default_transaction_read_only = on`；MySQL/Doris `SET SESSION TRANSACTION READ ONLY`）；数据源账号使用最小权限（只读账号，be-03 登记时约定）。
6. `assert_read_only` 违规抛 `ValueError`（属程序缺陷，非用户输入错误）→ 服务层映射 `INTERNAL_ERROR` 并 error 日志。

### 6.2 采样与近似统计

| 指标 | 计算 | 边界 |
|---|---|---|
| `row_count_approx` | MySQL `information_schema.tables.table_rows`；PG `pg_class.reltuples`；Doris `SHOW TABLE STATS` 的 `rowCount`；文件源按行扫描（有上限） | 缺统计 → 返回 `-1`（未知），不以 `COUNT(*)` 全表兜底 |
| `null_ratio` | `null_count / sample_size`（`numeric(6,4)`） | `sample_size=0` → `0.0000` |
| `distinct_approx` | 样本去重数按比例放大：`round(distinct_in_sample * row_count_approx / sample_size)`；样本与全量同阶（`sample_size >= row_count_approx`）时直接用去重数 | `row_count_approx < 0` → 直接返回样本去重数 |
| 采样行数 | `sampling.rows` 默认 `1000`，上限 `10000` | 超上限 → `VALIDATION_ERROR` |
| 采样范围 | `sampling.scope`：`full` / `incremental(time_column)` / `tables(...)` | 未知 scope → `VALIDATION_ERROR` |

超时：每语句 `statement_timeout`（默认 10s）+ 整轮探查 deadline（默认 `PROBE_TOTAL_TIMEOUT_SEC=120`）；超时即中止并置 `failed`。文件源按字节上限截断读取（默认 8 MiB），不整文件载入内存。

### 6.3 各库探查实现差异

| 类型 | schema 枚举 | 表枚举 | 字段/主键 | 注释 |
|---|---|---|---|---|
| MySQL | `information_schema.schemata` | `information_schema.tables` | `columns`；`statistics` 中 `COLUMN_KEY='PRI'` 定主键 | `columns.column_comment` |
| PostgreSQL | `information_schema.schemata` | `information_schema.tables`（`table_schema NOT IN ('pg_catalog','information_schema')`） | `columns` + `pg_index`/`pg_attribute` 定主键 | `pg_description`（`obj_description`） |
| Doris | `information_schema.schemata` | `information_schema.tables` + `SHOW FULL TABLES` | `information_schema.columns`；键模型（UNIQUE/AGGREGATE）`SHOW CREATE TABLE` 解析 | `columns.column_comment` |
| CSV | 无（单文件为一个表） | 文件本身 | 首行表头为列名；类型由前 N 行推断（int/float/bool/date/string） | 无 |
| JSON | 无 | 文件/顶层数组为表 | 首个对象/数组元素的键展平（嵌套用 `a.b`）；类型推断 | 无 |
| MinIO 文件源 | bucket 下 prefix 视为命名空间 | 每个对象为一个表 | 复用 CSV/JSON 推断（按扩展名分派） | 无 |

### 6.4 脱敏策略（`resolve_policy` 优先级）

优先级：**字段名正则命中 > 显式 `masking_policy` 规则 > `SensitiveLevel` 兜底 > 默认 `NONE`**。

| 字段名正则（忽略大小写，词边界） | 策略 | 参数 |
|---|---|---|
| `(^|_)(id_?card|idcard|identity|national_?id|cert_?no)($|_)` | `HASH` | 加盐 SHA256 |
| `(^|_)(phone|mobile|tel|msisdn)($|_)` | `KEEP_ENDS` | 保留首尾各 2 |
| `(^|_)(email|mail)($|_)` | `KEEP_ENDS` | 保留首尾各 2 |
| `(^|_)(name|real_?name|full_?name|cust_?name|username)($|_)` | `KEEP_ENDS` | 保留首 1、尾 0 |
| `(^|_)(addr|address|street|location)($|_)` | `TRUNCATE` | 保留前 8 字符 |
| `(^|_)(pass(word)?|pwd|token|secret|api_?key|access_?key|private_?key)($|_)` | `FULL_MASK` | 全 `***` |
| 其他 | 按 `SensitiveLevel`：`public`/`internal` → `NONE`；`confidential` → `KEEP_ENDS`；`restricted` → `HASH` | — |
| 长文本（`data_type` 为 text/blob 且长度 > 256） | `TRUNCATE` | 保留前 32 字符 |

`apply_masking` 具体行为（与 `core/logging._mask_value` 口径一致）：`NONE` 原值；`FULL_MASK` → `***`；`KEEP_ENDS` → 长度 ≤ `keep_prefix+keep_suffix+2` 时全掩码，否则 `前 keep_prefix + *** + 后 keep_suffix`；`HASH` → `sha256_hex(salt + ":" + value)` 全 64 hex（可用于等值比较，不可逆）；`TRUNCATE` → 前 `max_len` 字符 + `…`。NULL 一律保留为 `NULL`（不与其他值混淆）。

### 6.5 `E_SENSITIVE_PLAINTEXT` 兜底

对每个已脱敏值跑 `contains_plaintext_sensitive`（复用 be-01 的值形态规则：18 位身份证 / 11 位手机号 / 邮箱 / `sk-` / JWT / DSN / PEM）。命中说明策略漏配，处理为：该值替换为 `[REDACTED]`，并把该列记入 `masking_policy.warnings`（不阻断整轮探查）。这是**最后一道**防线——正常配置下不应触发；一旦触发即说明字段名正则或 `SensitiveLevel` 需补规则。

### 6.6 `profile_sha256` 计算输入

```
sha256 = sha256_hex(canonical_json({
    "data_source_id": data_source_id,
    "schema":   schema_snapshot,      # 规范化后（键排序、类型字符串统一小写）
    "sampling": sampling_policy,      # rows / scope / masking_policy
    "samples":  masked_samples        # 已脱敏值
}))
```

**排除**易变字段：`id` / `version` / `created_at` / `created_by` / `status` / `expires_at` / `error_message`。因此内容相同的两次探查得到**相同 sha256**（内容寻址），而源端结构或样本变化即产生新指纹——门禁（be-11）据此判断「Profile 是否变化、原方案是否失效」。`canonical_json` 是唯一序列化入口（be-01）。

## 7. 错误码与拒绝语义

| 触发条件 | 错误码 | HTTP | 写证据账本 |
|---|---|---|---|
| 数据源不存在 / 版本不存在 | `NOT_FOUND` | 404 | 否 |
| 跨租户访问 Profile | `TENANT_MISMATCH` | 403 | 否 |
| 非项目成员 | `FORBIDDEN` | 403 | 否 |
| 连接器类型未启用 | `VALIDATION_ERROR` | 422 | 否 |
| 采样配置非法（rows/scope/上限） | `VALIDATION_ERROR` | 422 | 否 |
| 源端不可达 / 认证失败 / 探测超时 | `DATASOURCE_UNREACHABLE` / `DATASOURCE_AUTH_FAILED` / `DATASOURCE_TIMEOUT` | 502/502/504 | 是（`METADATA_PROBED`，`result=failed`） |
| Profile 非 ready 或已过期 | `METADATA_PROFILE_EXPIRED` | 409 | 是（由调用方 be-09 在生成阻断时写） |
| 同 `(data_source_id, version)` 重复插入 | `CONFLICT` | 409 | 否 |
| 只读白名单被违反（程序缺陷） | `INTERNAL_ERROR` | 500 | 否 |

探查失败时 `metadata_profile.error_message` 只存**脱敏后的**原因（如 `unreachable` / `auth_failed` / `timeout` / `sql_guard_violation`），不含 host、连接串或样本原文。

## 8. 安全与合规约束

- **只读保证三重**：`assert_read_only` 白名单 + 只读会话 + 最小权限账号。任何路径都不得执行 DDL/DML。
- **入库前已脱敏**：掩码在 `services/metadata.py` 调 `mask_row` 之后才写 `masked_samples`；DB 里不存在原文。原始样本行只在 `clients/db` 返回值中短暂存在，随即被 `mask_row` 消费，不写日志、不入 `meta` 字段。
- **日志边界**：探查过程日志只记 `data_source_id` / `table` / 行数 / 耗时 / 策略名，**不记样本值**（be-01 脱敏链兜底）。
- **模型上下文边界**：Profile 是唯一投喂给 LLM 的元数据形式，只含 Schema、类型、统计与脱敏样本；be-09 生成时禁止再查源端原始行。
- **Secret**：探查凭据经 Vault 内存物化，用完即弃；不落 `args` 之外的任何持久层。
- **副作用出口**：探查经 `ToolBroker` 调 `ToolName.METADATA_PROBE`（P3，免 Capability，执行者 api，只读）。
- **租户过滤**：所有查询带 `tenant_id`；跨租户 → `TENANT_MISMATCH`。
- **不可变与审计**：`version` 行只增；每次探查写 `METADATA_PROBED`（含 `result`、`tables_count`、`sha256`，不含样本值）。

### 8.1 🔴 探查结果**不能**走 `ToolResult.detail`（2026-10-16 实现时确认）

`harness/broker.py::_safe_detail` 会丢掉所有非白名单键，且任何 Mapping/list/tuple/set 值一律丢。
这是**有意的**（防止某个执行器顺手把远端数据塞进账本），但它意味着：

> **探查结果必须由执行器自己落库**，工具只返回扁平的摘要键
> （`{profile_id, version, tables_count, target}`）。

因此 `MetadataProbeArgs` 需要一个**必填的 `profile_id`**——「往哪个档案里写」。
早先的设计里 executor 自己新建一行、调用方再猜 id；现在的形态是 service 先建 `probing` 行
拿到 id，再把它交给工具。**这是本模块的架构地基**：
改 `_safe_detail` 的白名单去迁就探查结果，会削弱**所有**工具的 payload 卫生。

### 8.2 `metadata_profile` 是「不可变制品」的**部分**例外

CLAUDE.md §5.4 的不可变表清单里没有 `metadata_profile`，这是有意的：
一次探查是「先占位（`probing`）→ 再填内容（`ready`/`failed`）」的两阶段写，
硬套 `__immutable__` 会让流程无法表达。

但**内容不可变由版本保证**：`schema_snapshot` / `masked_samples` 一旦随 `ready` 写入就不再改，
要更新只能升 `version`。`UPDATE` 只允许动 `status` / `error_message` / `completed_at`
三个字段，且只允许作用在 `probing` 行上（`_mark_failed` 里有 `WHERE status='probing'` 兜底）。

## 9. 测试要点

- **单元测试**（`engines/metadata` 纯函数，内存 SQLite/无依赖）
  - `assert_read_only`：`SELECT`/`SHOW`/`DESCRIBE`/`EXPLAIN` 通过；`UPDATE`/`DROP`/`CREATE`/`SELECT 1; DROP TABLE t`/`SELECT 1 -- x\nDROP` 全部拒绝。
  - `resolve_policy`：`id_card`→HASH、`phone`→KEEP_ENDS(2,2)、`user_name`→KEEP_ENDS(1,0)、`address`→TRUNCATE(8)、`password`→FULL_MASK、未命中字段按 `SensitiveLevel` 取值。
  - `apply_masking`：`KEEP_ENDS` 短值（长度 ≤ 参数之和 +2）→ 全掩码；`HASH` 同盐同值稳定、异盐异值；`NONE` 原样；`NULL` 保持 `NULL`。
  - `contains_plaintext_sensitive`：身份证/手机/邮箱/sk-/JWT 命中；普通短串不命中。
  - `normalize_schema` 幂等：同输入两次得到相同字典（`canonical_json` 稳定）；`profile_sha256` 对同内容稳定、对样本变化敏感。
  - `diff_schema`：新增/删除/改类型/改可空性各自分类正确。
  - `estimate_*`：样本含 NULL 的比例、样本去重放大在 `row_count_approx=-1` 时退化。
- **集成测试**（真实 MySQL/PG/Doris/Vault）
  - 端到端：登记源 → 探查 → 库中 `masked_samples` 断言**原文不存在**（对敏感列做反向查找）。
  - 只读：以只读账号探查成功；伪造 DDL 语句被 `sql_guard` 拒绝且源端表未变。
  - 过期：把 `expires_at` 置为过去 → 读请求置 `expired` 并抛 `METADATA_PROFILE_EXPIRED`。
  - 版本：连续两次探查产生 `version=n`、`n+1`；内容相同则 `sha256` 相同。
  - 缓存：`KEY_META_CACHE` 命中不回源；过期后缓存失效。
  - 审计：`METADATA_PROBED` 落账本且 payload 无样本值。
- **必须覆盖的反例**：源端被修改（DDL 被拒）；日志中出现样本原文（全日志扫描）；越权/跨租户读其他项目的 Profile；探查失败行被静默删除。
- **测试基建**：纯函数与 ORM 约束在内存 SQLite 跑；真实库探查标 `integration` 在 ECS `--profile demo` 下跑。

## 10. 未决与风险

| 事项 | 现状 | 建议 / 验证方式 |
|---|---|---|
| 脱敏盐来源 | `apply_masking` 需 `salt`，但 `Settings` 无对应项，Vault 也无约定键 | **建议**在 Vault 存 `metadata_mask_salt`（每租户一份）并加入 `Settings` 引用；或退化为 `SECRET_KEY` 派生盐（安全性较低），需拍板 |
| Profile 过期时长未冻结 | `expires_at` 由探查写入，TTL 未定 | 建议 `METADATA_PROFILE_TTL_DAYS=7`，加入 `Settings` 并在 PRD §12 口径内确认 |
| `METADATA_PROFILE_EXPIRED` 无异常子类 | 码已存在，无 `AppError` 子类 | **建议新增** `MetadataProfileExpiredError(AppError)`（`http_status=409`） |
| 探查失败无专用错误码 | 失败靠 `DATASOURCE_*` 表达；白名单违规用 `INTERNAL_ERROR` | **建议新增** `METADATA_PROBE_FAILED`（用于「已连上但探查中途失败」） |
| 缺 `metadata.probed` 之外的审计事件 | `EvidenceEventType` 仅 `METADATA_PROBED` | 失败探查复用同一事件并带 `result=failed`，暂不新增枚举值 |
| 并发探查同源 | 仅靠 `UK(data_source_id, version)` 与 `max+1`，高并发会撞号 | 建议引入 `gen:lock:{data_source_id}` 类 Redis 锁或 PG advisory lock；M1 先串行化（前端防重复提交） |
| `expired` 置位时机 | 采用读取时惰性置位 | 是否另设定时任务批量置位待定；惰性方案已能阻断生成 |
| 每语句/整轮超时默认 | 未定义 | 建议 `DATASOURCE_PROBE_STATEMENT_TIMEOUT_SEC=10`、`PROBE_TOTAL_TIMEOUT_SEC=120` |
| 表/列注释可能含敏感信息 | 注释原样进入 `schema_snapshot` | 建议对注释同样过 `contains_plaintext_sensitive`；M1 先记录风险，M2 前补做 |
| Doris 键模型解析 | 依赖 `SHOW CREATE TABLE` 文本解析，格式随版本变动 | M3 实机验证 Doris 2.1 输出格式；不稳定则退化为仅列信息 |
| 文件源规模上限 | 靠字节/行数截断读取 | 大 CSV 是否走 MinIO Select 或分块读取待定 |
