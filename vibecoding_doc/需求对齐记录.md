## 一、交付与环境（2026-10-14 冻结）

| 项 | 决策 | 理由 |
|---|---|---|
| 「生产级」的含义 | **质量标杆，非真实业务流量**。按生产标准建（多租户隔离、审计、备份、监控告警、CI/CD、密钥不落盘），数据源与用户为自建仿真环境 | 若真有业务方，PRD §13.2 的验收线会写成「接入我们生产库那套」，而它写的是「至少一种数据库 + 一种文件或 API 源」 |
| 运行环境 | 阿里云 ECS `60.205.138.167`（root，华北2） | 项目负责人自有机器 |
| 部署形态 | **单机 Docker Compose** + 阿里云 ACR 镜像仓库 + 云效流水线。不使用 ACK/K8s/SAE | 组件多（9+），K8s 运维成本会挤占 50% 工期；「生产级」的实质是可运维、可审计、可回滚、有监控有备份，compose 配 healthcheck/restart policy/资源 limit/日志轮转/定时备份即可 |

| 分工 | Claude 全权写代码；项目负责人拍板 + 验收，每周至少一次验收反馈 | — |
| 里程碑节奏 | M1 环境与骨架 → M2 生成链路 → M3 治理链路 → M4 生产化与 Benchmark，每个里程碑必须**可演示** | 避免堆一堆没接线的模块 |

## 二、PRD §15 待确认事项（2026-10-14 全部采纳推荐值）

| # | 事项 | 冻结值 | 关键约束 |
|---|---|---|---|
| 1 | 数据源连接器优先级 | 真做 **MySQL（源）+ Doris（目标）+ MinIO/CSV（文件源）**；PostgreSQL 因控制面自身需要而顺带实现；Oracle / ClickHouse / Excel / Parquet / REST 仅注册连接器接口与表单，不真连 | 依据 PRD §13.2「至少完成一种异构数据库和一种文件或 API 数据源接入」 |
| 2 | 模型 Provider 与预算 | 只真接 **DeepSeek**（`deepseek-chat` 生成，`deepseek-reasoner` 用于根因诊断）；Provider 抽象层保留多实现接口；单次生成 prompt 预算 ≈ 8K token（元数据 Profile 只投喂相关表 + 统计，绝不投喂原始样本）；Benchmark 采用**缓存回放** | PRD §6.3.2「业务层不得依赖具体模型实现」 |
| 3 | SecretProvider / Vault | **真上 Vault 单机容器**（KV v2 + AppRole），轮转周期 90 天 | PRD §2.2 第 6 条点名 SecretProvider / Vault KV v2；它是「全链路无明文」验收的直接证据 |
| 4 | 原子 Swap 实现 | 抽象 `TargetPublisher` 接口：**Doris** 走 `ALTER TABLE <shadow> REPLACE WITH TABLE <formal> PROPERTIES("swap"="true")`；**MySQL** 走 `RENAME TABLE` 双表交换。演示走 Doris | PRD §6.5.4「发布失败不得留下半发布状态」 |
| 5 | P0–P3 判定矩阵与阈值 | 见下方「三、风险判定矩阵」，**必须是纯规则引擎** | PRD §1.4 要求 P0/P1 拦截率 100%，LLM 参与即不可保证 |
| 6 | Benchmark 范围与基线 | **L0** ≈30 条静态注入用例（含「把身份证号明文导出到公网」类恶意需求）；**L1** 假 SeaTunnel 执行器注入故障（格式错乱、超预算、超时）；**L2** 一条 MySQL→Doris 真链路。数据集版本化，基线首次跑完写死 | PRD §6.6 |
| 7 | 指标刷新、告警渠道、保留周期 | 运行中心前端 **2s 轮询**（不引 WebSocket）；**Prometheus + Grafana**；告警走**钉钉机器人 webhook**；ExecutionRun 与运行日志保留 **90 天**，质量报告与证据账本永久 | 降低复杂度换取可维护性 |
| 8 | 证据账本存储与导出 | PostgreSQL 表 + 链式哈希，**每 100 条事件打一次 Ed25519 签名检查点**；永久保留；导出 JSON + CSV，并附**独立验链脚本** | PRD §10.1「哈希链和签名检查点」 |

## 三、技术栈与架构决策（2026-10-14 冻结）

| 决策点 | 冻结值 | 理由 |
|---|---|---|
| 后端分层 | 沿用 `rag_manager_agent`：FastAPI + SQLAlchemy(async) + Alembic + `uv`，目录 `api / services / engines / clients / models / schemas / tasks / core / harness` | 既有分层铁律已验证 |
| 控制面库 | **PostgreSQL 16** | PRD §16 交付物明列 |
| LangGraph Checkpoint | **PostgreSQL**（`langgraph-checkpoint-postgres`） | Workflow State 需跨请求恢复，且要与 Preparation/审批处于同一事务边界；Redis 重启会丢状态 |
| Redis 职责 | 仅 Celery broker/result、缓存、登录失败计数、**Capability 消费标记** | 职责单一 |
| Outbox 投递 | Celery **beat 每 2s 扫描** outbox 表 + `FOR UPDATE SKIP LOCKED` | 不用 `LISTEN/NOTIFY`（连接管理复杂、难测）；SKIP LOCKED 天然抗并发重复投递 |
| Capability 令牌 | **Ed25519(EdDSA) 签名的 JWT + `jti`**；消费标记 **Redis `SETNX` + PG 唯一约束双保险** | PRD §1.4 要求「未授权/重复执行成功率 = 0」，单一存储都有竞态窗口 |
| 服务进程 | `api` / `worker` / `beat` 三进程共用一份代码与 Dockerfile | 沿用既有习惯 |
| SeaTunnel | 官方 `apache/seatunnel` 镜像跑 **Zeta local 模式** | 省去在 ECS 装 JDK 与解压发行包，避免 Windows 原生运行的坑 |
| 前端 | Vue 3 + TypeScript(strict) + Vite + Pinia + **Element Plus** + ECharts + axios；DAG 拓扑用 **Vue Flow**；HOCON 高亮用 **CodeMirror 6** | Element Plus 为既有熟练栈；Vue Flow 比 X6 轻且 TS 友好；Monaco 体积过大 |
| 文档体系 | `vibecoding_doc/` 下 PRD.md → 概要设计总纲.md → 核心数据字典.md → `模块概要设计/be-xx·fe-xx` → `specs/`，仓库根 `CLAUDE.md` | 沿用既有 spec 驱动流程 |
| 测试 | pytest + pytest-asyncio + httpx AsyncClient，跑 compose 内**真实** PG/Redis | 协议类需求（重放、自批、指纹失效）用 mock 测不出来 |

## 四、风险判定矩阵（P0–P3，已冻结）

判定入口：`engines/policy/pdp.py`。**纯函数 + 规则表，无 LLM、无网络调用。**

| 等级 | 触发条件（任一命中） | 系统行为 |
|---|---|---|
| **P0** | 目标为生产环境且写正式表；敏感字段（身份证/手机号/邮箱/地址/Token）以明文出域；需求意图包含绕过审批、关闭审计、导出明文敏感数据；跨租户资源访问 | **直接阻断**，不进入审批也不进入执行；写入证据账本 |
| **P1** | 资源范围超出项目授权（跨库/跨 schema）；执行预算超默认阈值 3 倍；无回滚方案；引用未登记的 Secret；目标环境标记为生产但仅写影子表 | 允许进入审批，但**强制双职责审批**且提示强化项 |
| **P2** | 非生产环境；资源范围在授权内；预算在默认区间；有回滚方案 | 常规双职责审批（数据 + 安全） |
| **P3** | 纯只读探查（元数据探查、连通性测试） | 免审批，仅记审计事件 |

默认预算阈值（可被项目级配置覆盖）：最大读取行数 `1e8`、最大写入字节 `50 GiB`、最大执行时长 `7200 s`、输出放大比 `1.5`、错误拒绝率 `5%`（演示场景「脏数据超限」用例另设 `20%`）。
