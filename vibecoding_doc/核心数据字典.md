# 核心数据字典

> 覆盖 PRD §9.1 全部 26 个实体 + 支撑表。所有表默认含 `id BIGSERIAL PK`、`created_at`、`updated_at`（🔒 标记的不可变表**无** `updated_at`，且禁止 UPDATE）。
> 命名：表名小写下划线单数；枚举一律 `varchar` + CHECK 约束（不用 PG enum 类型，便于加值不改类型）。

## 0. 通用约定

- 多租户：所有业务表带 `tenant_id`，二级带 `project_id`；查询强制过滤。
- 软删除：仅 `data_source` / `pipeline` / `project_member` 用 `status` 字段，其余物理删除无意义（不可变表只增）。
- 时间：`timestamptz`；金额/字节用 `bigint`；比率用 `numeric(6,4)`。
- JSON 一律 `jsonb`，并在 `schemas/` 层用 Pydantic 强校验（不裸存）。

## 9. 关系速查

```
tenant 1─n project 1─n project_member n─1 app_user
                        └─n role_assignment (maker / checker_data / checker_security / operator / auditor)
project 1─n data_source n─1 secret_reference
               └─n metadata_profile（版本递增，sha256 绑定生成）
project 1─n pipeline 1─n pipeline_version（🔒 不可变）
                              ├─1 etl_plan 🔒
                              ├─1 hocon_artifact 🔒
                              ├─1 quality_contract 🔒
                              ├─1 runtime_supervision_contract 🔒
                              └─n preparation 🔒
                                     ├─n approval_decision 🔒（按 slot 唯一）
                                     └─n capability 🔒
                                            └─1 execution_run 1─n execution_metric
                                                              ├─1 quality_report 🔒
                                                              └─n error_record 🔒
所有关键动作 ──▶ evidence_event 🔒 ──每100条──▶ evidence_ledger_block 🔒
副作用命令 ──▶ outbox_message ──beat扫描──▶ celery worker
```

## 10. 待确认（跨模块缺口 · 全局编号）

> 本节的编号是**全仓库共用**的一套：各模块 spec 的「待确认」遇到**跨模块**缺口（表/列/枚举/契约不全）
> 时，在这里追加，编号只增不改。spec 自己的待确认可以带前提（「等 X 定了再 Y」），本清单**只收跨模块项**。
> 编号沿用既有 spec：M2-01 用 1–6、M2-02 用 7–13、M2-03 用 14–21、M2-04 用 8–16、M2-05 用 17–**27**、
> M2-06 用 7–20（跨 spec 已出现重号），故**新增自 28 起**。

| # | 缺口 | 建议 | 提出于 |
|---|---|---|---|
| **28** | `metadata_profile.expires_at` 探查侧从不写入 → 档案 TTL 闸惰性（准备单/Commit 判过期的比较恒不触发） | 探查成功时写 `now + PROFILE_TTL`（新增 Settings 项） | M3-01 §12 |
| **29** | `assert_committable` 不重跑 PDP；`input_fingerprint` 不含 `policy_version` → 策略升级不足以拦下 Commit | 在 `assert_committable` 内重跑 `decide_for_project` 并比对 level | M3-01 §12 |
