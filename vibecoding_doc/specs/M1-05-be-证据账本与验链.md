## 1. 模块定位

### 1.1 做什么

1. **链式哈希**：每条事件的 `event_hash` 覆盖其全部语义字段 + 前一条的 `event_hash`。
2. **单入口 append**：唯一写路径 `EvidenceLedger.append()`，自动算 `prev_hash` / 序号。
3. **检查点**：每 `LEDGER_CHECKPOINT_INTERVAL` 条打一个 Ed25519 签名块。
4. **验链**：从零重算（`verify_chain`），支持区间；断链给出类型 + 位置 + 散文说明。
5. **独立验链脚本**：`scripts/verify_ledger.py`，**不 import 本模块**。
6. **查询 / 验链 / 导出接口**：auditor 只读。

### 1.2 明确不做

- **不提供任何改/删接口**。append-only 是架构约束，不是「还没做」。
- **不提供「解密 payload」**。payload 在写入前已被脱敏（`_assert_payload_clean`）。
- **不实现检查点验签**（M4）。本模块只签发、只重算哈希链。
- **不做账本分区/归档**（be-06 §10 已登记为当前不做）。

## 3. 接口契约（前缀 `/api/v1`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/governance/evidence` | **auditor** | 游标分页 + 过滤；`project_id` 必填 |
| POST | `/governance/evidence/verify` | **auditor** | `{project_id, from_seq?, to_seq?}` |
| GET | `/governance/evidence/export` | **auditor** | `?format=json|csv`；返回文件流（**不套信封**） |

### 3.1 🔴 与 be-06 §3.1 的漂移（以 `frontend/src/api/governance.ts` 为准）

| 项 | be-06 §3.1 | 采纳 | 理由 |
|---|---|---|---|
| 查询路径 | `GET /governance/ledger` | `GET /governance/evidence` | 前端已定型；账本对用户的名字就是「证据」 |
| 分页 | `page` / `page_size` | **`cursor` + `limit`** | **这条比路径更重要**：账本持续 append，offset 分页会漏读或重读——翻页时新事件插进来，第二页会重复第一页的尾巴。游标基于 `seq` 才稳定 |
| 验链 | `GET .../verify` | `POST /evidence/verify` | 验链要重算全链，是有代价的动作，不该能被 GET 缓存或预取 |
| 导出 | `GET /governance/ledger/export` | `GET /governance/evidence/export` | 前端没有这个入口，**保留 be-06 的设计**（§6.5 定了格式）——审计要能拿走一份离线可验的副本 |
| 过滤参数名 | `occurred_from` / `occurred_to` | `from` / `to` | 前端 `EvidenceFilter.from/to` 已定型 |
| `event_type` | 数组 | **逗号分隔字符串** | 前端 `filter.event_type?.join(',')`；未知取值 → 422（静默丢掉一个筛选项会让用户看到一份「看起来完整」的结果） |

### 3.2 游标是不透明串

`encode_cursor(seq) = f"ev:{seq}"`，`decode_cursor` 拒绝一切不符合该形态的输入。
让客户端能构造游标（比如直接传整数）就意味着「从任意位置开始翻」会被当成合法输入，
而它跳过的那些事件不会有人注意到。

## 4. 核心逻辑

### 4.1 `event_hash` 的覆盖范围

```
event_hash = sha256("|".join([
    seq, tenant_id, project_id|0, actor_id|0,
    event_type, subject_type, escape(subject_id),
    artifact_hash, escape(canonical_json(payload)),
    prev_hash, occurred_at_utc_iso(occurred_at),
]))
```

🔴 **`tenant_id` / `project_id` 必须参与**——原式把它们留在覆盖之外，
后果是「把一条事件改挂到别的租户名下，验链照样通过」。多租户账本的核心价值
恰恰是「谁在哪个租户做了什么」，而它的归属却不可验证。

调用方必须保证的前提：`payload` 内**不得出现 float 与 datetime**，
比率用字符串（`"0.0500"`）。`canonical_json` 的 `default=str` 会把 datetime
变成平台相关格式，从而让同一语义在两台机器上算出不同哈希。

`escape()` 转义分隔符 `|`（并**先**转义反斜杠）：不转义时
`("a|b","c")` 与 `("a","b|c")` 会拼出同一串。

`occurred_at_utc_iso` 固定 6 位微秒：微秒为 0 时 `isoformat()` 会省略小数部分，
于是同一条事件有两种写法、两个哈希。

### 4.2 append

1. `_assert_payload_clean()`：命中敏感键名/值形态 → `SensitivePayloadError`（**500，不写**）。
2. `_lock_tail_and_next_seq()`：`SELECT ... ORDER BY seq DESC LIMIT 1 FOR UPDATE`，
   取 `seq+1` 与新 `prev_hash`；期间串行化失败由调用方按 `is_retryable` 重试。
3. 校验 `occurred_at` 带时区（裸 datetime 会按本地时区解释，容器 UTC 与开发机 UTC+8 哈希不同）。
4. `compute_event_hash()` → INSERT → **返回已 flush 未 commit 的对象**，事务边界归调用方。
5. 若 `seq % checkpoint_interval == 0` 且有签名器 → `sign_checkpoint()`。

**「返回未 commit」是刻意的**：这样「业务事实 + 证据 + 消费标记」能在同一个事务里落地，
而不是「业务提交了、证据写失败了」。

### 4.3 验链

`verify_chain` **从零重算**，不比对存储值。只比对存储的 `event_hash` 等于相信
被检验对象自证清白——改 payload 同时改 `event_hash` 会被判为合法。

三种断链与对应 `broken_kind`（取值与前端 `LedgerBreakReason` 逐字一致）：

| 检测 | `broken_kind` | `broken_reason`（散文） |
|---|---|---|
| `seq` 不连续 | `missing_event` | 期望 X，实到 Y（有事件被删除） |
| `prev_hash` 与前条 `event_hash` 不符 | `prev_hash_mismatch` | seq=N 之前被改动或插入 |
| `event_hash` 重算不符 | `hash_mismatch` | seq=N 的内容被改动（含租户或项目归属） |
| （M4）检查点签名不符 | `signature_invalid` | — **暂无产生路径** |

**`from_seq > 1` 时不校验首条的 `prev_hash`**：那一段本就缺了头，
拿它去对 `ZERO_HASH` 必然失败，于是「只想复核最近一千条」会变成一个
永远返回断链的功能——而一个总是报警的告警等于没有告警。
报告的 `ok` 此时只代表**这一段**自洽，前端必须把 `started_from_block_seq`
一起展示（非 `null` = 部分验证）。

`checked_blocks` 只统计**完全落在已验区间内**的检查点：
只要 `from_event_seq` 就够的话，一个覆盖 1..1000 的块在「只验了 3 条」时也会被算进来，
于是报告显示「验了 3 条事件、覆盖 1 个检查点」，而那个检查点里的 997 条谁都没看过。

### 4.4 断链不是 HTTP 错误

`verify_ledger` 发现断链时返回 **200 + `ok=false`**（be-06 §7 第 9 行）：
「查到了断链」是一次成功的查询，前端要拿结果渲染断点位置，
500 会把它变成一句「服务器错误」。同时**断链本身入账**（`POLICY_BLOCKED`，
`subject_type="ledger"`）——它是需要人工介入的安全事件。

### 4.5 拒绝读账本这件事本身要入账（be-06 §7 第 6 行）

非 auditor 查询 → `RoleRequiredError` + 追加 `LEDGER_ACCESS_DENIED`。
审计日志被越权查询，正是审计员最需要看到的事件；只回 403 而没留痕，
事后查不出「谁试过翻账本」。写账本失败只记 structlog 并**回滚**——
不能让一个失败的 append 把会话留在坏事务里，也不能把 403 变成 500。

`can_read_ledger` **刻意不放开给 maker / operator**：账本记录的是「谁在什么时候批了什么」，
而他们正是被记录的对象。只读不算越权，但查询接口能按 `event_type` / `subject_id` 检索，
放开就等于给了一个「翻查同事操作记录」的入口。

### 4.6 导出自带验链报告

- JSON：`{"events": [...], "report": {...}, "exported_at", "filter", "exported_by"}`；
- CSV：固定列序（见下）、`payload_json` 单行 JSON、**UTF-8 带 BOM**（否则 Windows Excel
  按 GBK 读，中文列全乱码）、CRLF 行尾；
- 两种格式都**先验链再把报告写进去**：一份无法自证完整的副本，
  在审计桌上和被删了几行的打印件没有区别。
- 流式产出（JSON 分块、CSV 逐行），服务端不在内存里攒整份文件。

CSV 列序（**写死而非反射**：反射出来的列序会随模型改动而变，而拿旧文件对账时列序必须可预期）：

```
seq,occurred_at,event_type,tenant_id,project_id,actor_id,subject_type,
subject_id,artifact_hash,prev_hash,event_hash,payload_json
```

`export_evidence(..., max_events=)` 与 `EvidenceFilter.limit` 是**两个语义**：
后者是查询分页大小，前者是本次导出最多带走多少条。API 的 `limit` 映射到 `max_events`。

### 4.7 独立验证器

`scripts/verify_ledger.py` **刻意不 import `harness.ledger`**：
用被审计对象的代码去验证被审计对象，等于让它自证清白。
它自己实现 `_FIELD_ORDER`（11 个字段，显式契约）、`escape`、`canonical_json`、
`event_hash`，用 `psycopg` 裸读（不经 ORM），退出码 0/1/2。
输出**只用 ASCII**（`OK checked=N ...` / `BROKEN ... at_seq=N ...`），
因为 Windows 控制台是 GBK。

### 4.8 安全红线落地

| 红线 | 本模块怎么做 |
|---|---|
| 证据账本单入口 | `append()` 是唯一写路径，`prev_hash` / `event_hash` 由它算，调用方无从提供 |
| 不可变制品 | `EvidenceEvent` / `EvidenceLedgerBlock` 都是 `__immutable__`；ORM 事件监听器拦截 UPDATE |
| 无明文 Secret | `_assert_payload_clean` 在写入前拦下敏感键名与值形态；命中时**不写**账本，只记 structlog（含键路径，**不含值**） |
| 租户隔离 | 查询一律带 `tenant_id`；`event_hash` 覆盖 `tenant_id`，篡改归属即断链 |
| 四眼强制 | 拒绝读账本的尝试入账，供审计复核 |

## 5. 错误码

| 触发 | 码 | HTTP | 写账本 |
|---|---|---|---|
| payload 命中敏感规则 | `INTERNAL_ERROR` | 500 | **否**（要写的正是它；只记 structlog） |
| payload 含不可序列化对象 | `VALIDATION_ERROR` | 422 | 否 |
| 链尾锁等待超时 / 重试 5 次仍失败 | `CONFLICT` | 409 | 否 |
| `event_type` 不在枚举内 | `VALIDATION_ERROR` | 422 | 否 |
| 查询者非 auditor | `ROLE_REQUIRED` | 403 | **是**（`LEDGER_ACCESS_DENIED`） |
| `tenant_id` 与上下文不符 | `TENANT_MISMATCH` | 403 | 是 |
| 导出 `format` 非 json/csv | `VALIDATION_ERROR` | 422 | 否 |
| 游标形态非法 | `VALIDATION_ERROR` | 422 | 否 |
| 验链发现断链 | **不报错**：200 + `ok=false` | 200 | 是（`POLICY_BLOCKED`） |

## 6. 异步任务

本模块**无** Celery 任务。`append` 在关键路径上（Commit、每次 ToolBroker 拒绝、
每次状态流转），签名是微秒级、每 100 条一次，不是瓶颈。
**不再加索引**：每个额外索引都会线性放大 INSERT 成本，而账本写多读少。

## 8. 验收标准（对应 CLAUDE.md §10）

1. **验链脚本能从零独立验证全链**：`scripts/verify_ledger.py --dsn ...` 退出码 0。
2. **篡改必被发现**：改 payload 不改哈希 → `hash_mismatch`；删中间一条 → `missing_event`；
   改 `actor_id` → `hash_mismatch`（归属在哈希覆盖内）。
3. **黄金哈希稳定**：`_GOLDEN`（20 项输入的固定输出）不变。
   **改这个字面量之前先回答：历史账本怎么办？**
4. **拒绝读账本入账**：maker 查询后账本多一条 `ledger.access_denied`。
5. **游标分页不漏不重**：5 条数据 limit=2 逐页取，并集等于全集且顺序一致。
6. **导出 JSON 的 report.ok 为真且 `checked_events` 等于实际条数**；CSV 带 BOM、12 列、
   `payload_json` 可解析回原对象。
7. **区间验链不误报**：`from_seq>1` 时 `ok=true` 且 `started_from_block_seq != null`。
8. 反例：非 auditor 查询/验链/导出、跨租户事件不可见、非法游标、空结果页游标为 `null`。
