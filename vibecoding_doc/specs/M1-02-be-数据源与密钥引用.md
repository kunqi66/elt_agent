## 1. 模块定位

### 1.1 做什么

1. 数据源的登记、改名、停用/启用、删除（引用计数兜底）。
2. 凭据写入 Vault，库里只留 `SecretReference`（provider + path + version + key_names）。
3. 连通性测试：异步（202 + 轮询），读只读、不写远程。
4. 按连接器类型校验 `endpoint` 形状（`ConnectorSpec` 注册表）。
5. 数据源审计事件写入账本。

### 1.2 明确不做

- **不做元数据探查**（be-04）。本模块只测「连得上吗」。M1 早期版本把探查塞在连通性里，
  已拆出——见 §5.4，那是一次真实的功能泄漏。
- **不签发 Capability**（be-05）。连通性是 P3 免签工具。
- **不管凭据轮转**（M4）。`last_rotated_at` 只记录，不驱动。
- **不校验远端 schema**。目标库是否存在、表结构对不对，在执行阶段由 SeaTunnel 报错。

## 3. 涉及的表

| 表 | 动作 | 关键约束（字典 §2） |
|---|---|---|
| `data_source` | 读写 | `UK(project_id, name)`、`Index(project_id, type)`、`status` active/disabled |

### 3.1 🔴 Vault 路径：`elt/{tenant_id}/{project_id}/{name}`

be-03 正文与 §9 对路径写法的描述不一致（一处给模板、一处给示例）。
`clients/vault.py:56-62` 的 `build_path()` 是**唯一实现**，取
`elt/{tenant}/{project}/{name}`：租户在最外层，使「删租户清凭据」是一次前缀删除；
`name` 而非 `data_source_id`，因为 id 是自增的、跨环境不同（同一个逻辑数据源在
dev/staging 上 id 不同，而 Vault 路径应当稳定）。**同一语义只此一份**，别处不得再拼字符串。

### 3.2 字典与代码的一致点（勿改）

`data_source.type` 取值含 `oracle` / `clickhouse` / `excel` / `rest`——这四种
**只登记、不真连**（无 driver，连通性测试直接返回「连接器未实现」）。
这是刻意的：让用户能先把拓扑登记完整，而不是等到 M4 才有地方放。

## 4. API 契约（前缀 `/api/v1`）

| 方法 | 路径 | 权限 | 幂等 | 说明 |
|---|---|---|---|---|
| GET | `/datasources` | 任一项目角色 | 天然 | 过滤 `type`/`env`/`sensitive_level`/`status`/`q`；**逗号分隔多值** |
| GET | `/datasources/{id}` | 同上 | 天然 | 含 `secret_ref` 视图（仅键名）与最新探查摘要 |
| POST | `/datasources` | maker / operator / checker_security | **是** | `{name, type, env, sensitive_level, endpoint, tags, credentials}` |
| PUT | `/datasources/{id}` | 同上 | 否 | `endpoint`/`tags`/`env`/`sensitive_level`；**不含 `credentials`** |
| POST | `/datasources/{id}/disable` | 同上 | **是** | 停用；探查与执行前会拒 |
| POST | `/datasources/{id}/enable` | 同上 | **是** | 启用 |
| DELETE | `/datasources/{id}` | 同上 | **是** | 有引用（探查档案/流水线）时 409 |
| POST | `/datasources/{id}/credentials` | 同上 | **是** | 重设凭据；写 Vault 新版本，旧版本保留 |
| POST | `/datasources/{id}/connectivity-tests` | 同上 | **是** | **202** + `{test_id, status}` |
| GET | `/datasources/{id}/connectivity-tests/{test_id}` | 同上 | 天然 | 轮询结果 |
| POST | `/datasources/{id}/probes` | 同上 | **是** | **202**，见 be-04 |
| GET | `/datasources/{id}/profiles` | 同上 | 天然 | 探查档案列表（be-04） |
| GET | `/datasources/{id}/profiles/{version}` | 同上 | 天然 | 单个档案（be-04） |
| GET | `/datasources/{id}/profiles/{version}/schema` | 同上 | 天然 | 可选 `?table=`（be-04） |
| GET | `/datasources/{id}/profiles/{version}/samples` | 同上 | 天然 | 脱敏样本，可选 `?table=&limit=`（be-04） |

### 4.0 🔴 与 be-03 §3.1 的漂移（本次以 `frontend/src/api/datasource.ts` 为准）

| 项 | be-03 原设计 | 采纳（前端） | 采纳理由 |
|---|---|---|---|
| 修改 | `PATCH` | `PUT`，**不含 `credentials`** | 换凭据是独立动作，要有自己的审计与幂等键；混在同一个 PUT 里，一次改名会顺手把凭据也覆盖成 `null` |
| 停用 | `PATCH {status}` | `POST .../disable` + `.../enable` | 状态机两条边语义不同（停用要检查在跑的作业），合成一个幂等写接口会丢掉这层判断 |
| 删除 | `DELETE` 直接删 | 同上，但有**引用计数** | 数据源被流水线引用时删除，会让冻结版本指向一个不存在的源 |
| 凭据字段名 | `secret` | `credentials` | 前端 `DataSourceCreate.credentials` 已定型。**后端字段名也统一叫 `credentials`**，`secret_ref` 只用于**响应**里的引用视图 |
| 连通性 | 同步返回结果 | **202 + `test_id` 轮询** | 直连远端可能耗时数秒到数十秒（DNS、握手、超时），同步会占住一个 API worker |

### 4.1 Python 跨模块契约


## 5. 核心逻辑

### 5.1 凭据写入（唯一允许接触明文 Secret 的路径）

1. `require_project_roles(manage=True)`。
2. 校验 `credentials` 形态：`engines/security/credentials.py` 的纯函数判定
   （必须是非空字符串映射、键名合法、无控制字符、值长度上限）。
3. `build_path(...)` → `vault.write_secret(path=..., values=credentials)`。
4. `INSERT`/`UPDATE secret_reference`（`key_names=sorted(keys)`、`last_rotated_at=now`）。
5. 账本 `SECRET_MATERIALIZED`，payload **只含 path 与 key_names**，绝不含值。
6. 响应只回 `SecretRefView{provider, path, version, key_names, last_rotated_at}`。

### 5.2 连通性测试

1. `require_project_roles`，数据源必须 `active`。
2. 生成 `test_id`（不可枚举），落 Redis `{status: "pending"}`（TTL 300s）。
3. `run_connectivity_test.apply_async(..., queue="etl.default")`。
4. worker：经 `ToolBroker.execute(ToolName.DATASOURCE_CONNECTIVITY_TEST, caller="worker")`
   → `clients/datasource_probe.py` 执行；结果写 Redis，账本追加 `DATASOURCE_CONNECTIVITY_TESTED`。
5. 前端轮询 `GET .../connectivity-tests/{test_id}`；Redis 键过期 → 返回 `expired` 而非 404
   （404 会让前端以为「这个测试从没存在过」，而它其实跑完了，只是结果被 TTL 收了）。

### 5.3 删除与引用计数

`_reference_count` 数 `metadata_profile` 中该数据源的档案数。> 0 → `ConflictError`。
**M1 只数探查档案**：流水线版本还不存在（M2 才有），所以「被流水线引用」这一层
暂时无从检查——记在 §10-3，M2 落地时必须补上，否则删除一个被版本引用的数据源
会让冻结版本指向空。

### 5.4 🔴 本次修正：探查从连通性里拆出去

**原缺陷**：`run_probe` 一度同时做两件事——测连通性 + 顺手探一遍元数据（`scope`/`tables`/
`sample_rows`/`masking_policy` 全是它的参数）。后果有两层：

1. **一次只读的连通性检查会真的去读远端库并落样本**。用户在「测试连接」按钮上
   预期的是握手，不是全库抽样。
2. **前端的 `scope` 无处可传**：`POST /connectivity-tests` 的入参里没有 `scope`，
   于是「只探 schema」这个选项在后端无对应路径，M1 只能写死。

**修正**：探查独立成 `POST /datasources/{id}/probes`（be-04），`run_probe` 只保留
连通性字段。`tasks/datasource.py` 的 payload 同步去掉 `tables`。

### 5.5 安全红线落地

| 红线 | 本模块怎么做 |
|---|---|
| 无明文 Secret | 明文只存在于 ① 请求体 ② `vault.write_secret()` 的入参 ③ worker 内存中物化后的驱动连接串。**不落库、不进日志、不进账本、不进任何响应**。`DataSourceRead` 里没有承载值的字段——这是结构性保证 |
| 副作用唯一出口 | 连通性测试经 `ToolBroker.execute()`；`api/` 与 `services/` 不 import 任何数据库驱动 |
| 脱敏默认开启 | 连接串只以 `endpoint.host/port/database` 形式回显；`credentials` 只回键名 |
| 证据账本单入口 | `SECRET_MATERIALIZED` / `DATASOURCE_CREATED` / `DATASOURCE_CONNECTIVITY_TESTED` 三类，全部经 `append()` |
| 租户隔离 | 所有查询带 `tenant_id`（经 `ProjectScopedMixin` 与显式 where 两处） |

## 6. 错误码

| 触发 | 码 | HTTP |
|---|---|---|
| 非项目成员 / 无管理权 | `ROLE_REQUIRED` | 403 |
| 跨租户 | `TENANT_MISMATCH` | 403 |
| `endpoint` 与 `type` 不符 | `VALIDATION_ERROR` | 422 |
| `credentials` 形态非法 | `VALIDATION_ERROR` | 422 |
| 同名数据源 | `CONFLICT` | 409 |
| 有引用时删除 | `CONFLICT` | 409 |
| 连接器未实现（oracle/clickhouse/excel/rest） | `VALIDATION_ERROR` | 422 |
| 连通性失败 | 不作为 HTTP 错误 | 202 后由轮询结果承载 |

连通性失败**不抛异常**：它是被测对象的属性，不是本次请求的错误。
把「连不上」变成 500 会让监控把「用户配错了密码」记成「服务故障」。

## 8. 验收标准

1. 建数据源后：Vault 有值、`secret_reference` 有行、**响应与日志里 grep 不到明文口令**。
2. `PUT` 改名不影响 `secret_reference.version`；`POST /credentials` 才使 version +1。
3. 连通性测试 202 → 轮询得 `succeeded` / `failed`；Redis 键过期后返回 `expired`。
4. 停用后：探查与执行均被拒（be-04 的 `start_probe` 与 executor 两道）。
5. 删除有档案的数据源 → 409；无档案 → 204。
6. 跨租户访问 → 404/403（不得泄漏「这个 id 存在」）。
7. 反例：`endpoint` 缺 `host`、`credentials` 为空、`type=oracle` 时真连 → 均 422。
