# 概要设计总纲

> 上游：[PRD.md](PRD.md) ｜ 同层：[核心数据字典.md](核心数据字典.md) ｜ 决策依据：[需求对齐记录.md](需求对齐记录.md)
> 本文只写**结构、边界与协议**；模块内部细节见 `模块概要设计/be-xx-*.md`、`fe-xx-*.md`。

## 1. 系统边界

```
                    ┌──────────────────── 控制面（本系统，只传指令与指标） ────────────────────┐
 浏览器(Vue3) ──HTTP──▶ Nginx ──▶ FastAPI(api) ──▶ PostgreSQL(控制面) / Redis
                                      │  ▲                    ▲
                                      │  │                    │
                          ┌───────────┘  └────────┐           │
                          ▼                       ▼           │
                   LangGraph 编排            Harness 内核      │
                 (Checkpoint 落 PG)    (PDP/Capability/Broker/ │
                          │             ReplayGuard/Outbox/    │
                          │             EvidenceLedger)        │
                          └──────────┬────────────┘            │
                                     ▼                          │
                              Outbox 表 ──beat 扫描──▶ Celery worker ──┘
                                                          │
                    ┌─────────────────────────────────────┘
                    ▼
            ┌──────────────────── 数据面（SeaTunnel Zeta，搬数据） ────────────────────┐
            │  source(MySQL/文件) ──▶ transform ──▶ sink(影子表)   +   sink(错误表)      │
            └──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
                        质量校验通过 ──▶ 原子 Swap ──▶ 正式表
```

**铁律**：控制面**不搬运业务数据**。控制面只写指令（SeaTunnel 配置 + Secret 引用 + 预算）、只读指标（行数/字节/时长/拒绝率）。海量数据一行都不经过 FastAPI 进程。

## 2. 进程与模块拓扑

| 进程 | 职责 | 关键模块 |
|---|---|---|
| `api` | HTTP 控制面；启动 LangGraph、写 Preparation、审批、Commit | `api/` `services/` `workflow/` `harness/`（签发侧） |
| `worker` | 消费 Outbox 命令；验签 Capability；物化 Secret；提交/停止 SeaTunnel 作业；采集指标；执行 Swap 与回滚 | `tasks/` `harness/`（消费侧） `clients/seatunnel` `clients/doris` |
| `beat` | 每 2s 扫描 Outbox 投递；每 30s 采集运行指标；每日备份与账本检查点 | `tasks/periodic.py` |
| `frontend` | 控制台（Nginx 托管静态资源并反代 `/api`） | `frontend/` |

后端分层：`api/`（只做校验/注入/权限/转发）→ `services/`（编排）→ `engines/`（纯算法）/`clients/`（外部系统）/`models/`（ORM）。`harness/` 与 `engines/` 均不依赖上层，`harness/` 是所有副作用的唯一出口。

## 3. 三层状态隔离（PRD §8.1）

| 状态 | 载体 | 生命周期 | 权限边界 |
|---|---|---|---|
| Conversation State | `pipeline_conversation` 表（消息历史 + 用户补充项） | 随 Pipeline 长期存在 | Maker 可读写自己的会话 |
| Workflow State | LangGraph Checkpoint（PG 表，`thread_id = pipeline_id`） | 跨请求恢复，图跑完归档 | 仅服务端读写；前端只读状态快照 |
| Execution State | `execution_run` / `execution_metric` / `quality_report` | 一次执行一个实例，不可变 | 操作员可触发动作，审计员只读 |

**隔离规则**：执行状态**不得**被对话状态覆盖；同一个 Pipeline 可以有多条 ExecutionRun，但任一时刻只允许一条处于 `Queued/Running/Interrupted/RollingBack`。

## 5. Harness 安全执行内核

| 模块 | 入口 | 职责 | 不做什么 |
|---|---|---|---|
| `PDP` | `engines/policy/pdp.decide(intent, scope, env, level)` | 纯规则表输出 P0–P3 与审批要求 | 不调 LLM、不查库 |
| `CapabilityIssuer` | `harness/capability.issue(preparation, subject, tool)` | 用 Ed25519 私钥签 JWT（含 `jti/subject/tool/env/artifact_sha256/exp`，默认 5 分钟） | 不落私钥到仓库 |
| `CapabilityVerifier` | `harness/capability.verify(token, expected)` | 验签 + 校验过期/主体/工具/环境/指纹 | 不查业务库 |
| `ReplayGuard` | `harness/replay.consume(jti)` | **原子**消费：Redis `SETNX` 成功 **且** PG 唯一约束插入成功才算消费 | 不允许「先查后写」 |
| `ToolBroker` | `harness/broker.execute(tool, token, args)` | 所有副作用的唯一出口；按工具注册表校验所需 Capability 与风险等级 | 不被 api/service 绕过 |
| `TransactionalOutbox` | `harness/outbox.enqueue(session, topic, payload)` | 与业务事实**同事务**写入 outbox 表 | 不在事务内直接 `apply_async` |
| `EvidenceLedger` | `harness/ledger.append(event)` | 计算 `prev_hash`/`event_hash` 链式写入；每 100 条打 Ed25519 签名检查点 | 不接收明文敏感值（写入前强制脱敏） |

**工具注册表**（唯一允许的副作用动作）：

| 工具名 | 风险 | 必需 Capability | 执行者 |
|---|---|---|---|
| `seatunnel.submit` | P1 | 是 | worker |
| `seatunnel.stop` | P2 | 是 | worker |
| `target.publish_swap` | P0 | 是（额外要求质量报告通过） | worker |
| `target.rollback_cleanup` | P1 | 是 | worker |
| `datasource.connectivity_test` | P3 | 否（只读） | api |
| `metadata.probe` | P3 | 否（只读） | api |

## 6. 数据流与安全边界

```
Vault(KV v2) ──AppRole token──▶ worker 内存 ──▶ SeaTunnel 配置(临时文件,0600,执行后删除)
   │                                              │
   └─ 只存密文；PG 只存 secret_reference(path,version) ─┘
                                    │
                                    ▼
                       日志/API/账本/LLM 上下文：一律只出现引用与掩码值
```

- **Secret 生命周期**：`SecretReference`（PG）→ Vault 读取（worker 内）→ 物化为临时文件或环境变量 → 作业结束立即销毁 → 审计事件记「谁在何时物化了哪个引用」，**不记值**。
- **脱敏策略**：探查样本按字段类型与敏感等级走掩码（保留首尾）/ 哈希 / 截断；错误表只存 `payload_digest`（SHA256 + 长度），不存原文。
- **模型上下文边界**：只投喂 Schema、字段类型、统计与脱敏样本值，**绝不**投喂连接串、Secret、未脱敏样本。

## 7. API 分组（PRD §9.2）

| 分组 | 前缀 | 要点 |
|---|---|---|
| 认证与项目 | `/api/v1/auth` `/api/v1/projects` | JWT(access+refresh)、Redis 失败锁定、成员与职责槽 |
| 数据源 | `/api/v1/datasources` | CRUD、连通性测试、探查、Profile 查询 |
| Pipeline | `/api/v1/pipelines` | 需求对话、生成、门禁、版本冻结、Diff |
| 审批 | `/api/v1/preparations` | Prepare、审批列表、审批决定、状态 |
| 执行 | `/api/v1/runs` | Commit、查询、暂停、取消、回滚 |
| 监控 | `/api/v1/monitor` | 指标、日志、质量报告、根因诊断 |
| 安全治理 | `/api/v1/governance` | 策略、Benchmark、评测结果、账本查询与验链 |

横切要求：租户过滤、`Idempotency-Key`、统一错误码、审计事件写入、副作用接口经 ToolBroker。

## 8. 运行监督与质量分流

- **监督契约**：`max_read_rows / max_write_bytes / max_duration / max_amplification_ratio / max_reject_rate`，超**预警阈值**（默认 80%）写告警事件，超**硬阈值**触发硬中断。
- **硬中断路径**：监督引擎 → `seatunnel.stop` → 保存失败快照（`execution_metric` 最后 N 点 + 错误码分布）→ 证据事件 → 状态 `Interrupted` → 允许受管回滚。
- **指标来源**：行数/字节/时长取自 SeaTunnel 作业指标；**拒绝率与错误码分布直接查目标端错误表**（最可信，不受 SeaTunnel 指标口径影响）。← *待 M3 实机验证，若 SeaTunnel REST 指标不可用则退化为「只查目标表 + 时长自计时」*。
- **原子发布**：`TargetPublisher.publish(run)`；Doris 用 `REPLACE WITH TABLE ... swap=true`，MySQL 用 `RENAME TABLE`；失败不改正式表，进入 `Failed` 且可诊断。

## 9. 部署拓扑（单机 Compose）

| Profile | 服务 | 说明 |
|---|---|---|
| 默认 | `postgres` `redis` `minio` `vault` `api` `worker` `beat` `nginx`(+静态前端) | 常驻；轻量 |
| `demo` | `mysql` `doris` `seatunnel` | 演示数据面；Doris 吃 8G+ 内存，默认不启 |
| `obs` | `prometheus` `grafana` | M4 接入 |

外网仅暴露 Nginx（80/443）；PG/Redis/MinIO/Vault 仅在内网网络内可达（**ECS 安全组必须同步收紧**）。
